# 축소하면 지도 위 카드 닫기 작업내용

기간: 2026-08-08
범위: 결함 지도(`DefectMap`). 사용자가 축소하면 지도 위에 펼쳐둔 것(묶음 결함 목록,
상세 카드)을 닫는다.

관련 문서: [결함-묶음-목록_작업내용.md](결함-묶음-목록_작업내용.md)(묶음 결함 목록),
[결함-카드-끌어-옮기기_작업내용.md](결함-카드-끌어-옮기기_작업내용.md)(상세 카드),

## 1. 무엇을 바꿨나

**축소(zoom out)하면 묶음 결함 목록과 상세 카드를 닫는다.**

축소는 "넓게 보고 싶다"는 뜻이다. 그런데 카드가 지도의 절반을 덮고 있어 정작 넓힌 화면이
가려진다. **확대는 그대로 둔다** — 들여다보는 중이니 카드도 함께 필요하다.

```ts
maps.Event.addListener(map, 'zoom_changed', () => {
  const nextZoom = map.getZoom()
  const zoomedOut = nextZoom < lastZoom
  lastZoom = nextZoom
  …
  if (zoomedOut && !ours) closeMapOverlaysRef.current()   // setClusterList(null) + onSelect(null)
})
```

배율만 보면 확대인지 축소인지 알 수 없어 **이전 배율과 견준다.** `zoom_changed`는 배율이
실제로 바뀔 때만 온다.

---

## 2. 우리가 부른 축소는 세지 않는다

`fitBounds`(첫 조회 결과에 지도를 맞추는 호출)는 배율을 **내릴 수도** 있다. 그때 카드를
닫으면 **조건을 바꿨을 뿐인데 보던 카드가 사라진다.**

그래서 `fitBounds` 직전에 표식을 세우고, `zoom_changed` 처리에서 그 표식을 한 번 쓰고
지운다.

```ts
skipZoomOutCloseRef.current = true    // fitBounds 직전
```

다른 프로그램 호출(묶음 클릭 확대, 새 결함 이동, 목록 선택 확대)은 **모두 확대**라서 이
표식이 필요 없다. 축소가 되는 자리는 `fitBounds` 하나뿐이다.

## 2.1 닫는 함수는 ref로 잡는다

지도 설정 effect는 **한 번만** 돈다. 그 안에서 `onSelect`를 직접 잡으면 낡은 클로저가 되어
나중에 바뀐 상위 함수를 부르지 못한다. `closeMapOverlaysRef`에 최신 것을 넣어두고 그것을
부른다(이 파일이 `filtersRef`·`filterKeyRef`에 쓰는 방식과 같다).

---

## 3. 확인한 것

**e2e 4개**(`e2e/defect-zoom-out-close.spec.ts`).

| 상황 | 결과 |
| --- | --- |
| 상세 카드를 열고 축소 | 카드가 닫힌다 |
| 상세 카드를 열고 **확대** | 카드가 남는다 |
| 묶음 목록을 열고 축소 | 목록이 닫힌다 |
| 카드를 연 채 검색어를 넣어 필터 변경(`fitBounds`) | 카드가 **남는다**(§2) |

축소·확대는 가짜 지도에 낸 `zoomMapBy(page, ±1)`로 흉내낸다. 가짜가 배율이 바뀔 때
`zoom_changed`를 쏘도록 함께 고쳤다(전에는 `bounds_changed`·`idle`만 쏘았다).

앞의 두 시험을 **고치기 전 코드에 돌려 실패하는 것까지 확인했다**(카드가 그대로 남는다).

`npm run test:e2e:defect`에 넣었다 — 결함 화면 e2e 64개 통과. 단위 시험 110 pass,
`tsc -b`·`eslint`·CSP 게이트 PASS.

## 4. 남은 것

### 내 몫

- 없다.

### 알아둘 것

- 앞으로 **배율을 내리는 프로그램 호출**을 새로 만들면 `skipZoomOutCloseRef`를 함께
  세워야 한다. 안 세우면 사용자가 축소한 것으로 보고 카드를 닫는다.
- 로봇 지도(`RobotMap`)에는 같은 처리가 없다. 거기에도 지도 위 카드가 생기면 같은 판단이
  필요하다.
