## 2. 설계 판단과 그 이유

### 2.1 로딩 상태를 state가 아니라 파생값으로 두었다

`useEffect` 본문에서 `setLoading(true)`를 호출했더니 eslint의
`react-hooks/set-state-in-effect`가 막았다. 우회하지 않고 구조를 바꿨다.

```
requestKey = JSON.stringify({filters, page, sort, reloadToken})
loading    = snapshot?.key !== requestKey
```

응답을 받은 마지막 키와 지금 조건을 비교한다. effect는 promise 콜백에서만 setState 한다.
부수 효과로 **갱신 중에도 이전 목록이 남아 화면이 깜빡이지 않는다**(stale-while-revalidate).

### 2.2 지도는 목록과 별개로 자기 데이터를 조회한다

처음에는 목록 20건을 마커로 넘겼는데, 그러면 화면에 보이는 범위에 결함이 50건 있어도 20개만
찍힌다. 지도는 `/defects/map` GeoJSON을 직접 받고 뷰포트 `bbox`로 다시 조회한다.
필터는 목록과 같은 객체를 공유해 두 화면이 어긋나지 않는다.

`idle` 이벤트에 300ms debounce를 걸었다. 지도를 끄는 동안 매 프레임 조회하면 안 된다.

### 2.3 첫 조회는 bbox 없이 하고 결과에 지도를 맞춘다

기본 뷰포트(구미시청)와 결함 위치가 다를 수 있다. 첫 조회는 뷰포트 제한 없이 전체를 받고
`fitBounds`로 이동한 뒤, 그때부터 뷰포트 기반 조회로 전환한다.

**맞추기 전의 `idle`은 무시한다.** 이걸 안 막으면 지도 생성 직후 발생하는 `idle`이 엉뚱한
bbox를 걸어 첫 조회 결과를 스스로 지운다(§3.2).

### 2.4 상태 전이표를 프론트에 복제했다

`ALLOWED_TRANSITIONS`는 서버 `DefectWorkflow`를 그대로 옮긴 것이다. 중복이지만 의도한
중복이다 — 드롭다운에 갈 수 없는 상태를 띄우고 409를 받게 하는 것보다, 갈 수 있는 것만
보여주는 편이 낫다. **최종 판정은 서버가 하고 프론트는 안내만 한다.**

같은 이유로 `RESOLVED`를 고르면 처리 결과 드롭다운이 나타난다. 서버가 완료 처리에
`resolution`을 필수로 요구하므로, 없으면 422를 받는다.

### 2.5 상세를 별도 라우트가 아니라 지도 위 카드로 만들었다

마커를 눌렀을 때 페이지가 통째로 바뀌면 지도에서 위치 맥락을 잃는다. 카드로 띄우면
주변 결함을 보면서 처리할 수 있다. 목록 행 선택과 같은 `selectedDefectId`를 쓰므로
목록·지도·카드가 항상 같은 결함을 가리킨다.

### 2.6 이미지 404는 오류가 아니라 "없음"이다

이미지가 연결되지 않은 결함이 흔하다(업로드 실패, 아직 미연결). 404를 에러로 표시하면
정상 상태를 사고처럼 보여준다. `ImageState`를 `loading|none|error|ready` 넷으로 나눠
404만 `none`으로 접었다.

### 2.7 필터를 URL query에 실었다

새로고침해도 조건이 유지되고, **시연 중 특정 조건의 화면을 링크로 공유**할 수 있다.
조건이 바뀌면 페이지를 0으로 되돌린다(현재 페이지가 범위를 벗어날 수 있다).

### 2.8 발행기에 분산·변주 옵션을 넣었다

`--spread-m`이 없으면 서버의 2m 병합에 걸려 30건을 쏴도 결함이 1건이 된다.
`--damage-ratio`를 생략하면 값을 순환시켜 `DefectRiskAssessment`의 25/50/75 임계에 맞춰
LOW~CRITICAL이 고르게 나온다. 시연 데이터가 한 등급에 몰리지 않게 하려는 것이다.

---

### 2.9 bbox 오버레이를 SVG 정규 좌표계로 그렸다

`bboxNorm`이 이미 0~1 정규값이므로 `viewBox="0 0 1 1"`로 두면 **좌표를 그대로 `rect`에
넣을 수 있다.** 이미지 픽셀 크기나 종횡비를 계산할 필요가 없고, 창 크기가 바뀌어도
저절로 따라간다.

DOM 요소를 절대배치하는 방법도 있지만 좌표를 퍼센트로 환산해야 하고, 무엇보다
**CSP가 `style` 속성을 막는다**(§3.1). SVG는 좌표가 **속성**이고 색·두께만 CSS 클래스라
CSP와 무관하다.

`vectorEffect="non-scaling-stroke"`를 준 이유는 `preserveAspectRatio="none"` 때문에
가로·세로 배율이 달라져 선 두께가 찌그러지기 때문이다.

**이 값은 임베디드가 보내는 것이다.** 웹은 추론을 하지 않는다. MQTT 계약
`evidence.bbox_norm`(필수, 4개, 0~1, `x_min < x_max` 검증)을
`IncidentEventIngestionService`가 그대로 저장하고 조회할 때 돌려줄 뿐이다.
지금 화면의 상자가 항상 같은 위치인 것은 개발용 발행기가 값을 고정해 둬서다.

### 2.10 단건 결함 보고서용 이미지 조회를 따로 뒀다

보고서 방향이 "기간 기준"에서 **"결함 단건 기준"**으로 바뀌었다(7/31). 기존
`findReportImages(userId, from, to, n)`는 *기간 내 대표 결함*을 고르므로, 단건 보고서에
쓰면 대개 다른 결함의 이미지가 나온다.

호출부(`ReportLlmRequestFactory.matchesEvidence`)가 근거 결함과 이미지의 `defectId`를
대조해 불일치를 걸러내므로, 결과는 **에러가 아니라 "이미지 없는 보고서"**다. 조용히
잘못되는 종류라 별도 경로를 만들었다.

```
findReportImagesForDefect(userId, defectId) → List<DefectReportImage>  // 0~1개
```

가시 범위와 병합 결함 처리는 기간 조회와 같다. 테스트에서 **위험도가 더 높은 다른 결함을
먼저 만들어 둔 뒤** 요청한 결함의 이미지가 나오는지 확인한다 — 기간 기준이었다면 실패할
상황을 재현한 것이다.

## 3. 작업 중 겪은 함정

### 3.1 CSP가 인라인 스타일을 막아 마커가 보이지 않았다 — 오늘의 가장 큰 함정

지도는 뜨고 범례 숫자도 지도를 움직일 때마다 바뀌는데 **마커만 안 보였다.** 좌표 순서,
CSS 높이, 클라이언트 ID, 마커 effect 실행 여부를 차례로 배제했지만 원인을 못 찾았다.

브라우저 콘솔이 답이었다.

```
Applying inline style violates the following Content Security Policy
directive 'style-src 'self''. (수십 회)
```

`frontend/nginx/default.conf`의 CSP가 `style-src 'self'`라, 마커 HTML의 `style="..."`
속성이 전부 차단됐다. 요소는 DOM에 있었지만 width·height·background가 하나도 적용되지
않아 **크기 0으로 렌더**됐다.

→ 마커 모양을 `App.css`의 클래스로 옮겼다. CSP를 약화시키지 않는 쪽이 옳다.

**교훈:** "요소는 만들어졌는데 안 보인다"면 콘솔부터 본다. 원격에서 추측으로 좁히려다
시간을 썼고, 중간에 "icon.size 때문일 것"이라는 틀린 진단도 냈다.

### 3.2 첫 `idle`이 첫 조회 결과를 지웠다

기본 중심이 구미시청인데 당시 시드 데이터는 서울 강남에 있었다. 지도를 만들면 곧바로
`idle`이 발생하고, 그 시점의 구미 기준 bbox로 재조회하면 0건이 돌아와 **전체 조회로 받은
결과를 덮어썼다.** 마커가 영영 안 보이는 상태가 된다.

→ `fittedRef`로 "결함 위치에 맞추기 전의 idle"을 무시한다(§2.3).

### 3.3 로컬에 node가 없어 타입 검사를 두 번이나 헛돌렸다

`npx tsc -b`가 Windows 셸로 새면서 **가짜 `tsc` npm 패키지를 설치하고 exit 0**을 냈다.
"타입 검사 통과"라고 두 번 보고했는데 둘 다 무효였다.

`npm ci`도 조용히 실패하고 있었다. `package.json`의 `engines`가 node **24.18.0**으로
고정돼 있는데 `node:24-alpine` 이미지가 24.18.1이라 `notsup`으로 거부됐다.

→ `node:24.18.0-alpine` 컨테이너 + **`./node_modules/.bin/tsc`를 직접 호출**한다.
`npx`는 이 환경에서 신뢰할 수 없다.

**교훈:** 검증 명령이 "통과"했다고 말하기 전에 그 명령이 실제로 무엇을 실행했는지 확인한다.
`&& echo 성공` 패턴은 파이프 뒤에 붙으면 앞 명령이 아니라 `tail`의 종료 코드를 본다.

### 3.4 서버 enum을 추측해서 틀렸다

`DEFECT_TYPES`와 `RESOLUTIONS`를 그럴듯하게 지어냈는데 실제와 달랐다.

| 내 추측 | 실제(`DefectFilter.java`) |
| --- | --- |
| `OBSTRUCTED`, `MISINSTALLED` | `BLOCKED`, `MISSING_SUSPECTED`, `INSTALLATION_INVALID`, `UNKNOWN_ANOMALY` |
| `FALSE_POSITIVE`(resolution) | `CLEANED`, `NOT_APPLICABLE` |

→ 계약을 옮길 때는 **반드시 그 순간의 서버 소스를 열어본다.**

### 3.5 MQTT 페이로드 키가 `robot_id`가 아니라 `mqtt_id`였다

`test/통신테스트/mqtt_tls_test.py`를 그대로 돌렸더니 `MQTT_PAYLOAD_MALFORMED`가 났다.
세 가지가 어긋나 있었다.

- `ttl_sec` 누락 (`@NotNull @Min(60) @Max(300)`)
- `robot_id` → 계약은 **`mqtt_id`** (DB의 UUID `robot_id`와 구분,
  `final-mqtt-topic-schema-v2.md` 42~44행)
- `zone_id: "ZONE-TEST-01"` → 패턴은 `^[A-Z]-[0-9]{2}$`

그 스크립트는 임베디드에도 배포된 자산이라 B에게 넘겼고, 나는 계약에 맞는 발행기를 따로
만들었다.

### 3.6 `seq`는 boot_id마다 1부터다

두 번째 발행에서 `--seq 2`를 줬더니 `MQTT_REPLAY_REJECTED`. 실행마다 새 `boot_id`가
생기므로 seq도 1부터 시작해야 한다(V17 제약).

### 3.7 `docker compose restart`가 exit 127로 죽는다

WSL bind-mount가 stale해지는 문제로 보인다. `mqtt-init`도 같은 증상이었다.
**`up -d --force-recreate`를 쓴다.**

### 3.8 직접 INSERT한 로봇은 1분마다 ERROR를 낸다

MQTT 자격증명 행이 없어 `MqttCredentialRegistryService`가 주기적으로 실패 로그를 남긴다.
시드로 만든 로봇의 부작용이며, B가 정식 등록하면 사라진다.

### 3.9 sed 치환으로 파이썬 들여쓰기를 깨뜨렸다

기본 좌표를 바꾸면서 교체 문자열에 공백을 중복으로 넣어 `IndentationError`가 났고,
첫 발행이 0건이었다. 파이썬 파일은 치환 후 `ast.parse`로 확인하는 습관이 필요하다.

---

### 3.10 `object-fit: cover`가 bbox 좌표를 어긋나게 한다

카드 사진에 `object-fit: cover; max-height: 220px`를 주고 있었다. cover는 **이미지를
잘라서** 상자에 맞추므로, 오버레이 SVG는 잘리지 않은 전체 좌표계를 그린다. 상자가 사진 속
결함과 어긋난다.

→ `figure`로 감싸고 이미지를 원본 비율(`width:100%; height:auto`)로 두었다. figure 높이를
이미지가 정하므로 `inset:0` SVG가 항상 정확히 겹친다. 320×240은 약 231px, 실제 Jetson
1920×1080은 약 173px이라 카드 안에 들어간다.

**교훈:** 이미지 위에 좌표를 그릴 때는 `object-fit`을 먼저 확인한다. `cover`·`contain`
모두 그림 상자와 픽셀 상자를 어긋나게 한다.

## 5. 운영 메모

**프론트 검증 명령** — 로컬에 node가 없으므로 컨테이너로 돌린다.

```
docker run --rm --user "$(id -u):$(id -g)" \
  -e HOME=/cache -e npm_config_cache=/cache/npm \
  -v "$PWD:/app" -v "<캐시경로>:/cache" -w /app \
  node:24.18.0-alpine sh -ec \
  "npm ci && ./node_modules/.bin/tsc -b && ./node_modules/.bin/eslint . && ./node_modules/.bin/vite build"
```

`npx`를 쓰지 않는다(§3.3). 이미지 태그는 `engines`와 정확히 같아야 한다.

**시연 데이터 재구성** — [지우-remaining-7days.md](../지우-remaining-7days.md) §6.6 참고.
볼륨을 초기화해도 3분 안에 복구된다.

**마커 스타일을 바꿀 때** — 반드시 `App.css`의 `.defect-marker*` 클래스를 고친다.
마커 HTML에 `style` 속성을 쓰면 CSP가 차단해 조용히 사라진다(§3.1).
