## 2. 설계 판단과 그 이유

### 2.1 로딩 상태를 state가 아니라 파생값으로 두었다

`useEffect` 본문에서 `setLoading(true)`를 호출했더니 eslint의
`react-hooks/set-state-in-effect`가 막았다. 우회하지 않고 구조를 바꿨다.

```
requestKey = JSON.stringify({filters, page, sort, reloadToken})
loading    = snapshot?.key !== requestKey
```

응답을 받은 마지막 키와 지금 조건을 비교한다. effect는 promise 콜백에서만 setState 한다.
부수 효과로 **갱신 중에도 이전 목록이 남아 화면이 깜빡이지 않는다**(stale-while-revalidate).

### 2.2 지도는 목록과 별개로 자기 데이터를 조회한다

처음에는 목록 20건을 마커로 넘겼는데, 그러면 화면에 보이는 범위에 결함이 50건 있어도 20개만
찍힌다. 지도는 `/defects/map` GeoJSON을 직접 받고 뷰포트 `bbox`로 다시 조회한다.
필터는 목록과 같은 객체를 공유해 두 화면이 어긋나지 않는다.

`idle` 이벤트에 300ms debounce를 걸었다. 지도를 끄는 동안 매 프레임 조회하면 안 된다.

### 2.3 첫 조회는 bbox 없이 하고 결과에 지도를 맞춘다

기본 뷰포트(구미시청)와 결함 위치가 다를 수 있다. 첫 조회는 뷰포트 제한 없이 전체를 받고
`fitBounds`로 이동한 뒤, 그때부터 뷰포트 기반 조회로 전환한다.

**맞추기 전의 `idle`은 무시한다.** 이걸 안 막으면 지도 생성 직후 발생하는 `idle`이 엉뚱한
bbox를 걸어 첫 조회 결과를 스스로 지운다(§3.2).

### 2.4 상태 전이표를 프론트에 복제했다

`ALLOWED_TRANSITIONS`는 서버 `DefectWorkflow`를 그대로 옮긴 것이다. 중복이지만 의도한
중복이다 — 드롭다운에 갈 수 없는 상태를 띄우고 409를 받게 하는 것보다, 갈 수 있는 것만
보여주는 편이 낫다. **최종 판정은 서버가 하고 프론트는 안내만 한다.**

같은 이유로 `RESOLVED`를 고르면 처리 결과 드롭다운이 나타난다. 서버가 완료 처리에
`resolution`을 필수로 요구하므로, 없으면 422를 받는다.

### 2.5 상세를 별도 라우트가 아니라 지도 위 카드로 만들었다

마커를 눌렀을 때 페이지가 통째로 바뀌면 지도에서 위치 맥락을 잃는다. 카드로 띄우면
주변 결함을 보면서 처리할 수 있다. 목록 행 선택과 같은 `selectedDefectId`를 쓰므로
목록·지도·카드가 항상 같은 결함을 가리킨다.

### 2.6 이미지 404는 오류가 아니라 "없음"이다

이미지가 연결되지 않은 결함이 흔하다(업로드 실패, 아직 미연결). 404를 에러로 표시하면
정상 상태를 사고처럼 보여준다. `ImageState`를 `loading|none|error|ready` 넷으로 나눠
404만 `none`으로 접었다.

### 2.7 필터를 URL query에 실었다

새로고침해도 조건이 유지되고, **시연 중 특정 조건의 화면을 링크로 공유**할 수 있다.
조건이 바뀌면 페이지를 0으로 되돌린다(현재 페이지가 범위를 벗어날 수 있다).

### 2.8 발행기에 분산·변주 옵션을 넣었다

`--spread-m`이 없으면 서버의 2m 병합에 걸려 30건을 쏴도 결함이 1건이 된다.
`--damage-ratio`를 생략하면 값을 순환시켜 `DefectRiskAssessment`의 25/50/75 임계에 맞춰
LOW~CRITICAL이 고르게 나온다. 시연 데이터가 한 등급에 몰리지 않게 하려는 것이다.

---

### 2.9 bbox 오버레이를 SVG 정규 좌표계로 그렸다

`bboxNorm`이 이미 0~1 정규값이므로 `viewBox="0 0 1 1"`로 두면 **좌표를 그대로 `rect`에
넣을 수 있다.** 이미지 픽셀 크기나 종횡비를 계산할 필요가 없고, 창 크기가 바뀌어도
저절로 따라간다.

DOM 요소를 절대배치하는 방법도 있지만 좌표를 퍼센트로 환산해야 하고, 무엇보다
**CSP가 `style` 속성을 막는다**(§3.1). SVG는 좌표가 **속성**이고 색·두께만 CSS 클래스라
CSP와 무관하다.

`vectorEffect="non-scaling-stroke"`를 준 이유는 `preserveAspectRatio="none"` 때문에
가로·세로 배율이 달라져 선 두께가 찌그러지기 때문이다.

**이 값은 임베디드가 보내는 것이다.** 웹은 추론을 하지 않는다. MQTT 계약
`evidence.bbox_norm`(필수, 4개, 0~1, `x_min < x_max` 검증)을
`IncidentEventIngestionService`가 그대로 저장하고 조회할 때 돌려줄 뿐이다.
지금 화면의 상자가 항상 같은 위치인 것은 개발용 발행기가 값을 고정해 둬서다.

### 2.10 단건 결함 보고서용 이미지 조회를 따로 뒀다

보고서 방향이 "기간 기준"에서 **"결함 단건 기준"**으로 바뀌었다(7/31). 기존
`findReportImages(userId, from, to, n)`는 *기간 내 대표 결함*을 고르므로, 단건 보고서에
쓰면 대개 다른 결함의 이미지가 나온다.

호출부(`ReportLlmRequestFactory.matchesEvidence`)가 근거 결함과 이미지의 `defectId`를
대조해 불일치를 걸러내므로, 결과는 **에러가 아니라 "이미지 없는 보고서"**다. 조용히
잘못되는 종류라 별도 경로를 만들었다.

```
findReportImagesForDefect(userId, defectId) → List<DefectReportImage>  // 0~1개
```

가시 범위와 병합 결함 처리는 기간 조회와 같다. 테스트에서 **위험도가 더 높은 다른 결함을
먼저 만들어 둔 뒤** 요청한 결함의 이미지가 나오는지 확인한다 — 기간 기준이었다면 실패할
상황을 재현한 것이다.

### 2.11 이력은 탭을 열 때만 조회하고, 로딩 상태는 두지 않았다

상세 카드를 띄울 때마다 상세·이미지·관측·변경 이력을 네 번 부르면 낭비다. 탭을 처음 열
때만 조회하고, 상태를 바꾸면 변경 이력 상태를 `idle`로 되돌려 다음에 열 때 새로 읽는다.

`loading` 상태를 따로 두지 않았다. effect 본문에서 동기로 `setState`를 하면
`react-hooks/set-state-in-effect`에 걸리기 때문이다(§2.1과 같은 규칙). **"탭이 열려
있는데 아직 `idle`"이면 조회 중**으로 해석한다. 상태가 하나 줄어 오히려 단순해졌다.

관측 탭의 개수는 이미 갖고 있는 `observationCount`를 쓴다. 개수를 보여주자고 조회를
한 번 더 하지 않는다.

### 2.12 변경 이력은 전체 snapshot이 아니라 바뀐 항목만 보여준다

서버는 `beforeValues`/`afterValues`에 **전체 snapshot**을 준다. 그대로 뿌리면 무엇이
바뀌었는지 읽어낼 수 없다. 두 객체를 비교해 값이 달라진 키만 골라
`defectType: DAMAGED → BLOCKED` 형태로 보여준다.

### 2.13 SSE는 "다시 읽어라"만 전달하고 화면은 REST로 갱신한다

이벤트 페이로드에 `defectType`·`riskLevel`·`workflowStatus`가 다 들어 있어서 그것으로
목록을 직접 고칠 수도 있다. 그렇게 하지 않았다.

계약(24장, openapi `/api/v1/stream/defects`)이 **"이벤트는 변경 알림만 제공하고
클라이언트는 REST로 최신 상태를 다시 조회한다"**로 정의돼 있다. 이벤트로 로컬 상태를
패치하면 이벤트 유실·순서 뒤바뀜·필터 조건 변화에서 서버와 어긋나고, 그 어긋남은
화면만 봐서는 발견되지 않는다.

그래서 훅은 `onSnapshotRequired()`만 부르고, 이미 있던 `reloadToken` 배선을 그대로
재사용한다. 목록과 지도가 각자 자기 조건으로 다시 읽으므로 **필터가 걸려 있으면 새 결함도
그 조건에 맞을 때만 나타난다** — 이벤트를 직접 반영했다면 필터를 무시하고 끼어들었을 것이다.

**재조회는 400ms debounce**를 건다. 로봇이 결함을 연속으로 올리면 `defect.created`가
초 단위로 몰려온다.

**재연결 직후에도 전체 재조회를 요청한다.** 끊겨 있는 동안 놓친 이벤트는 되돌아오지 않는다.
`CONNECTED` 이벤트를 그 신호로 쓴다.

### 2.14 실시간 연결 상태를 항상 보여준다

SSE가 끊긴 채 조용히 있는 것이 가장 위험하다. 관리자는 "결함이 없다"고 오해한다.
헤더에 `실시간 연결됨 / 연결 중… / 연결이 끊겨 재연결 중…`을 항상 띄운다.

### 2.15 관측에 탐지 로봇 이름을 붙였다 (2026-08-01)

관측 응답에 `robot_id`(UUID)만 있어 화면에서 쓸 수 없었다. `robot.robot`을 조인해
`robotName`을 내려준다.

```sql
LEFT JOIN robot.robot r ON r.robot_id = o.robot_id
```

**`LEFT JOIN`인 것이 요점이다.** 이름은 표시용이라 로봇 행이 없다고 관측 자체가 사라지면
안 된다. 그때는 화면에 `이름 없는 로봇`으로 뜬다.

`robot` 패키지 파일은 건드리지 않았다. defect 쪽 쿼리에서 읽기만 했고, `gilbom_app`에
`robot.robot` SELECT 권한이 이미 있는 것을 확인했다.

**임무는 같이 넣지 않았다** — §3.13 참고.

### 2.16 결함 수정 모달 — 서버 규칙을 화면에 미러링했다 (2026-08-01)

`PATCH /defects/{id}`는 이미 있었고 프론트 `updateDefect()`도 있었는데 **부르는 화면이
없었다.** `DefectEditModal`을 만들어 상세 카드에 붙였다.
수정 항목은 유형·심각도·구역·위치 설명·재검토 필요 + 수정 사유다.

**막는 조건을 서버와 똑같이 두었다.** `DefectCommandService.requireChangeable()`가
종결 상태와 병합된 결함을 `DEFECT_STATE_CONFLICT`로 거부한다. 화면도 같은 규칙으로
버튼을 잠그고 사유를 툴팁에 띄운다. **저장을 눌러서 409를 받는 경로가 없다.**

| 조건 | 화면 |
| --- | --- |
| 종결(`RESOLVED`·`FALSE_POSITIVE`·`REJECTED`) | 버튼 비활성 + "종결된 결함은 수정할 수 없습니다." |
| `mergedIntoDefectId != null` | 버튼 비활성 + "대표 결함에서 수정해야 합니다." |
| `DEFECT_STATUS_UPDATE` 없음 | 버튼 자체를 렌더하지 않는다 |

**바뀐 축만 담아 보낸다.** 서버는 PATCH 본문의 null을 "변경 없음"으로 읽고, 바뀐 것이
하나도 없으면 `COMMON_INVALID_REQUEST`를 던진다. 그래서 화면이 먼저 비교해 저장 버튼을
잠근다. 400을 받아 안내하는 것보다 낫다.

**빈 입력은 "지운다"가 아니라 "건드리지 않는다"로 했다.** 서버에 null로 지우는 계약이
없다. 구역을 지우고 저장하면 화면상으로는 지워진 것처럼 보이는데 값은 그대로 남으므로,
그건 거짓말이 된다. 아예 안 보내고 모달에 그렇게 적었다.

**좌표는 넣지 않았다.** 위경도를 숫자로 입력하게 하는 건 지도가 있는 화면에서 쓸모가
없다. 옮기는 UI가 생길 때 함께 다룬다.

수정 후에는 변경 이력 탭을 `idle`로 되돌려 다시 읽게 한다. 유형·심각도는
`appendAttributeHistories`가 **축마다 따로** 이력을 남긴다.

### 2.17 수동 병합 UI와 병합 정보 표시 (2026-08-01)

**둘을 한 번에 만들었다.** 병합 정보 표시를 따로 만들면 화면에 아무것도 안 뜬다 —
`merged_into_defect_id`를 채우는 것이 수동 병합 API뿐이기 때문이다(§3.13).

**무엇을 병합하나.** 중복으로 잡힌 *결함 행* 여러 개를 하나로 묶는다. source 결함에
`merged_into_defect_id`를 찍고, `defect_merge_history`에 기록하고, 대표 결함의 집계를
관측에서 다시 계산한다. **관측 행은 옮기지 않는다** — V12가 `defect_observation`에
UPDATE 권한을 주지 않아, 집계할 때 `merged_into_defect_id` 연결을 따라간다.

**왜 자동 병합이 있는데도 필요한가.** `findMergeCandidate()`는 탐지 시점에 반경 2m ·
같은 유형 · 같은 블록 타입 · 같은 순찰구역이 **전부** 맞을 때만 동작한다. GPS가 2m 넘게
튀거나, 같은 블록을 `DAMAGED`/`UPLIFTED`로 다르게 분류하거나, 좌표가 `valid=false`면
별도 결함으로 남는다. 그 판단을 사람이 넣는 통로다.

#### 설계 판단

- **기본 대표는 관측이 가장 많은 결함.** 근거가 제일 많은 쪽이라 대개 맞고, 사용자가
  라디오로 바꿀 수 있다
- **선택은 화면에 보이는 것만 유지한다.** 페이지·필터가 바뀌면 화면에 없는 결함이 선택에
  남아 "3건 선택됨"인데 체크는 하나만 보이는 상태가 된다. `checkedVisible`로 걸러 넘긴다
- **체크박스 클릭은 전파를 막는다.** 행 클릭이 상세 열기라, 안 막으면 체크할 때마다
  카드가 열린다
- **2건 미만이면 병합 버튼을 잠근다.** 서버 `sourceDefectIds`가 `@NotEmpty`라 1건만
  고르면 대표를 뺀 나머지가 비어 400이 난다
- **체크박스 열은 `DEFECT_MERGE` 권한이 있을 때만** 붙인다. 열 개수가 달라지므로 CSS도
  `.defect-table.is-selectable` modifier로 분리했다

#### 병합 정보는 방향이 둘이다

| 상황 | 표시 |
| --- | --- |
| 흡수한 쪽(대표) | "다른 결함 N건을 흡수한 대표 결함" + 관측 합산 안내 |
| 흡수된 쪽 | "다른 결함으로 병합됨" + **대표 결함 열기** |

두 번째가 요점이다. 흡수된 결함은 목록·지도에서 빠지지만 **링크로는 도달할 수 있다.**
열었을 때 왜 수정이 잠겨 있는지 설명이 없으면 고장으로 보인다(§2.16의 잠금 사유와 같다).

### 2.18 마커 클러스터링을 직접 만들었다 (2026-08-01)

시연 구역(구미 진평동)이 좁아 결함 40여 건이 격자로 겹쳐 보였다. **계획 D3에 있었는데
사유 없이 빠져 있던 항목**이고, 전수 대조에서 찾았다.

**네이버 `MarkerClustering`을 쓰지 않았다.** SDK 본체가 아니라 별도 스크립트라
`script-src`에 새 출처를 열어야 한다. 방금 CSP를 건드리지 않고 축척을 해결해 놓고
(§3.14) 다시 여는 것은 앞뒤가 맞지 않는다. 필요한 동작이 격자 묶기뿐이라 직접 만들었다.

#### 위경도가 아니라 화면 픽셀로 나눈다

```js
const offset = projection.fromCoordToOffset(new maps.LatLng(lat, lng))
const key = `${Math.floor(offset.x / 44)}:${Math.floor(offset.y / 44)}`
```

위경도로 나누면 **확대할 때마다 셀 크기를 다시 정해야 하고, 위도에 따라 셀이
찌그러진다.** 픽셀 격자는 배율과 무관하게 "화면에서 겹치는가"를 그대로 표현한다.
`fromCoordToOffset`은 bbox 계산에 이미 쓰고 있어 새로 만든 것이 없다.

셀 크기 44px은 마커 상자(34px)보다 조금 크게 잡았다. 같으면 딱 붙은 마커가
안 묶인다.

#### 나머지 판단

- **묶은 위치는 구성원 평균 좌표.** 첫 마커 자리에 두면 덩어리가 한쪽으로 치우쳐
  실제 분포와 다르게 보인다
- **색은 가장 급한 상태.** 처리 중인 결함이 섞여 있는데 종결 색으로 보이면 안 된다.
  `received > progress > done` 순으로 고른다
- **클릭하면 2단계 확대.** 대개 그 정도면 나뉜다. 21을 넘지 않게 막았다
- **`idle`에서만 다시 계산한다.** 화면 좌표 기준이라 확대·이동 후 재계산이 필요한데,
  `bounds_changed`로 하면 드래그 중 매 프레임 마커를 다시 만든다

#### 선택한 결함은 묶지 않는다

이게 없으면 **카드를 열어둔 채 지도를 움직였을 때 그 마커가 덩어리에 흡수된다.**
어디를 보고 있는지 알 수 없어지므로, 선택된 것만 빼서 항상 개별 마커로 그린다.

클러스터 아이콘도 마커와 같이 HTML 문자열이라 **모양은 전부 `App.css`에 둔다.**
`style` 속성을 쓰면 §3.1과 똑같이 안 보인다.

### 2.19 처음 들어오면 미종결만 보여준다 (2026-08-01)

지도가 격자로 꽉 차 보이던 진짜 이유는 겹침이 아니라 **볼 필요 없는 마커**였다.
클러스터링(§2.18)으로 겹침을 푼 뒤에도 화면이 무거워서 데이터를 세어봤다.

| 상태 | 건수 | |
| --- | --- | --- |
| REJECTED / FALSE_POSITIVE / RESOLVED | 10 / 8 / 7 | **종결 25건** |
| NEW / IN_PROGRESS / ACCEPTED | 9 / 4 / 3 | 미종결 16건 |

**41건 중 25건(61%)이 조치할 것이 없는 결함**이었다. `RESOLVED`만의 문제가 아니라
종결 3종 전부가 그렇다.

기본 상태 조건을 `NEW·ACCEPTED·IN_PROGRESS`로 뒀다. **감추는 것이 아니라 기본값을
정하는 것이다** — 필터 체크박스에 그대로 켜져 있고 종결을 체크하면 다시 보인다.
지도와 목록이 필터를 공유하므로 함께 움직인다.

#### 함정 — "안 고름"과 "전부 풀었음"이 URL에서 같아 보인다

처음에는 "URL에 `status`가 없으면 첫 진입"으로 판정했다. 그런데 **사용자가 체크를
전부 풀면 `writeFilters`가 `status`를 하나도 쓰지 않아** URL이 첫 진입과 똑같아진다.
그러면 기본값이 다시 걸려 **전체 보기가 영원히 불가능**해진다.

`allStatus=1` 표식으로 둘을 구분했다.

```ts
workflowStatuses: params.has('status')
  ? (params.getAll('status') as WorkflowStatus[])
  : (params.has('allStatus') ? [] : DEFAULT_WORKFLOW_STATUSES)
```

#### effect로 URL을 덮어쓰려다 방향을 바꿨다

처음 구현은 "첫 진입이면 effect에서 기본값을 URL에 써넣기"였는데 eslint
`react-hooks/refs`에 걸렸다(렌더 중 ref 읽기). 우회하려다 보니 setState-in-effect로
번졌다.

**결과적으로 URL에서 바로 파생시키는 지금 방식이 낫다.** effect도 setState도 없고,
링크를 공유하면 상태가 그대로 재현된다. 규칙이 `readFilters` 한 곳에만 있다.

> 린트가 막았을 때 우회할 방법을 찾기 전에 **왜 막는지**를 먼저 보면 대개 더 단순한
> 설계가 나온다. 이번이 그 경우였다.

## 3. 작업 중 겪은 함정

### 3.1 CSP가 인라인 스타일을 막아 마커가 보이지 않았다 — 오늘의 가장 큰 함정

지도는 뜨고 범례 숫자도 지도를 움직일 때마다 바뀌는데 **마커만 안 보였다.** 좌표 순서,
CSS 높이, 클라이언트 ID, 마커 effect 실행 여부를 차례로 배제했지만 원인을 못 찾았다.

브라우저 콘솔이 답이었다.

```
Applying inline style violates the following Content Security Policy
directive 'style-src 'self''. (수십 회)
```

`frontend/nginx/default.conf`의 CSP가 `style-src 'self'`라, 마커 HTML의 `style="..."`
속성이 전부 차단됐다. 요소는 DOM에 있었지만 width·height·background가 하나도 적용되지
않아 **크기 0으로 렌더**됐다.

→ 마커 모양을 `App.css`의 클래스로 옮겼다. CSP를 약화시키지 않는 쪽이 옳다.

**교훈:** "요소는 만들어졌는데 안 보인다"면 콘솔부터 본다. 원격에서 추측으로 좁히려다
시간을 썼고, 중간에 "icon.size 때문일 것"이라는 틀린 진단도 냈다.

### 3.2 첫 `idle`이 첫 조회 결과를 지웠다

기본 중심이 구미시청인데 당시 시드 데이터는 서울 강남에 있었다. 지도를 만들면 곧바로
`idle`이 발생하고, 그 시점의 구미 기준 bbox로 재조회하면 0건이 돌아와 **전체 조회로 받은
결과를 덮어썼다.** 마커가 영영 안 보이는 상태가 된다.

→ `fittedRef`로 "결함 위치에 맞추기 전의 idle"을 무시한다(§2.3).

### 3.3 로컬에 node가 없어 타입 검사를 두 번이나 헛돌렸다

`npx tsc -b`가 Windows 셸로 새면서 **가짜 `tsc` npm 패키지를 설치하고 exit 0**을 냈다.
"타입 검사 통과"라고 두 번 보고했는데 둘 다 무효였다.

`npm ci`도 조용히 실패하고 있었다. `package.json`의 `engines`가 node **24.18.0**으로
고정돼 있는데 `node:24-alpine` 이미지가 24.18.1이라 `notsup`으로 거부됐다.

→ `node:24.18.0-alpine` 컨테이너 + **`./node_modules/.bin/tsc`를 직접 호출**한다.
`npx`는 이 환경에서 신뢰할 수 없다.

**교훈:** 검증 명령이 "통과"했다고 말하기 전에 그 명령이 실제로 무엇을 실행했는지 확인한다.
`&& echo 성공` 패턴은 파이프 뒤에 붙으면 앞 명령이 아니라 `tail`의 종료 코드를 본다.

### 3.4 서버 enum을 추측해서 틀렸다

`DEFECT_TYPES`와 `RESOLUTIONS`를 그럴듯하게 지어냈는데 실제와 달랐다.

| 내 추측 | 실제(`DefectFilter.java`) |
| --- | --- |
| `OBSTRUCTED`, `MISINSTALLED` | `BLOCKED`, `MISSING_SUSPECTED`, `INSTALLATION_INVALID`, `UNKNOWN_ANOMALY` |
| `FALSE_POSITIVE`(resolution) | `CLEANED`, `NOT_APPLICABLE` |

→ 계약을 옮길 때는 **반드시 그 순간의 서버 소스를 열어본다.**

### 3.5 MQTT 페이로드 키가 `robot_id`가 아니라 `mqtt_id`였다

`test/통신테스트/mqtt_tls_test.py`를 그대로 돌렸더니 `MQTT_PAYLOAD_MALFORMED`가 났다.
세 가지가 어긋나 있었다.

- `ttl_sec` 누락 (`@NotNull @Min(60) @Max(300)`)
- `robot_id` → 계약은 **`mqtt_id`** (DB의 UUID `robot_id`와 구분,
  `final-mqtt-topic-schema-v2.md` 42~44행)
- `zone_id: "ZONE-TEST-01"` → 당시에는 `^[A-Z]-[0-9]{2}$` 패턴이 있었으나,
  V36 이후 형식 제약 없이 순찰 구역 업무 코드를 그대로 보존한다.

그 스크립트는 임베디드에도 배포된 자산이라 B에게 넘겼고, 나는 계약에 맞는 발행기를 따로
만들었다.

### 3.6 `seq`는 boot_id마다 1부터다

두 번째 발행에서 `--seq 2`를 줬더니 `MQTT_REPLAY_REJECTED`. 실행마다 새 `boot_id`가
생기므로 seq도 1부터 시작해야 한다(V17 제약).

### 3.7 `docker compose restart`가 exit 127로 죽는다

WSL bind-mount가 stale해지는 문제로 보인다. `mqtt-init`도 같은 증상이었다.
**`up -d --force-recreate`를 쓴다.**

### 3.8 직접 INSERT한 로봇은 1분마다 ERROR를 낸다

MQTT 자격증명 행이 없어 `MqttCredentialRegistryService`가 주기적으로 실패 로그를 남긴다.
시드로 만든 로봇의 부작용이며, B가 정식 등록하면 사라진다.

### 3.9 sed 치환으로 파이썬 들여쓰기를 깨뜨렸다

기본 좌표를 바꾸면서 교체 문자열에 공백을 중복으로 넣어 `IndentationError`가 났고,
첫 발행이 0건이었다. 파이썬 파일은 치환 후 `ast.parse`로 확인하는 습관이 필요하다.

---

### 3.10 `object-fit: cover`가 bbox 좌표를 어긋나게 한다

카드 사진에 `object-fit: cover; max-height: 220px`를 주고 있었다. cover는 **이미지를
잘라서** 상자에 맞추므로, 오버레이 SVG는 잘리지 않은 전체 좌표계를 그린다. 상자가 사진 속
결함과 어긋난다.

→ `figure`로 감싸고 이미지를 원본 비율(`width:100%; height:auto`)로 두었다. figure 높이를
이미지가 정하므로 `inset:0` SVG가 항상 정확히 겹친다. 320×240은 약 231px, 실제 Jetson
1920×1080은 약 173px이라 카드 안에 들어간다.

**교훈:** 이미지 위에 좌표를 그릴 때는 `object-fit`을 먼저 확인한다. `cover`·`contain`
모두 그림 상자와 픽셀 상자를 어긋나게 한다.

### 3.11 flex 항목에 `overflow`를 주면 내용이 있어도 0px로 눌린다

이력 탭을 열어도 아무것도 안 보였다. 에러도 없고 콘솔도 조용했다.

세 가지를 차례로 확인해 배제했다.

- DB에 이력 12건 기록됨 (`STATUS_CHANGED`, 전이·사유 정상)
- 서버 `findHistory` 쿼리 정상
- **서빙 중인 번들에 이력 탭 코드가 들어 있음** (`"아직 변경 이력이 없습니다"` 문자열로 확인)

원인은 CSS였다. `.defect-card`가 세로 flex인데 `.defect-card-timeline`에
`overflow-y: auto`를 줬다. **flex 항목에 `overflow`를 지정하면 자동 최소 크기
(`min-height: auto`)가 0이 되어, 내용이 있어도 공간이 모자라면 0px까지 눌린다.**
카드 높이 약 390px에 내용이 550px를 넘어 정확히 그 상황이었다.

→ `min-height`와 `flex-shrink: 0`을 주어 항목이 눌리는 대신 **카드가 스크롤**하게 했다.
사진·하단 버튼에도 같은 처리를 했다.

**교훈:** 세로 flex 안에서 스크롤 영역을 만들 때는 `overflow`만 주면 안 된다.
`min-height` 또는 `flex-shrink: 0`을 함께 준다.

### 3.12 배포 시각을 잘못 읽어 오진했다

위 문제를 조사하면서 "이력 탭 코드가 아직 배포되지 않았다"고 한 번 잘못 판단했다.
이미지 빌드 시각(12:56 UTC)이 소스 수정 시각(21:53 KST = 12:53 UTC)보다 **나중**인데
타임존을 섞어 읽고 반대로 결론 냈다.

→ 배포 여부는 시각 비교 대신 **번들에서 그 코드의 문자열을 직접 찾는 편이** 확실하다.

```
docker compose exec -T frontend sh -lc 'grep -l "고유한 문자열" /usr/share/nginx/html/assets/*.js'
```

### 3.13 "화면에 안 보인다"를 두 번 연속 잘못 짚었다 (2026-08-01)

D3 잔여 항목을 고르면서 **작업 항목 두 개를 세웠다가 둘 다 착수 직전에 철회했다.**
둘 다 원인이 같다 — 코드만 보고 "표시가 없네"라고 판단하고 **데이터를 안 봤다.**

**(1) 병합 정보 표시.** "2m 자동 병합이 핵심 기능인데 화면에 안 보인다"고 판단했다.
실제로는 `IncidentEventIngestionService.findMergeCandidate()`가 반경 2m 안에 같은 유형
결함이 있으면 **새 결함 행을 만들지 않고 기존 결함에 관측을 붙인다.** 그래서 자동 병합의
결과는 `observation_count` 증가이고, 카드의 "누적 N회"·"관측 N" 탭이 **이미 그것이다.**

`merged_into_defect_id`를 세팅하는 곳은 `DefectRepository:217` 하나뿐이고 **수동 병합
API 전용**이다. DB에 그 값이 있는 행은 0건이었다. 표시만 먼저 만들었으면 **영원히 빈 칸**
이었을 것이다. 수동 병합 UI와 한 덩어리로 D4에 미뤘다.

**(2) 임무 정보.** 같은 실수를 반복하지 않으려고 이번엔 먼저 쿼리를 돌렸다.

| | 결과 |
| --- | --- |
| 관측에 `robot_id` 있음 | 43 / 43 |
| 관측 ↔ 임무 매칭 | **0 / 43** |

`defect_observation`에 `mission_id`가 **없다.** 붙이려면 `robot_id` + 촬영 시각이
`mission.started_at ~ ended_at`에 드는지로 추론해야 하는데, DB의 미션 1건은
`MIS-TEST-001` / `CREATED` / **`started_at`이 null**이다. 만들어도 43건 전부 빈칸이다.

**교훈: 표시 기능을 만들기 전에 그 값을 만들어내는 경로가 실제로 도는지 먼저 센다.**
`SELECT count(*)` 한 줄이면 되고, 이번엔 그걸로 두 시간 넘게 아꼈다.

### 3.14 CSP가 막는 것은 인라인 속성만이 아니다 — 지도 컨트롤 (2026-08-01)

§3.1에서 마커가 안 보였던 원인을 "CSP가 인라인 스타일 속성을 막는다"로 정리했는데,
**절반만 맞았다.** `style-src 'self'`는 **외부 도메인의 스타일시트 파일도 통째로 막는다.**
그래서 네이버 지도 SDK는 자기 컨트롤의 여백·배경·테두리를 전부 잃는다.

증상은 이랬다.

| 컨트롤 | 증상 |
| --- | --- |
| 줌 | 기본 LARGE 슬라이더가 왼쪽 위에서 마커를 가림, 스킨 없이 뼈대만 |
| 축척 | 글자만 남아 컨테이너 모서리에서 **반쯤 잘림** |
| 로고 | 정상 (이미지+링크라 CSS가 없어도 보인다) |

**위치를 바꿔서는 해결되지 않았다.** 오른쪽 아래 → 왼쪽 위 → 왼쪽 아래로 옮겨봤지만
전부 잘렸다. 여백이 CSS에서 오는데 그 CSS가 통째로 없으니 어느 모서리에 둬도 우리
컨테이너의 `overflow: hidden` + `border-radius: 14px`에 잘린다. **세 번 옮겨보고서야
"위치 문제가 아니라 여백 문제"라는 걸 알았다.**

#### 해결: 우리가 그린다

- **줌**: SMALL 스타일 + 오른쪽 위. 작아지고 마커를 안 가리니 스킨이 없어도 덜 거슬린다
- **축척**: 네이버 컨트롤을 끄고 직접 그린다. `getBounds()`로 1px당 m를 구해
  96px 안에 들어가는 가장 큰 1·2·5 계열 값을 고른다. 경도 1도의 거리는 위도에 따라
  줄어들므로 `cos` 보정한다

막대 너비는 배율마다 달라져 클래스로 뺄 수 없다. **`style` 속성 대신 SVG 기하 속성으로
그렸다** — bbox 오버레이(§2.9)와 같은 방식이고, `width`·`path`는 스타일이 아니라
기하 정보라 CSP와 무관하다. **한 번 데인 방식을 반복하지 않으려고 검증된 패턴을 골랐다.**

#### 그리고 내가 만든 버그

축척 계산을 `idle` 리스너 안, 그것도 `fittedRef` 가드 **뒤에** 넣어서 영영 뜨지 않았다.

```js
if (!fittedRef.current) return   // bbox 전용 가드인데 축척까지 막았다
setScale(...)
```

게다가 `fitBounds`가 뷰포트를 바꾸지 않으면 `idle`이 **한 번도 오지 않는다.**
가드 밖으로 빼고, 지도 생성 직후 1회 계산하고, `bounds_changed`를 구독해 고쳤다.
같은 값이면 이전 객체를 그대로 돌려줘 드래그 중 리렌더를 막는다.

> **교훈: 다른 목적으로 만든 가드 안에 새 로직을 얹지 않는다.** 가드의 사유가 새 로직에도
> 적용되는지 먼저 본다. 이번 건 "첫 조회 결과를 지우지 않으려고" 만든 가드였고 축척과는
> 아무 상관이 없었다.

`unsafe-inline`은 끝까지 건드리지 않았다. 시연 나흘 전에 보안 헤더를 흔들 이유가 없고,
필요한 화면은 전부 우리 CSS로 만들 수 있었다.
