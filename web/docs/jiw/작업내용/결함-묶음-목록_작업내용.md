# 묶음을 누르면 구성원 목록이 열린다

- **날짜:** 2026-08-06
- **범위:** `/defects` 지도의 묶음(cluster) 클릭. `web/frontend/gilbom/src/features/defect/` 안에서 끝났다.
- **한 줄:** 묶음 안이 **10건 이하**면 확대와 함께 지도 위 왼쪽에 구성원 목록을 편다.
  줄마다 결함 코드·사진·위치가 있고, 누르면 목록 표에서 고른 것과 똑같이 상세 카드가
  뜨고 그 마커에 선택 표시가 붙는다.

---

│ ┌──────────────────────┐ │                             │
│ │ 이 위치의 결함 3건  ✕ │ │      ┌───────────────────┐  │

시안은 직방류 부동산 앱의 "지도 위 매물 목록"을 벤치마킹했다.

| 파일 | 무엇 |

| `DefectMap.tsx` | 묶음 클릭 시 10건 이하면 목록도 연다. `clusterList` 상태 |

| `e2e/defect-cluster.spec.ts` | 묶음 목록 4개 추가, 스텁에 상세·이미지 종단 추가 |

## 2. 설계 판단과 그 이유

### 2.1 왜 10건인가

두 가지가 함께 걸린다.

- **화면**: 목록이 지도를 가리지 않을 만한 길이가 그쯤이다. 스무 건이면 목록이 지도
  높이를 다 먹고, 그럴 바에는 아래 목록 표를 보는 게 낫다.
- **요청 수**: 지도 GeoJSON(`/defects/map`)의 속성에는 **결함 코드까지만** 있다 —
  사진 URL도 위치 이름도 없다. 그래서 결함 하나마다 상세와 이미지 URL을 따로 받는다.
  10건이면 최대 20번이고, **묶음을 누른 순간에만** 나간다.

10건을 넘으면 지금처럼 확대만 한다.

### 2.2 왜 서버 계약을 늘리지 않았나

`/defects/map`의 properties에 `locationLabel`·`representativeImageUrl`을 얹으면 요청이
1번으로 준다. 하지만 그 응답은 **화면에 보이는 결함 전부**(수백 건일 수 있다)에 대해
나가고, 그중 목록으로 펼쳐보는 건 한 묶음뿐이다. 안 쓸 값을 전부 실어 나르는 쪽이
비싸다. 게다가 이미지 URL은 만료가 짧은 서명 URL이라, 지도 조회 때 미리 발급해두면
목록을 열 때쯤 만료돼 있을 수 있다. **필요할 때 그 건에 대해서만** 받는 편이 맞다.

### 2.3 목록은 고른 뒤에도 닫지 않는다

줄을 누르면 상세 카드가 오른쪽에 뜬다. 이때 목록을 닫으면 형제 결함으로 넘어갈 때마다
묶음을 다시 눌러야 한다. 목록(왼쪽 300px)과 카드(오른쪽 340px)가 겹치지 않게 배치해
둘을 함께 띄운다 — 지도가 가로 폭을 전부 쓰게 된 뒤라 자리가 난다.

선택한 결함은 원래도 묶음에서 빠져 낱개 마커로 그려지고 `is-selected`가 붙는다
(`DefectMap`의 marker effect). 목록에서 골라도 같은 경로를 타므로 마커 표시는 공짜로 따라온다.

### 2.4 사진 상태는 셋이다

`undefined`(조회 중) / `null`(없음) / URL. 둘을 뭉뚱그리면 사진이 없는 결함에 자리표시가
영영 돈다. 404는 "아직 이미지가 연결되지 않은 정상 상태"라 오류로 보이지 않게 `null`로
접는다. 그 밖의 오류도 목록에서는 마찬가지로 접는다 — 목록에서 이미지 오류를 알려봐야
사용자가 할 수 있는 일이 없고, 상세 카드는 그 오류를 제대로 보여준다.

## 3. 작업 중 겪은 함정

### 3.1 `react-hooks/set-state-in-effect`가 두 곳에서 걸렸다

이 저장소의 eslint는 **effect 본문에서 동기 setState를 금지**한다. 두 자리를 각각 다르게 풀었다.

- **묶음이 바뀔 때 이전 사진·위치를 지우는 것** → `setEntries({})` 대신 상위에서
  `key={구성원 id들}`을 줘서 컴포넌트를 **새로 마운트**한다. 초기 state가 곧 빈 값이다.
- **조건이 바뀌면 목록을 닫는 것** → `setClusterList(null)` 대신 **어느 조건에서 편
  것인지 함께 저장**하고 렌더에서 걸러낸다. 이 파일이 `viewport`·`featureSnapshot`에
  이미 쓰고 있는 방식이다.

```ts
const [clusterList, setClusterList] = useState<{
  filterKey: string
  features: DefectMapFeature[]
} | null>(null)
const visibleClusterList = clusterList?.filterKey === filterKey
  ? clusterList.features
  : null
```

### 3.2 배열을 effect 의존성에 그대로 넣으면 조회가 멈추지 않는다

`features`는 매 렌더 새 참조다. `defectId`를 이어붙인 문자열을 의존성으로 쓴다.

### 3.3 e2e 스텁에 상세·이미지 종단을 더해야 했다

`defect-cluster.spec.ts`의 `stubMap`은 지도 GeoJSON만 막고 있었다. 목록이 결함마다
`/defects/{id}`와 `/defects/{id}/image-url`을 부르므로 둘을 더했다. `defectAt(i)`가 만드는
id의 **끝 12자리가 `i+1`**이라 그것으로 몇 번째 결함인지 되찾는다.

사진은 실제로 받아지는 URL이어야 `<img>`가 깨지지 않으므로 1×1 PNG를 따로
`page.route`로 물렸다. `defectAt`의 세 번째 건은 이름이 없어(`locationLabel: null`)
구역 코드로 떨어지는 경로까지 함께 시험한다.

## 5. 남은 것

### 내 몫

- **목록은 묶음을 누른 시점의 구성원 그대로다.** 지도를 옮기거나 확대해도 갱신되지
  않는다(조건이 바뀔 때만 닫힌다). 그 편이 "방금 누른 그 덩어리"를 계속 보여줘서 낫다고
  봤지만, 병합 등으로 사라진 결함을 누르면 상세가 404가 난다.
- 목록에 키보드 이동(↑↓)은 없다. Tab으로 줄을 훑는 것은 된다.
- 좁은 화면(≤700px)에서는 목록과 상세 카드가 겹친다. 지금 이 화면은 좌우 여백이 넉넉해
  겪지 않지만, 모바일을 받으면 목록을 시트로 내려야 한다.

### 다른 팀원 몫

- 없다. `features/defect`와 그 e2e 안에서 끝났다.

## 6. 2차 — 목록에서 고르면 마커가 지도 가운데로 (같은 날)

카드만 떠도 **마커가 화면 밖이면 어디 일인지 알 수 없다.** 두 목록(아래 목록 표, 묶음
목록) 어느 쪽에서 고르든 그 결함이 지도 가운데로 오게 했다.

### 6.1 선택이 아니라 "요청"에 반응한다

`selectedDefectId`가 바뀔 때마다 옮기면 **지도 마커를 눌렀을 때도** 지도가 미끄러진다.
이미 그 자리를 보고 있는데 손가락 밑에서 지도가 움직이면 방금 무엇을 눌렀는지 놓친다.
그래서 선택 상태를 보지 않고, 목록이 보내는 요청에 반응한다.

- **묶음 목록**은 `DefectMap` 안에 있어 직접 옮긴다. `onSelect`가 좌표까지 넘긴다.
- **아래 목록 표**는 페이지에 있어 `centerRequest` prop으로 내려보낸다.

```ts
export type DefectMapCenterRequest = {
  latitude: number
  longitude: number
  token: number   // ← 이게 핵심
}
```

**`token`이 없으면 같은 행을 다시 눌렀을 때 아무 일도 일어나지 않는다.** 선택이 그대로라
좌표도 그대로고, effect 의존성이 안 바뀐다. 지도를 딴 곳으로 끌어놓고 같은 행을 다시
누르는 것이 "가운데로 되돌려 달라"는 뜻인데 그게 죽는다. 요청마다 token을 올린다.
(e2e `같은 행을 다시 눌러도 가운데로 되돌아온다`가 이 회귀를 지킨다.)

### 6.2 배율은 건드리지 않는다

`panTo`만 하고 `setZoom`은 하지 않는다. 고른 결함을 **보려는** 것이지 더 들여다보려는
것이 아니고, 확대까지 바뀌면 주변 결함이 화면에서 사라져 맥락을 잃는다.

### 6.3 `panTo`는 있을 수도, 없을 수도 있다

우리 `src/types/naver-maps.d.ts`는 우리가 쓰는 것만 선언한 손수 만든 타입이라 `panTo`가
없었다. 선택적 메서드(`panTo?`)로 추가하고 호출부에서 확인한다 — SDK 버전에 따라 없을
수 있고, **움직임을 줄이는 설정**(`prefers-reduced-motion`)에서도 미끄러지는 대신
`setCenter`로 순간 이동한다. 목록에서 고를 때 지도까지 스크롤하는 기존 코드가 이미 같은
설정을 보고 있어 결이 맞다.

그래서 e2e도 `test.use({ reducedMotion: 'no-preference' })`로 고정해야 한다. 안 그러면
실행 환경에 따라 `panTo`가 아니라 `setCenter`가 불려 단정이 흔들린다.

### 6.4 e2e 3개 추가 (총 32개)

가짜 지도 SDK에 `panTo`를 더하고 옮겨간 자리를 따로 기록했다(`mapCalls.panned`).
`setCenter`와 섞어 세면 첫 화면 맞추기(`fitBounds`)·묶음 확대와 구분되지 않는다.

목록 표를 쓰는 시험을 위해 `stubMap`에 목록 응답 인자를 더했다 — 전에는 늘 빈 목록이었다.
