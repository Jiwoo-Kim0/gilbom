## 1. 배경

필터 패널이 세로로 너무 길었다. 처리 상태 6개 + 결함 유형 4개 + 심각도 4개, **체크박스
14개가 모두 펼쳐져 있어** 사이드바 아래쪽의 "최소 AI 신뢰도" 슬라이더와 "필터 초기화"가
스크롤 없이는 보이지 않았다. 지도·목록보다 필터가 긴 화면이 됐다.

종료 날짜 입력도 실효가 없었다. 결함은 미래에 생기지 않으니 상한은 늘 "지금"이고,
프리셋 버튼("오늘", "지난 7일", "지난 30일")은 그 "지금"을 눌린 순간의 값으로 못박아
넣고 있었다.

## 3. 설계 판단과 그 이유

### 3.1 조건 셋만 접었다. 검색·날짜·신뢰도는 그대로 뒀다

접는 이유는 "길이"뿐이므로, 한 줄이면 끝나는 컨트롤을 굳이 클릭 뒤로 숨기지 않았다.
드롭다운으로 바꾼 것은 항목이 여럿인 다중 선택 셋(처리 상태·결함 유형·심각도)뿐이다.

### 3.2 닫힌 상태에서도 무엇이 걸려 있는지 보인다

접기의 대가는 "지금 무슨 조건이 걸렸는지 안 보인다"다. 트리거 버튼에 요약을 남겨 그것을
막았다.

- 선택 없음 → `전체` (빈 배열은 조건 없음, 즉 전체 조회다)
- 1~2개 → 라벨을 이어붙임 (`신규, 접수`)
- 3개 이상 → `신규 외 3개` + 오른쪽에 개수 배지

첫 진입 기본값이 `NEW·ACCEPTED·IN_PROGRESS` 셋이므로, 열자마자 트리거에 `신규 외 2개`와
배지 `3`이 보인다. **종결 결함이 기본으로 빠져 있다는 사실이 접힌 채로도 드러난다.**

### 3.3 선택 상태는 여전히 URL이 소유한다

드롭다운은 **열림 여부만** 자기 `useState`로 갖는다. 체크 결과는 그대로 부모의
`onChange` → URL query다. 링크 공유와 새로고침 유지가 깨지지 않는다.

체크할 때마다 URL이 바뀌어 리렌더가 일어나지만, 컴포넌트가 언마운트되지 않으므로
**패널은 열린 채 남는다.** 여러 개를 연달아 체크할 수 있다.

### 3.4 패널은 아래 컨트롤을 밀지 않고 그 위에 얹는다

`position: absolute` + `z-index: 20`. 펼칠 때 아래 항목이 밀려 내려가면 방금 누른 위치가
움직여 다음 클릭이 어긋난다. `.defect-filter`나 `.content-card`에 `overflow: hidden`이
없어 그대로 얹힌다.

### 3.5 종료 시각은 UI·URL에서만 뺐다. 타입과 API에는 남겼다

`DefectFilters.to`와 `defectApi`의 `to` 처리는 지웠다면 요약 조회
(`getDefectSummary`의 `Pick<DefectFilters, 'from' | 'to' | 'patrolAreaId'>`)까지
번졌다. 기간을 못박아 조회하는 쪽에는 상한이 필요하므로 계약은 그대로 두고,
**결함 필터 패널만 노출을 끊었다.**

대신 `readFilters`에서 `to`를 읽지 않게 했다. 그러지 않으면 예전 링크에 남은 `to=`가
**화면에 보이지 않는 상한**으로 계속 걸려 "왜 새 결함이 안 나오지"가 된다. 프리셋도
`to: ''`를 함께 써서 남아 있던 값을 지운다.

### 3.6 접근성

- 트리거는 `aria-expanded`·`aria-controls`. 버튼 안에는 `전체`처럼 값만 있어
  그것만으로는 무슨 조건인지 알 수 없으므로, 위의 라벨과 함께 읽히도록
  `aria-labelledby="{라벨} {트리거}"`로 묶었다 → "처리 상태, 전체".
- 패널은 `role="group"` + `aria-label`.
- Esc로 닫고 **포커스를 트리거로 되돌린다.** 사라진 패널 안에 포커스를 남기면 키보드
  사용자가 자기 위치를 잃는다.
- 바깥 클릭은 `pointerdown`으로 닫는다.

## 4. 작업 중 겪은 함정

### 4.1 effect에서 setState는 lint가 막는다

`disabled`가 켜지면 열린 패널을 닫으려고 `useEffect(() => { if (disabled) setOpen(false) })`
를 썼더니 `react-hooks/set-state-in-effect`가 에러로 잡았다(경고가 아니라 에러다).

파생값으로 바꿨다.

```tsx
const expanded = open && !disabled
```

렌더에서 가리기만 하므로 `disabled`가 풀리면 원래 상태로 돌아온다. effect보다 짧고
동작도 낫다.

### 4.2 `.defect-filter-checkbox + .defect-filter-checkbox`가 이중 간격을 만들었다

패널이 `display: grid; gap: 10px`인데 기존 인접 선택자 규칙의 `margin-top: 10px`이 더해져
20px가 됐다. 이 클래스는 이제 드롭다운 패널에서만 쓰이므로 인접 규칙을 지웠다.

### 4.3 WSL에서 프론트를 띄우는 방법 — Linux node가 없다

이 WSL에는 **Linux node가 설치돼 있지 않다**(`command -v node`가 빈 결과). `npx`/`npm`은
Windows 쪽(`/mnt/c/Program Files/nodejs`)으로 잡히고, cmd.exe가 UNC 경로를 작업
디렉터리로 못 써서 `npm run dev`·`npm run lint`가 통째로 실패한다.

정리하면 이렇게 나눠 쓴다.

| 무엇 | 어떻게 |
| --- | --- |
| tsc / eslint / node --test | `"/mnt/c/Program Files/nodejs/node.exe" node_modules/<도구>` — 순수 JS라 Windows node로 돌아간다 |
| vite dev | Windows node로는 **안 된다.** `node_modules`가 Linux용으로 설치돼 있어 `@rolldown/binding-win32-x64-msvc`가 없다 |

그래서 dev 서버는 컨테이너로 띄웠다.

```bash
docker run -d --rm --name gilbom-vite-ui -p 4174:4174 \
  -v /home/ssafy/S15P11D101/web/frontend/gilbom:/app -w /app \
  -e VITE_NAVER_MAP_CLIENT_ID=e2e-map-client \
  node:24.18.0-alpine node node_modules/vite/bin/vite.js --host 0.0.0.0 --port 4174
```

`--network host`는 **쓰면 안 된다.** 여기 docker는 Docker Desktop이라 host 네트워크가
WSL이 아니라 Docker VM이고, 그러면 WSL·Windows 어디서도 포트가 안 보인다.
`-p`로 퍼블리시해야 (기존 `gilbom-frontend`가 `127.0.0.1:3000`으로 보이는 것과 같은 방식)
양쪽에서 붙는다. `--host 0.0.0.0`도 필요하다.

### 4.4 Playwright 임시 스펙은 프로젝트 안에 둬야 한다

설정·스펙을 스크래치패드(`/tmp/...`)에 두면 `@playwright/test`를 못 찾는다
(`node_modules`가 부모 경로에 없다). 프로젝트 하위 임시 폴더에 두고 끝나면 지웠다.

또 Windows Playwright가 WSL 공유로 만든 `test-results/`는 **root 소유로 생겨 `rm`이
막힌다.** 만든 쪽에서 지워야 한다.

```bash
powershell.exe -NoProfile -Command "Remove-Item -Recurse -Force '\\wsl.localhost\Ubuntu\...\test-results'"
```

### 4.5 `check()`는 실패하고 `click()`은 성공했다

`<label>` 안의 체크박스를 Playwright `check()`로 누르면
`Clicking the checkbox did not change its state`가 났다. 같은 요소를 `click()`으로 누르면
정상이다(`isChecked() === true`, URL에 `status=RESOLVED` 추가). 실제 동작에는 문제가 없고
`check()`의 검증 방식 문제라, 시간을 더 쓰지 않고 `click()`으로 확인했다. **결함 화면
e2e를 쓸 때 같은 곳에서 막힐 수 있다.**

커밋하지 않았다. 다시 볼 일이 있으면 이 시나리오를 다시 만든다.

## 7. 2차 — 검색 분리, 필터를 지도 오른쪽으로, 기간 조건 제거

같은 날 손그림 시안으로 배치를 다시 받았다.

```
┌──────────────────────────────────────┐
│                검색                   │   ← 가로 전체
└──────────────────────────────────────┘
┌───────────────────────┐ ┌──────────┐
│                       │ │          │
│         지도           │ │   필터    │   ← 필터가 오른쪽
│                       │ │          │
└───────────────────────┘ └──────────┘
```

### 7.1 무엇을 바꿨나

| 파일 | 변경 |
| --- | --- |
| `DefectSearchBar.tsx` | **신규.** 검색만 떼어낸 가로 카드. 돋보기 아이콘 + `type=search` |
| `DefectFilter.tsx` | 검색·날짜 범위 삭제. 이제 조건 드롭다운 3개 + 신뢰도 + 초기화뿐 |
| `DefectManagePage.tsx` | 검색바를 지도 위로, `defect-layout` 안 순서를 지도 → 필터로 |
| `defectTypes.ts` | `from`도 `to`와 함께 "화면은 노출하지 않는다"로 주석 |
| `App.css` | `.defect-layout`을 `1fr 280px`로 뒤집고 `.defect-search-bar` 추가, 쓰지 않게 된 날짜 프리셋 스타일 삭제 |

검증: `tsc -b`·`eslint`·단위 테스트 44 pass. Playwright로 배치를 좌표까지 확인했다(§7.5).

### 7.2 검색은 왜 컴포넌트로 뺐나

필터 패널 안에 있던 검색창은 **폭이 280px에 묶여** `결함 코드·위치 검색` placeholder가
겨우 들어가는 크기였다. 위로 올려 921px을 쓰게 했다.

카드 자체를 입력처럼 보이게 하고 `input`의 테두리·배경은 지웠다. 카드 테두리와 입력
테두리가 겹치면 이중선이 된다. 포커스 표시는 `:focus-within`으로 **카드 쪽에** 준다.

### 7.3 기간 조건은 UI에서 완전히 빼고 계약만 남겼다

날짜 범위(프리셋 3개 + 시작 입력)를 지웠다. 조치 대상 결함을 고를 때 "언제 것인지"보다
상태·심각도가 기준이라, 실제로 눌러 쓰는 조건이 아니었다.

`DefectFilters.from`·`to`와 `defectApi`의 처리는 **남겼다.** 지우면
`getDefectSummary(Pick<DefectFilters, 'from' | 'to' | 'patrolAreaId'>)`까지 번지고,
기간을 못박아 조회하는 쪽에는 상한·하한이 필요하다.

대신 `readFilters`에서 `from`도 읽지 않게 했다(1차에서 `to`에 한 것과 같은 이유).
**화면에 없는 조건이 URL로만 걸려 있으면 "왜 결함이 안 나오지"의 원인이 되고, 화면
어디에도 단서가 없다.**

### 7.4 배치는 DOM 순서를 그대로 두고 CSS로만 뒤집었다

`.defect-layout`을 `280px 1fr` → `minmax(0, 1fr) 280px`로 바꾸고 JSX 순서도 지도 → 필터로
맞췄다. 그러면 좁은 화면(≤820px, 한 줄로 접힘)에서 필터가 **420px 지도 아래**로 밀린다.
`@media`에서 `.defect-filter { order: -1 }`로 올렸다. 검색 → 필터 → 지도 순이 된다.

`minmax(0, 1fr)`이어야 한다. 그냥 `1fr`이면 지도 캔버스가 커질 때 그리드가 밀려 필터가
잘린다.

### 7.5 확인한 것

Playwright로 좌표를 직접 비교했다(임시 스펙, 커밋하지 않음).

- 검색 `y=287 < 지도 y=365`, 검색 폭 `921 > 필터 폭 280 × 2`
- 필터 `x=948`, 지도 `x=307 + 폭 623 = 930` → **필터가 지도 오른쪽에 있다**
- 필터 안에 `searchbox` 0개, `날짜 범위`·`오늘`·`시작` 텍스트 0개
- 검색 입력 → URL `q=DEF-UI`, 조회 쿼리도 `q=DEF-UI` 포함
- `필터 초기화` → 검색창까지 빈 값 (§7.6)
- 760px 폭에서 필터 `y=371 < 지도 y=813`

### 7.6 초기화는 검색어까지 지운다

`필터 초기화`는 `EMPTY_DEFECT_FILTERS`를 그대로 쓰므로 검색어도 지운다. 검색창이 카드
밖으로 나갔어도 **검색은 조건의 일부**이고, 위에 보이는 창이 함께 비워지니 숨은 동작이
아니다.

## 9. 3차 — 시작 날짜 되살리기와 목록 표 가독성

2차에서 기간 조건을 통째로 뺐는데 **시작일은 필요하다**는 피드백을 받았다. 그리고

### 9.1 무엇을 바꿨나

| 파일 | 변경 |
| --- | --- |
| `DefectFilter.tsx` | `시작 날짜` date 입력 + `전체 기간`(지우기), 힌트 문구 |
| `DefectManagePage.tsx` | URL `from` 읽기·쓰기 복구 (`to`는 그대로 안 쓴다) |
| `defectTypes.ts` | `from`/`to` 주석을 각각의 역할로 나눠 다시 씀 |
| `DefectList.tsx` | 시각 `hour12: false`, 위치는 이름만 + 전체 값은 `title`, 셀 클래스 |
| `App.css` | 표 8열 폭 확정, 행 구분선·hover·선택 강조, 심각도·상태 배지 색, 상태 점 색 |

검증: `tsc -b`·`eslint`·단위 테스트 44 pass. 브라우저에서 열 폭·행 높이·넘침을 측정했다(§9.6).

### 9.2 시작 날짜는 날짜만 받고 값은 시각까지 들고 간다

서버는 `from`을 `d.last_seen_at >= :from`으로 걸고(`DefectFilter.java`), `defectApi`는
`new Date(filters.from).toISOString()`으로 보낸다. 그래서 `<input type="date">`의
`2026-08-03`을 그대로 넣으면 **UTC 자정으로 해석돼 KST에서는 9시간 밀린다.**

`filters.from`은 datetime-local 문자열로 유지하고 입출력만 변환했다.

```tsx
toDateInputValue: from.slice(0, 10)          // 2026-08-03T00:00 → 2026-08-03
fromDateInputValue: `${date}T00:00`          // 2026-08-03 → 2026-08-03T00:00
```

실제로 나가는 값을 확인했다: 브라우저가 KST일 때 `from=2026-08-02T15:00:00.000Z`.
**로컬 자정이 맞게 넘어간다.**

입력 라벨은 `시작 날짜`이지만 서버 기준은 **최근 관측(`last_seen_at`)**이다.
"최초 발견"으로 읽으면 오해하므로 입력 아래에 `이 날짜 이후 관측된 결함`을 붙였다.

`type="date"`만으로는 값을 비울 방법이 마땅치 않아 legend 오른쪽에 `전체 기간` 링크
버튼을 뒀다. 누르면 `from: ''`이 되어 URL·조회에서 조건이 빠진다.

### 9.3 표는 열 폭이 문제였다 — fr를 6개만 적어 놨다

```css
/* 이전 */
grid-template-columns: 90px 1.4fr 1.4fr 1.1fr 0.8fr 0.6fr;
```

**열은 8개인데 템플릿에 6개만 있었다.** 신뢰도·상태는 암묵 열(auto)로 밀려나고,
`유형`·`심각도`가 각각 1.4fr로 **가장 넓은 두 열**이 됐다. 정작 값이 긴 `위치`는
1.1fr이라 세 줄로 접혀 행 높이가 들쭉날쭉했다.

값 폭이 정해진 열은 px로 못박고 **남는 폭은 위치가 받게** 했다.

| 열 | 폭 | 근거 |
| --- | --- | --- |
| 결함 코드 | 140px | `INC-20260805-000123` 19자. 13px + `tabular-nums`로 137px |
| 유형 | 68px | 가장 긴 `설치 이상` |
| 심각도 | 64px | 배지 `심각` |
| 위치 | `minmax(0, 1fr)` | 남는 폭 전부 (1280px 화면에서 158px) |
| 최근 관측 | 104px | `26. 08. 01. 09:30` |
| 반복 / 신뢰도 | 44 / 52px | `12회`, `91%` |
| 상태 | 108px | 상태 배지 + `검토` 배지가 한 줄에 들어가는 폭 |

`minmax(0, 1fr)`이어야 한다. 그냥 `1fr`이면 최소 폭이 콘텐츠 크기라 긴 위치 값이 열을
밀어내고 `text-overflow`가 걸리지 않는다.

### 9.4 위치는 이름만 찍는다

이름 + 좌표를 한 칸에 넣으면 `역삼역 3번 출구 앞 보도 · 37.50123, 127.04321`처럼
284px가 되어 어떤 폭에서도 **좌표 중간에서 잘린다.** 잘린 좌표는 아무 정보가 아니다.

- 이름이 있으면 **이름만** 찍고, 좌표까지 담은 전체 값은 `title`에 남긴다.
- 구역 코드만 있을 때는 같은 구역 결함이 전부 같은 값이 되므로 **좌표를 함께** 남긴다
  (원래 주석의 경고를 그대로 살렸다).
- 좌표는 상세 카드와 지도에 그대로 있다.

시각도 `hour12: false`로 바꿨다. `오전/오후`가 붙으면 열이 40px쯤 넓어지고, 세로로
훑을 때 숫자 위치가 어긋난다.

### 9.5 심각도·상태 배지는 클래스만 있고 CSS가 없었다

`DefectList`는 처음부터 `defect-risk defect-risk-critical`,
`defect-status defect-status-new`, `defect-review-flag`를 붙이고 있었는데
**어느 CSS 파일에도 그 규칙이 없었다.** `<em>`이라 기울어진 맨 텍스트로 나왔고,
심각도 `심각`과 상태 `완료`가 같은 모양이라 훑을 수 없었다.

배지로 만들고 색을 넣었다. 색 배합은 `report.css`의 상태 배지(연한 배경 + 진한 글자 +
같은 계열 테두리)를 그대로 따랐다. 심각도는 회색→호박→주황→빨강, 상태는 신규(호박)·
접수(파랑)·처리 중(금색)·완료(초록)·오탐/반려(회색)다. `검토`는 상태와 나란히 붙으므로
채우지 않고 테두리만 준다.

같은 이유로 **필터 드롭다운의 상태 점도 전부 회색이었다.** 점 클래스는 상태 코드로
만들어지는데(`defect-status-dot-new`), CSS에 있던 이름은 지도 범례용
(`-received`·`-progress`·`-done`)이라 하나도 걸리지 않았다. 목록 배지와 같은 색으로 맞췄다.

행에도 손을 댔다. 구분선(`border-top`), hover 배경, `cursor: pointer`(행 클릭이 상세
열기인데 커서가 화살표였다), 선택된 행은 왼쪽 3px 금색 + 연한 배경이다.

### 9.6 확인한 것

브라우저에서 값을 직접 재서 확인했다(임시 스펙, 커밋하지 않음).

- 열 폭: 코드 140 / 유형 68 / 심각도 64 / **위치 158** / 최근 관측 104 / 반복 44 /
  신뢰도 52 / 상태 108 → **유형·심각도 < 위치**
- 행 높이 8행 모두 49px (예전에는 위치가 접혀 들쭉날쭉했다)
- 넘치는 칸: 긴 이름의 위치 하나뿐(201 > 158, ellipsis + title). 코드·시각·배지는 안 넘침
- `.defect-risk-critical`의 `font-style: normal`, 배경색 `rgb(255, 240, 240)`
- 시작 날짜 `2026-08-03` → URL `from=2026-08-03T00%3A00`,
  조회 `from=2026-08-02T15:00:00.000Z`, `to=` 없음
- `전체 기간` 클릭 → URL·조회에서 `from` 사라짐

## 11. 4차 — 열이 겹쳐 보이던 원인과 열 간 여유

3차 결과에서 **결함 코드와 유형이 겹쳐 보이고, 최근 관측과 반복이 붙어 보인다**는
피드백을 받았다. 원인이 두 가지로 갈렸다.

### 11.1 정말 겹쳐 있었다 — `overflow: hidden`이 없었다

`.defect-cell-code`에 `white-space: nowrap`만 주고 `overflow: hidden`을 빼놨다.
그러면 넘친 글자가 잘리지 않고 **옆 칸 위에 그대로 그려진다.** 코드는 140px 열에
137px이라 글꼴이 조금만 달라지면 바로 넘쳤다.

셀 공통 규칙으로 올렸다. 이제 어떤 값이 얼마나 길어도 자기 칸 안에서 잘린다.

```css
.defect-table-row > span {
  min-width: 0;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

**이걸 `.defect-cell-location`이 이기지 못해 한 번 더 막혔다.**
`.defect-table-row > span`은 특이도 (0,1,1)이고 `.defect-cell-location`은 (0,1,0)이다.
그래서 위치 열의 `white-space: normal`이 무시되고 nowrap이 그대로 걸려, 두 줄로 접히지
않고 한 줄로 넘쳤다. 선택자를 `.defect-table-row > .defect-cell-location`으로 올려
(0,2,0) 해결했다. **잉크 폭을 재는 검증(§11.4)이 없었으면 그냥 지나쳤다** — 넘친 부분이
`overflow: hidden`으로 잘려 화면상으로는 그럴듯해 보였다.

### 11.2 붙어 보인 쪽은 값이 칸을 꽉 채워서였다

`최근 관측`은 `toLocaleString('ko-KR')`이 만든 `26. 08. 01. 오전 09:30`이라 104px 열을
거의 다 채웠다. 열 사이 여백이 12px뿐이니 `09:30`과 `1회`가 한 덩어리로 읽혔다.

- 표에서 쓸 시각은 직접 조립했다. `08.01 19:30`. **올해 것은 연도를 뺀다**(대부분이
  올해라 `26.`이 모든 행에 똑같이 붙어 폭만 먹었다). 해가 넘어간 결함만
  `25.12.31 08:45`로 연도가 붙어 오히려 눈에 걸린다.
- 열 간 여백을 `gap: 12px → 18px`, 행 좌우 padding도 `16px → 18px`로 넓혔다.
- 배지 열(심각도 58px, 신뢰도 46px)은 값이 짧아 여유가 남았으므로 줄여서 그 폭을
  위치 열에 넘겼다.

### 11.3 위치는 두 줄까지 허용했다

폭을 아무리 배분해도 1280px 화면에서 위치는 124px이다. 한 줄이면 8자밖에 안 들어간다.
두 줄까지 허용해 `역삼역 3번 출구 앞 보도`가 끝까지 보이게 했다.

```css
display: -webkit-box;
-webkit-box-orient: vertical;
-webkit-line-clamp: 2;
word-break: keep-all;   /* 한국어 단어 중간에서 끊지 않는다 */
```

두 줄이 되면 행 높이가 행마다 달라지므로 `.defect-table-body-row`에
`min-height: 64px`를 줘서 **한 줄짜리 행도 같은 높이**가 되게 했다. 62px로 잡았을 때는
반올림 때문에 행마다 62·63px로 1px씩 흔들렸다.

1440px 화면에서는 위치가 한 줄로 다 들어가고, 그때도 행 높이는 64px로 같다.

### 11.4 확인한 방법 — 열 폭이 아니라 "잉크 사이"를 쟀다

열 폭만 재면 안 된다. 칸이 넓어도 값이 칸을 꽉 채우면 옆 값과 붙어 보인다. 그래서
`document.createRange()`로 각 칸의 **실제 글자 영역**을 잡고 인접한 두 칸의
`right`–`left` 차이를 8행 전부에 대해 재서 최솟값을 봤다.

| 인접 열 | 이전 | 지금 |
| --- | --- | --- |
| 결함 코드 → 유형 | **겹침**(넘쳐서 덮음) | 27px |
| 유형 → 심각도 | — | 35px |
| 심각도 → 위치 | — | 36px |
| 위치 → 최근 관측 | — | 24px |
| 최근 관측 → 반복 | 16px | 21px |
| 반복 → 신뢰도 | — | 26px |
| 신뢰도 → 상태 | — | 36px |

그밖에 확인한 것: 8행 모두 높이 64px, 잘린 칸 0개(위치까지 두 줄로 다 들어감),
1440px에서도 최소 여유 유지. 최악값(`INC-20260805-000008`, `설치 이상`, `128회`,
`25.12.31 08:45`, 구역 코드 + 좌표)을 데이터에 섞어 재확인했다.

## 13. 5차 — 목록에서 고르면 지도까지 화면을 올린다

상세 카드는 지도 위에 뜨는데(`DefectMap` 안 `.defect-map-canvas-wrap`) 목록은 지도
아래에 있다. 목록 20행을 스크롤해 내려간 뒤 행을 누르면 **카드는 화면 위쪽 1300px
밖에서 열렸다.** 눌러도 아무 일도 안 일어난 것처럼 보인다.

### 13.1 스크롤은 목록에서 고를 때만 한다

지도 마커로 고를 때는 이미 지도를 보고 있으니 화면이 움직일 이유가 없다. 그래서
`DefectMap`의 `onSelect`는 그대로 `setSelectedDefectId`를 쓰고, `DefectList`에만
스크롤까지 하는 핸들러를 따로 넘겼다.

```tsx
const selectFromList = useCallback((defectId: string) => {
  setSelectedDefectId(defectId)
  const reduceMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches
  mapCardRef.current?.scrollIntoView({
    behavior: reduceMotion ? 'auto' : 'smooth',
    block: 'start',
  })
}, [])
```

`prefers-reduced-motion`을 켠 사용자에게 1300px을 부드럽게 흐르는 애니메이션은 멀미를
준다. 그때는 즉시 이동한다.

### 13.2 지도 카드에 ref를 뚫었다

`DefectMap`에 `cardRef?: RefObject<HTMLElement | null>` prop을 추가해 `<article
className="content-card defect-map-card">`에 걸었다. 페이지가 DOM을
`querySelector`로 뒤지지 않게 하려는 것이다.

화면 맨 위에 딱 붙지 않도록 여백은 CSS로 줬다. JS에 오프셋 숫자를 넣으면 헤더 높이가
바뀔 때마다 같이 고쳐야 한다.

```css
.defect-map-card { scroll-margin-top: 24px; }
```

### 13.3 확인한 것

목록 20행을 만들어 맨 끝까지 스크롤한 뒤 3번째 행을 눌렀다(임시 스펙, 커밋하지 않음).

| | 클릭 전 | 클릭 후 |
| --- | --- | --- |
| `window.scrollY` | 1695 | 342 |
| 지도 카드 top | **-1329px**(화면 밖) | +23.6px(= `scroll-margin-top`) |
| 상세 카드 위치 | — | y=114px, 388px 높이로 화면 안 |

선택된 행의 강조(`.is-selected`)도 그대로 남는다.

### 13.4 겪은 함정 — 스텁이 부실하면 화면이 통째로 사라진다

행을 누르자 `.defect-map-card`가 아예 없어져서 처음에는 내 변경이 언마운트를 일으킨
줄 알았다. 실제로는 상세 카드의 `BoundingBoxOverlay`가 터져 **라우터 에러 화면으로
넘어간 것**이었다.

```
TypeError: Cannot read properties of undefined (reading 'length')
The above error occurred in the <BoundingBoxOverlay> component.
```

`bboxNorm === null || bboxNorm.length !== 4`로 막고 있는데, 내 스텁이 `image-url`
응답에 그 필드를 아예 넣지 않아 `undefined`가 됐다. 서버 DTO는 항상 그 필드를 채우니
실제로는 나지 않는 오류다. **`page.on('pageerror')`를 붙이지 않았으면 원인을 한참
헤맸다.** 결함 화면 e2e를 쓸 때 상세 카드를 여는 시나리오라면 `image-url`까지
제대로 스텁하거나 404로 두어야 한다(404는 "이미지 없음"으로 정상 처리된다).

## 15. 6차 — 시작 날짜만 라벨 간격이 좁던 원인

필터 네 칸 중 **시작 날짜만** 라벨(`시작 날짜`)과 입력(`연도-월-일`) 사이가 붙어 보였다.

### 15.1 원인 — `<legend>`에는 부모의 `gap`이 걸리지 않는다

`.defect-filter-group`은 `display: grid; gap: 10px`인데, 그 안의 라벨을 `<fieldset>` +
`<legend>`로 짜놨다. **legend는 grid 항목이 아니다.** 브라우저가 fieldset 테두리 위에
따로 배치하므로 `gap`이 적용되지 않고, 입력이 legend 바로 아래에 붙는다. 드롭다운 세 칸은
`<span>` 라벨 + 버튼이라 정상적으로 10px이 걸려 있었다.

### 15.2 라벨 구조를 드롭다운과 같게 맞췄다

fieldset/legend를 걷어내고 `div` + `.defect-filter-group-heading`으로 바꿨다. 컨트롤이
하나뿐인 칸이라 그룹 의미의 fieldset보다 `<label htmlFor>`가 맞다.

| 칸 | 이전 | 지금 |
| --- | --- | --- |
| 시작 날짜 | `fieldset > legend` | `div > div.heading > label[for]` |
| 최소 AI 신뢰도 | `fieldset > legend` | `div > label.heading[for]` |

곁들여 고친 것:

- `fieldset[disabled]`이 사라졌으므로 `disabled`를 입력과 `전체 기간` 버튼에 직접 준다.
  안 옮기면 첫 조회 중에도 값을 바꿀 수 있게 된다.
- `input[type="range"]`는 UA가 위아래 2px 여백을 붙인다. 그만큼 어긋나 보여 `margin: 0`.
- 라벨과 입력을 `htmlFor`로 묶었다. 라벨을 눌러도 입력이 열린다(이전에는 legend라 안 됐다).

### 15.3 확인한 것

라벨 아래 끝과 컨트롤 위 끝 사이를 다섯 칸 모두 재서 비교했다(임시 스펙, 커밋하지 않음).

| 칸 | 이전 | 지금 |
| --- | --- | --- |
| 시작 날짜 | **붙어 있었다**(legend라 gap 없음) | 10px |
| 처리 상태 / 결함 유형 / 심각도 | 10px | 10px |
| 최소 AI 신뢰도 | 12px | 10px |

그밖에: 날짜 입력·`전체 기간` 지우기가 URL에 그대로 반영되고, 라벨 클릭 시 입력에
포커스가 간다.

## 17. 7차 — 검색 디바운스 300ms + Enter 즉시 확정

`INC-2026`을 치면 조회가 8번 나갔다. 쓸모 있는 것은 마지막 하나뿐이고 나머지 7번은
버려진다. 중간 결과가 깜빡이며 지나가고, 응답 순서가 뒤바뀌면 엉뚱한 목록이 잠깐 보인다.

### 17.1 300ms 묶기, Enter는 즉시

마지막 입력 뒤 300ms 조용해지면 한 번 보낸다. 보통 타자 간격이 200~300ms라 **치다가
잠깐 멈출 때마다 한 번씩 나가고**, 다 치고 나면 300ms 뒤에 나간다. 그 300ms가 아까운
사람은 Enter로 즉시 보낸다.

타이머는 effect가 아니라 이벤트 핸들러에서 직접 다룬다. effect로 하면 상위가 매 렌더마다
새 `onChange`(인라인 화살표 함수)를 넘기는 탓에 의존성이 흔들려 타이머가 계속 다시
시작된다.

조합 중(IME)에는 타이머를 걸지 않고, `compositionend` 뒤에 건다. 그래서 **한글도 음절마다
나가지 않고 함께 묶인다** — 이전에는 음절이 끝날 때마다 나갔다.

### 17.2 미루기 때문에 생긴 문제 두 개 (둘 다 실제 버그였다)

디바운스는 "요청을 미루는 것"이라, 미루는 사이에 세상이 바뀔 수 있다. 처음 구현에서
두 곳이 깨졌고 시험을 만들면서 드러났다.

**(1) 낡은 `onChange`로 보내 다른 조건을 지웠다.**
타이머가 렌더 당시의 `onChange`를 물고 있으면, 기다리는 사이에 심각도를 고르면
그 시점의 `filters`(심각도 없음)로 URL을 덮어써 **방금 고른 심각도가 사라졌다.**
`onChangeRef`로 항상 최신 것을 부르게 했다. 되돌려 놓고 시험해 실제로 실패하는 것을
확인했다(`severities=CRITICAL`이 빠진다).

**(2) `필터 초기화`가 대기 중인 입력을 취소하지 못했다.**
바깥에서 검색어가 바뀌면 타이머를 버리도록 했는데, 검색어가 **이미 비어 있는 상태에서**
뭔가 치다가 초기화를 누르면 `value`가 `''` → `''`로 그대로여서 컴포넌트가 변화를 알 수
없다. 300ms 뒤 대기 중이던 글자가 되살아나 초기화가 무효가 됐다.

`DefectFilter`에 `onReset` 신호를 주고, 상위가 `key`를 늘려 **검색창을 새로 마운트**하는
방식으로 고쳤다. 언마운트 정리에서 타이머가 지워지고 `draft`도 초기화된다. effect에서
`setState`를 하면 lint(`react-hooks/set-state-in-effect`)가 막으므로, 상태를 지우는
대신 컴포넌트를 다시 만드는 편이 규칙에도 맞았다.

### 17.3 확인한 것

임시 스펙 6개(커밋하지 않음). 세 번 연속 모두 통과했다.

| 시나리오 | 결과 |
| --- | --- |
| 60ms 간격으로 8글자 | 치는 동안 0건, 멈춘 뒤 `q=INC-2026` **1건** |
| 중간에 450ms 멈춤 | `INC` → `INC-2026` 2건 (멈출 때마다 한 번) |
| Enter | 120ms 안에 이미 나감, 이후 중복 없음, 폼 제출로 새로 뜨지 않음 |
| 초기화(대기 중) | 되살아나지 않음, 입력창 비어 있음, URL에 `q` 없음 |
| 한글 IME(CDP `Input.imeSetComposition`) | 조합 중 0건, 확정 뒤 `q=강` 1건 |
| 대기 중 심각도 변경 | `q=INC`와 `severities=CRITICAL`이 함께 실림 |

**함정:** Playwright의 키 입력은 WSL↔Windows CDP 왕복 때문에 글자 사이가 300ms를 넘길
때가 있어, 처음에는 시험이 실행마다 다르게 실패했다(구현 문제로 오인했다). 타자를
`page.evaluate` 안에서 넣어 간격을 페이지 안에서 만들면 안정된다. React는 native input
이벤트를 듣기 때문에 value setter를 직접 부르고 `new Event('input', {bubbles: true})`를
쏘면 된다.

## 19. 8차 — 필터 색을 지도 마커 기준에 맞추고 범례를 되살림

### 19.1 마커 색 기준이 바뀌어 있었다

오늘 들어온 머지(`86985a2`)가 **지도 마커 색을 처리 상태 3단계에서 결함 유형 4종으로**
바꿨다. 파손 빨강, 미설치 파랑, 설치 이상 황토, 기타 이상 보라다. 클러스터는 한 유형이면
그 색, 섞이면 회색이다.

그런데 필터 패널은 여전히 **처리 상태 목록에 색 점**을 달고 있었다. 마커가 상태 색이던
시절의 잔재라, 이제는 아무것과도 짝이 맞지 않는 색이다. 반대로 색이 필요한
**결함 유형 목록에는 점이 없었다.**

그리고 같은 머지가 **지도 범례를 없앴다.** 상태 3색 칩이 사라졌는데 유형 범례는 들어오지
않아서, 빨강·파랑·황토·보라가 무슨 뜻인지 설명하는 것이 화면에 하나도 없었다.

### 19.2 무엇을 바꿨나

| 파일 | 변경 |
| --- | --- |
| `index.css` | 유형 색 5개를 `--defect-damaged` 등 변수로 올림 |
| `App.css` | 마커·클러스터가 그 변수를 쓰게 하고, `.defect-status-dot*` → `.defect-type-dot*` |
| `DefectFilter.tsx` | 처리 상태의 `renderMark` 삭제, 결함 유형에 `defectTypeTone()` 기반 점 추가 |
| `DefectMap.tsx` | 유형 4색 + "여러 유형 묶음" 범례를 지도 위에 되살림, 유형별 개수 표시 |
| `e2e/defect-filter.spec.ts`, `e2e/defect-list.spec.ts` | 유형 점·범례 색이 마커와 같은지, 처리 상태에는 점이 없는지 |

**색 값은 한 곳에만 둔다.** 마커·클러스터·필터 점이 같은 CSS 변수를 쓰므로 "지도의 빨간
핀 = 파손"이 필터에서도 성립하고, 색을 바꿀 때 세 곳을 따로 고칠 일이 없다. 유형 → 색
매핑도 지도가 쓰는 `defectTypeTone()`을 그대로 가져다 쓴다.

곁들여 죽은 CSS를 지웠다. `.defect-status-dot-*`(상태 점)과 `.defect-legend-item-*`
(지도 범례)인데, 범례는 위 머지가 이미 없앤 것이라 선택자만 남아 있었다.

### 19.3 범례는 지금 그려진 마커를 센다

칩에 붙는 개수는 서버 전체가 아니라 **지금 지도에 그려진 features 기준**이다. 뷰포트를
옮기거나 필터를 바꾸면 함께 바뀌어야 "이 화면에 파손이 몇 건"으로 읽힌다. 지도가 아직
준비 중이면 `—`를 보여준다.

"여러 유형 묶음" 칩을 하나 더 뒀다. 클러스터가 여러 유형을 담으면 회색이 되는데, 그 회색도
설명이 필요하다.

### 19.4 확인한 것

- 결함 유형 패널: 점 4개, 색 전부 다름, 첫 항목(파손) 점 색 =
  `.defect-marker-damaged`의 계산된 배경색
- 처리 상태 패널: 점 0개
- 지도 범례: 칩 5개(유형 4 + 묶음 1), 색 전부 다름, 미설치 점 색 = 미설치 마커 색
- 결함 화면 e2e 16개 전부 통과
