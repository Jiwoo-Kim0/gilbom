# 로봇 화면 검색 줄 여백과 지도 범례 작업내용

기간: 2026-08-06
범위: `/robots` 화면 CSS 두 곳(`app/robot/css/robot.css`). 마크업·로직은 그대로다.

관련 문서: [결함-필터-UI-드롭다운_작업내용.md](결함-필터-UI-드롭다운_작업내용.md) §19.4
(결함 지도 범례에 같은 판단을 먼저 적용했다)

> **담당 범위 참고:** 로봇 화면은 B의 영역이다. 이번은 CSS 두 규칙만 손봤고 마크업·상태
> 로직은 건드리지 않았지만, 같은 파일을 고칠 때 충돌할 수 있으니 알고 있어야 한다.

---

## 1. 무엇이 문제였나

**검색 줄이 너무 두꺼웠다.** 한 줄짜리인데 위아래 여백이 32px씩 붙어 높이가 108px이었다.

**지도 범례가 필터 칩처럼 보였다.** 테두리 + 둥근 모서리 알약 모양이라 눌러서 거를 수
있는 것처럼 읽힌다. 실제로는 마커 색 설명일 뿐이다.

---

## 2. 무엇을 바꿨나

| 대상 | 이전 | 지금 |
| --- | --- | --- |
| 검색 줄 위아래 여백 | 32px (높이 108px) | **12px (높이 68px)** |
| 범례 칩 | `border 1px` + `radius 999px`, 높이 38px | **테두리 없음**, 높이 19px |
| 범례 항목 간격 | 10px | 20px |
| 범례 글자 | `--text`(진함) | `--text-muted` |

---

## 3. 함정 — `@import`한 CSS는 특이도가 같으면 진다

`.robot-filter-bar`에는 이미 `padding: 18px 20px`이 있었다. **그런데 화면에는 32px이
적용되고 있었다.**

`App.css`가 첫 줄에서 `@import './app/robot/css/robot.css'`로 들여온다. `@import`한 내용은
그 파일의 앞쪽에 놓이므로, 뒤에 나오는 `App.css`의

```css
.content-card { padding: clamp(22px, 3vw, 32px); }
```

이 같은 특이도(클래스 1개)로 **나중에 선언돼 이긴다.** 1280px 화면에서 `3vw = 38.4px`가
상한 32px로 잘려 32px이 된 것이다.

그래서 클래스를 둘 붙여 특이도를 올렸다.

```css
.content-card.robot-filter-bar { padding: 12px 20px; }
```

**`robot.css`에서 `.content-card`의 값을 덮으려면 항상 이렇게 해야 한다.** 같은 방식으로
쓰인 곳이 더 있는지는 확인하지 않았다(§5).

---

## 4. 확인한 것

브라우저에서 계산된 값을 직접 읽었다(임시 스펙, 커밋하지 않음).

```
이전: searchBar { paddingTop: 32px, height: 108 }  legend { border: 1px, radius: 999px, height: 38 }
지금: searchBar { paddingTop: 12px, height:  68 }  legend { border: 0px, radius: 0px,   height: 19 }
```

스크린샷으로도 검색 줄이 한 줄에 맞게 얇아지고, 범례가 `● 온라인(—) ● 경고(—) …`로
읽히는 것을 봤다.
