# 상단 바 고정(sticky) 작업내용

기간: 2026-08-06
범위: 모든 페이지 공통 상단 바(`App.css`의 `.topbar`)와 그에 딸린 스크롤 여백.
마크업은 그대로다.

관련 문서: [결함-필터-UI-드롭다운_작업내용.md](결함-필터-UI-드롭다운_작업내용.md) §13
(목록에서 고르면 지도까지 스크롤 — 이 변경과 맞물린다)

---

## 1. 무엇을 바꿨나

`.topbar`(페이지 제목 + 계정)를 `position: sticky; top: 0`으로 고정했다. 긴 목록을 내려도
**어느 페이지를 보고 있는지와 로그인한 사람이 계속 보이고**, 위로 되돌아가지 않고도 계정
메뉴로 갈 수 있다.

원래 반투명 배경 + `backdrop-filter: blur(16px)`가 들어가 있었다 — 고정을 염두에 둔
스타일이었고, 사이드바(`.nb-sidebar`)도 이미 `sticky`다. 그래서 붙인 것은 세 줄이다.

```css
position: sticky;
z-index: 50;
top: 0;
```

`z-index: 50`은 본문 위, 사진 확대 창(200)·건너뛰기 링크(100) 아래다.

---

## 2. 높이를 변수로 뺐다

고정 바가 생기면 **스크롤로 특정 요소를 화면에 올릴 때 그 요소가 바 밑에 숨는다.**
결함 목록에서 행을 고르면 지도 카드로 스크롤하는데(§관련 문서), `scroll-margin-top: 24px`
이던 값으로는 카드 위쪽이 바에 가려진다.

높이를 `.app-shell`에 변수로 두고 양쪽이 같은 값을 보게 했다.

```css
.app-shell { --topbar-height: 96px; }              /* 좁은 화면에서는 78px */
.topbar { min-height: var(--topbar-height); }
.defect-map-card { scroll-margin-top: calc(var(--topbar-height) + 16px); }
```

변수를 `.app-shell`에 둔 이유는 상속이다. 스크롤 대상이 어느 페이지에 있든 그 안쪽이므로
값을 따라 쓴다. 좁은 화면(≤820px)에서는 미디어 쿼리가 변수만 바꾸면 둘이 함께 따라온다.

---

## 3. 기존 e2e가 이 변경으로 깨졌다

`defect-list.spec.ts`의 "행을 고르면 지도까지 화면이 올라간다"가 스크롤 결과를
`expect(after).toBeLessThan(60)`으로 못박아 두었다. 고정 바가 생기니 카드가 112px 지점에
놓여 **정상 동작인데 시험이 실패한다.**

절대값을 지우고 **상단 바 높이를 기준으로** 고쳤다.

```ts
expect(after).toBeGreaterThanOrEqual(topbarHeight - 1)  // 바 밑에 숨지 않는다
expect(after).toBeLessThan(topbarHeight + 40)           // 지나치게 멀지도 않다
```

이렇게 두면 바 높이가 나중에 바뀌어도 시험이 따라온다.

---

## 4. 고정하고 나서 드러난 문제 — 지도가 상단 바를 침범했다

결함·로봇 화면에서 지도가 보이는 채로 스크롤하면 상단 바 위에 **`© NAVER Corp.`가 그대로
읽혔다.** 원인이 두 개 겹쳐 있었다.

### 4.1 z-index 경쟁 — 지도 요소가 바 **위에** 그려졌다

Naver SDK는 컨트롤·저작권 표시에 큰 z-index(1000대)를 쓴다.
`.defect-map-canvas-wrap`은 `position: relative`만 있고 z-index가 없어 **stacking context를
만들지 않는다.** 그러면 그 자식들의 z-index가 상단 바(z-index 50)와 **같은 층에서 경쟁**해
1000이 이긴다.

`overflow: hidden`은 이걸 막지 못한다. 상자 밖으로 나가는 부분만 자르는데, 스크롤하면
**상자 자체가 상단 바 영역과 겹치기** 때문이다.

`isolation: isolate`를 줘서 stacking context를 만들었다. 이제 내부 z-index가 몇이든 상자
밖으로 올라오지 못한다. 결함·로봇 두 지도에 같이 넣었다.

### 4.2 반투명 — 비치는 것도 문제였다

배경이 `rgba(255, 255, 255, 0.9)` + `backdrop-filter: blur(16px)`였다. 10%만 통과해도 대비가
큰 글자는 보이고, blur는 흐리게 만들 뿐 감추지 못한다. **불투명(`var(--surface)`)으로
바꾸고 `backdrop-filter`를 걷어냈다**(가릴 것이 없으니 GPU 작업만 남는다).

### 4.3 곁들여 옮긴 것 — 모달을 `document.body`로

`isolation: isolate`에는 대가가 있다. 그 안에 있는 요소는 **바깥 z-index와 경쟁할 수 없다.**
사진 확대 창과 결함 수정 모달이 상세 카드 안(=지도 안)에서 렌더되고 있어서, 화면 전체를
덮어야 하는 창이 **상단 바 밑에 깔리게 된다.**

두 모달을 `createPortal(…, document.body)`로 문서 최상단에 그리게 했다. 모달은 원래
문서 수준에 있어야 하는 것이라, 이 참에 제자리를 찾은 셈이다.

## 5. 확인한 것

- `position`이 `sticky`이고, **1751px 스크롤한 뒤에도 상단 바의 화면 좌표가 `top: 0`**이다
- 스크롤한 상태에서 계정 링크가 계속 보인다(눌 수 있다)
- 행을 고르면 지도 카드가 `top: 109px`에 놓인다 — 바 높이 100px보다 아래다
- 지도 안에 `z-index: 1000`짜리 `© NAVER Corp.` 흉내 요소를 심고 상단 바 뒤를 지나게
  스크롤한 뒤, 그 지점에서 `elementFromPoint`가 **상단 바를 집는지** 확인했다.
  고치기 전에는 그 요소가 잡혔고(스크린샷에서도 글자가 읽혔다), 고친 뒤에는 상단 바가 잡힌다.
  배경이 `rgba`가 아닌 것도 함께 검사한다 — **e2e에 남겼다**(`defect-list.spec.ts`)
- 사진 확대 창이 `BODY` 자식으로 그려지고 상단 바 지점에서 그 창이 잡힌다(덮는다)
- 결함 화면 e2e 18개 통과, 단위 시험 69 pass, `tsc -b`·`eslint`·CSP 게이트 PASS

## 6. 남은 것

### 내 몫

- 없다.

### 알아둘 것

- 앞으로 **스크롤로 무엇을 화면에 올리는 코드**를 새로 쓸 때는 `scroll-margin-top`에
  `var(--topbar-height)`를 함께 넣어야 한다. 안 넣으면 고정 바 밑에 숨는다.
- **화면 전체를 덮는 새 모달은 `document.body`로 portal**한다(§4.3). 지도·카드 안에서
  렌더하면 stacking context에 갇혀 상단 바 밑에 깔린다.
