## 2. 설계 판단과 그 이유

### 2.1 `<select>`를 걷어낸 대가를 알고 시작했다

네이티브 `<select>`는 **공짜로 주는 것이 많다.** 직접 그리기로 한 이상 그것들을 하나씩
다시 만들어야 한다. 이번에 넣은 것:

- `role="listbox"` / `role="option"` + `aria-selected` — 스크린리더가 고르개로 읽는다
- `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls`
- ↑↓·Home·End 이동, Enter·Space 고름, Esc 닫기, Tab이면 닫고 흘려보냄
- 바깥 누르면 닫힘, 고르면 여는 버튼으로 포커스 복귀

만들지 않은 것: 타자로 항목 찾기(`ㅅ`을 누르면 "신뢰도순") — 항목이 다섯 개뿐이라
↑↓이면 충분하다고 봤다.

### 2.2 포커스는 목록으로 옮기지 않는다

`aria-activedescendant` 방식이다. 포커스는 여는 버튼에 그대로 두고, 지금 짚은 항목의
`id`만 가리킨다. 목록으로 포커스를 옮기면 닫을 때 어디로 되돌릴지, 항목이 사라질 때
무엇을 잡을지가 지저분해진다. 키 처리도 버튼 한 곳에 모인다.

e2e가 이 성질을 지킨다 — 목록을 연 뒤에도 `trigger`가 `toBeFocused()`다.

### 2.3 짚은 자리와 훑는 자리를 같은 표시로

키보드로 짚은 항목(`is-active`)과 마우스로 올린 항목이 다른 표시를 쓰면, 둘을 섞어 쓸 때
"지금 Enter를 누르면 무엇이 걸리나"를 알 수 없다. `onPointerEnter`로 `activeIndex`를
같이 옮겨 **한 가지 표시**만 남겼다.

### 2.4 체크 자리는 늘 비워둔다

고른 줄에만 체크 아이콘을 넣고 나머지를 비우면 글자가 좌우로 흔들린다.
`visibility: hidden`으로 자리를 잡아두고 보이기만 바꾼다.

### 2.5 같은 값을 다시 고르면 아무 일도 안 한다

`onChange`는 값이 실제로 바뀔 때만 부른다. 상위(`DefectManagePage.changeSort`)가
URL을 새로 쓰면 그것이 곧 재조회라, 같은 값으로 URL을 덮으면 조회가 한 번 더 나간다.

### 2.6 상세 카드에서는 위로 뒤집는다

처리 상태·처리 결과는 카드 **바닥 쪽**에 있고 카드는 `overflow-y: auto`로 스스로
스크롤한다. 아래로 펼치면 목록이 카드 밖이라 잘린다.

열 때 자리를 재서 모자라면 `is-above` 클래스를 붙인다(inline style은 CSP가 막는다).
재는 대상은 화면만이 아니라 **스크롤하는 조상**까지다 — 카드 안에서는 화면에 자리가
있어도 카드 밖이면 소용없다.

```ts
for (let node = trigger.parentElement; node; node = node.parentElement) {
  const overflowY = getComputedStyle(node).overflowY
  if (overflowY === 'auto' || overflowY === 'scroll') { /* 이 상자에 갇힌다 */ }
}
```

아래가 모자라도 **위가 더 넓을 때만** 뒤집는다. 둘 다 좁으면 아래로 두고 목록 자체가
`max-height: 240px`로 줄어 그 안에서 스크롤한다.

### 2.7 "선택하세요"는 목록에도 남긴다

네이티브에는 `<option value="">선택하세요</option>`가 있었다. 그것을 지우면 **골랐다가
무를 길이 없어진다.** 빈 값을 목록 첫 줄로 그대로 두고, 버튼에서는 아직 고르지 않았다는
뜻으로 흐리게(`is-placeholder`) 보여준다.

정렬 e2e 3개.

- 열어서 고르면 URL(`sort=riskScore,desc`)과 목록 조회에 실린다, 닫힌 채로도 지금 기준이
  보인다, 고른 항목에 `aria-selected="true"`
- **키보드로만** — ↓로 열고(포커스는 버튼에 남고) ↓ Enter로 고른다. 날짜 열 제목이
  기준을 따라 "최초 발견"으로 바뀌는 것까지 확인
- Esc로 닫으면 고르지 않은 것이다(URL에 `sort`가 붙지 않는다)

처리 상태 e2e 2개.

- 카드 안에 네이티브 `select`가 하나도 없고, 첫 줄이 "선택하세요"이며, 상태를 고르면
  변경 사유 칸이 열린다
- **아래 자리가 모자라면 위로 뒤집는다** — `is-above`가 붙고 목록 바닥이 버튼 위, 카드
  안쪽에 있는지 좌표로 확인

## 4. 남은 것

### 내 몫

- 타자로 항목 찾기는 없다(§2.1).
- **`features/defect` 밖에도 네이티브 `<select>`가 남아 있다**(미션·관리자 화면 등).
  같은 컴포넌트로 맞추려면 이름부터 `defect-`를 떼고 공용 자리로 옮겨야 한다 — 남의
  화면이라 손대지 않았다.
- 뒤집기는 **열 때 한 번만** 잰다. 열어둔 채 카드를 끌어 옮기면 방향이 그대로다.
  실제로는 열린 목록 바깥을 누르면 닫히므로 겪기 어렵다.

### 다른 팀원 몫

- 없다. `features/defect` 안에서 끝났다.
