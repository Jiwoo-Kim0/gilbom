# 결함 조건 툴바와 상세 필터 모달

- **날짜:** 2026-08-06
- **범위:** `/defects` 화면의 검색·필터 배치. `web/frontend/gilbom/src/features/defect/` 안에서 끝났다.
- **한 줄:** 검색창을 262px로 줄이고, 지도 오른쪽 260px 사이드바에 있던 조건 전부를
  검색창 오른쪽 **알약 한 줄**로 옮겼다. 조건을 한 화면에 펼치는 **상세 필터 모달**을
  새로 만들었다.

│ 🔍 검색(262px) │ ⚙ │ 처리 상태▾ 결함 유형▾ 심각도▾ 기간▾ 신뢰도▾  ↻초기화 │

## 2. 설계 판단과 그 이유

### 2.1 왜 조건을 위로 올렸나

지도가 주인공인 화면인데 조건 다섯 개가 가로 260px를 **상시로** 깎고 있었다. 조건은
대개 한 번 걸어두고 안 건드리는데, 자리 값은 계속 냈다. 위로 올리니 지도가 툴바와 같은
폭을 쓴다(e2e가 `mapWidth === toolbarWidth`로 지킨다).

### 2.2 알약은 즉시, 모달은 "적용하기"

**같은 조건인데 반영 시점이 다르다.** 일부러 그렇게 뒀다.

- 알약은 한 번에 조건 하나만 바뀐다. 조회 한 번 나가는 게 자연스럽다.
- 모달은 다섯 개를 한꺼번에 짜맞추는 자리다. 고를 때마다 조회가 나가면 뒤 화면이 계속
  다시 그려져 무엇을 고르는 중인지 알 수 없다. 그래서 초안(`useState(filters)`)으로
  들고 있다가 "적용하기"에서 한 번만 `onChange`한다. "닫기"는 초안을 버린다.

e2e가 이 성질을 지킨다 — 모달에서 조건 둘을 바꿔도 목록 조회는 **한 번**.

### 2.3 배경은 55%가 아니라 32%

기존 수정·병합 모달(`.defect-modal-backdrop`)은 `rgb(15 23 42 / 55%)`다. 상세 필터는
**지도에 지금 무엇이 걸려 있는지 보면서** 조건을 고치는 자리라 그만큼 어두우면 안 된다.
`rgb(26 26 26 / 32%)`로 따로 뒀다. e2e가 alpha를 읽어 `0 < a < 0.5`를 확인한다.

### 2.4 모달에서도 체크박스를 버리지 않았다

벤치마킹한 시안은 토글 버튼 격자다. 같은 모양을 내되 요소는 `<input type="checkbox">`
그대로 두고 CSS로만 알약처럼 그렸다(`:has(input:checked)`, 입력은 크기 0 + `opacity: 0`
이라 포커스는 살아 있다). 버튼으로 바꿨으면 다중 선택이라는 사실과 선택 상태를
`aria-pressed`로 다시 만들어야 했고, 알약 패널과 모달이 서로 다른 컴포넌트가 됐을 것이다.
지금은 `DefectFilterOptions` 하나를 `variant`만 바꿔 두 곳에서 쓴다.

### 2.5 라벨이 알약 안으로 들어갔다

사이드바 시절에는 라벨이 컨트롤 **위**에 있었다(`.defect-filter-dropdown-label`). 가로
한 줄에 다섯 개가 들어가야 해서 버튼 안으로 넣었다. 덕분에 접근성 이름이
`"처리 상태 신규 외 2개"`로 자연히 만들어져 `aria-labelledby` 짝짓기가 필요 없어졌다.

### 2.6 한 줄에 넣으려고 깎은 것들

1440px에서 검색 + 알약 5 + 초기화가 한 줄에 들어가야 한다. 처음엔 11px이 모자라 초기화가
둘째 줄로 떨어졌다. 잰 값(`getBoundingClientRect`)을 보고 다음을 줄였다.

| 무엇 | 전 → 후 | 아낀 폭 |
| --- | --- | --- |
| 검색창 | 280 → 262px | 18 |
| 알약 사이 gap | 8 → 6px | 8 |
| 알약 좌우 padding | 14 → 12px | 20 |
| 알약 라벨 `AI 신뢰도` → `신뢰도` | | 22 |
| 알약 요약 `전체 기간` → `전체` | | 35 |
| 초기화 글자 `필터 초기화` → `초기화` | | 25 |

"초기화"는 글자만 줄이고 `aria-label="필터 초기화"`를 남겼다 — 스크린리더는 무엇을
되돌리는지 온전히 듣는다. **e2e도 이 접근성 이름으로 찾는다.**

`flex-wrap`이라 폭이 모자라면 알아서 두 줄로 접힌다. 1024px 이하에서는 검색창이 한 줄을
혼자 쓰도록 `width: 100%`만 얹었다.

## 3. 상세 필터 모달

- `role="dialog" aria-modal="true" aria-label="상세 필터"`, 열면 카드로 포커스 이동,
  닫으면 열었던 버튼으로 되돌림, Esc·바깥 클릭·닫기 버튼 모두 닫힘.
- 버튼 줄은 `position: sticky; bottom`. 조건이 길어지면 "적용하기"가 스크롤 밖으로 나가
  적용할 길을 못 찾는다.
- 배경 fade + 카드 8px 상승 애니메이션. `prefers-reduced-motion: reduce`에서는 fade만.
- X 버튼의 이름은 `"필터 창 닫기"`다. `"상세 필터 닫기"`로 두면 Playwright의
  `getByRole('button', { name: '상세 필터' })`가 **여는 버튼과 함께 두 개를 집는다**
  (name은 기본이 부분 일치다). 아래 §5.2 참고.

## 5. 작업 중 겪은 함정

### 5.1 `getByRole('heading', { level: 2 })`는 원래부터 없었다

기존 필터 e2e 3개가 "바깥을 눌러 패널 닫기"에 `level: 2`를 쓰는데, `/defects`에는
**h2가 하나도 없다.** `AppLayout`이 제목을 `<h1>`로 그린다(HEAD에서도 그렇다 —
`git grep '<h2' HEAD`로 확인). 즉 이 3개는 내 변경 전부터 30초 타임아웃으로 죽고 있었다.
`level: 1`로 고쳤다.

**결함 e2e를 손볼 때는 먼저 고친 것 없이 한 번 돌려 기준선을 봐야 한다.**

### 5.2 Playwright `getByRole(name)`은 부분 일치다

`aria-label="상세 필터 닫기"`인 X 버튼이 `{ name: '상세 필터' }` 조회에 함께 걸려
strict mode 위반이 났다. 두 길이 있다.

- 이름을 겹치지 않게 짓는다 → X는 `"필터 창 닫기"`로.
- 스펙에서 `{ name: '닫기', exact: true }`를 쓴다 → 바닥 버튼 "닫기"와 X를 가른다.

같은 이유로 `기간` 알약과 패널 안 `전체 기간` 버튼도 정규식 `/기간/`에 함께 걸린다.
그쪽은 클래스로 좁혔다(`locator('.defect-filter-chip-trigger', { hasText: '기간' })`).

### 5.3 눈에 보이는 글자를 줄이면 e2e가 텍스트로 찾던 곳이 깨진다

`defect-search.spec.ts`가 `button.textContent.includes('필터 초기화')`로 초기화 버튼을
집고 있었다. 글자를 "초기화"로 줄이면서 `button[aria-label="필터 초기화"]`로 바꿨다.
**접근성 이름으로 찾으면 눈에 보이는 글자가 바뀌어도 안 깨진다.**

### 5.4 컴포넌트 파일에서 순수 함수를 내보내면 eslint가 막는다

`react-refresh/only-export-components`. 요약 문자열 함수들을 `defectFilterSummary.ts`로
따로 뺐다. 컴포넌트 파일은 컴포넌트만 내보낸다.

### 5.5 WSL에서 화면을 띄우는 길 (또 막혔다)

`node_modules`가 Windows용(`@rolldown/binding-win32-x64-msvc`)이라 컨테이너 vite는 못
쓰고, UNC 경로(`\\wsl.localhost\...`)에서 Windows node로 vite를 띄우면
`Failed to resolve entry for package "vite"`로 죽는다. 결국
[결함-증거사진-확대보기_작업내용.md](결함-증거사진-확대보기_작업내용.md) §5.1의
**Windows 파일시스템 복사본**(`/mnt/c/temp/gilbom-verify`)에서 돌렸다. Playwright도
그 복사본에서 실행했다 — 브라우저가 Windows 쪽에 설치돼 있다.

```bash
cp -r src e2e playwright.config.ts /mnt/c/temp/gilbom-verify/
printf 'VITE_NAVER_MAP_CLIENT_ID=e2e-map-client\n' > /mnt/c/temp/gilbom-verify/.env
cd /mnt/c/temp/gilbom-verify \
  && "/mnt/c/Program Files/nodejs/node.exe" node_modules/@playwright/test/cli.js test e2e/defect-filter.spec.ts
```

`webServer`는 그 경로에서 `npm run dev`가 정상으로 뜬다(cmd.exe가 UNC가 아닌 실제
Windows 경로를 작업 디렉터리로 받는다).

## 6. 남은 것

### 내 몫

- **알약 패널은 왼쪽 정렬 고정이다.** 오른쪽 끝 알약(신뢰도)이 좁은 화면에서 열리면
  패널이 카드 밖으로 나갈 수 있다. 1024px 이하에서는 조건 줄이 접혀 알약이 왼쪽으로
  오므로 지금 배치에서는 안 겪었지만, 알약을 더 늘리면 `align="right"`가 필요하다.
- **상세 필터에 검색어 칸은 없다.** 검색창이 모달 밖에 그대로 보여서 넣지 않았다.
  모달만 열고 검색까지 끝내고 싶다는 요구가 오면 다시 본다.
- 모달 안 포커스 트랩은 없다(카드로 포커스를 옮기고 Esc·복귀만 처리). 기존
  `DefectMergeModal`·`DefectEditModal`도 같은 수준이라 맞춰 뒀다. 셋을 함께 올리는 게 맞다.

### 다른 팀원 몫

- 없다. `features/defect`와 그 e2e 안에서 끝났다.
