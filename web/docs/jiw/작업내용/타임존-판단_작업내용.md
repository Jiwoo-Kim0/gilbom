# 화면 시각의 타임존 판단 기록

기간: 2026-08-06
범위: 프론트 시각 표시·입력의 타임존 기준. **서울 고정으로 바꿨다가 브라우저 로컬로
되돌렸다.** 지금 코드는 브라우저 로컬이다(원래 동작).

관련 문서: [defect-schema.md](../../defect-schema.md)(`TIMESTAMPTZ`),
[결함-필터-UI-드롭다운_작업내용.md](결함-필터-UI-드롭다운_작업내용.md) §9.2(시작 날짜 입력)

---

## 1. 층별 기준 — 이건 안 바뀌었다

| 층 | 기준 |
| --- | --- |
| DB | `TIMESTAMPTZ` — UTC 순간(instant) |
| 컨테이너 | `TZ: ${TZ:-UTC}` |
| API 응답 | Java `Instant` → `2026-08-04T02:00:00Z` |
| 화면 표시·입력 | **브라우저 로컬 타임존** |

저장·전송은 순간이라 타임존 논쟁의 대상이 아니다. **사람이 읽는 자리만** 기준을 정하면 된다.

한국 날짜가 꼭 필요한 한 곳은 서버가 명시한다 — 결함 코드 `INC-YYYYMMDD-…`의 날짜는
`ZoneId.of("Asia/Seoul")`로 뽑는다.

---

## 2. 서울로 고정했다가 되돌린 이유

먼저 **표시·입력을 모두 `Asia/Seoul`로 못박았다**(커밋 `26d8d37`). 근거는 "관제 화면은
한국 시간 하나로 읽혀야 한다"였다.

**같은 날 되돌렸다**(커밋 아래 §4). 판단이 바뀐 지점은 이것이다 — 화면을 보는 사람은
자기 기계 시간으로 생각한다. 해외에서 접속해도 "지금 몇 시"의 기준은 그 사람의 시계다.
서울로 못박으면 화면의 시각과 사용자의 시계가 어긋나 오히려 계산을 강요한다.

**되돌린 뒤 감수하는 것**(알고 받아들인 것):

- 다른 나라에서 보면 같은 결함이 다른 시각으로 보인다. 순간은 같으니 정렬·조회 결과는
  동일하고, 보이는 숫자만 다르다.
- 화면의 날짜와 **결함 코드의 날짜(서울 기준)가 하루 어긋날 수 있다.** UTC 15:00 이후
  들어온 결함이 그렇다.
- 날짜 입력(`시작 날짜` 등)의 경계도 로컬 자정이다. 다른 타임존에서 같은 날짜를 골라도
  조회 경계가 다르다.

팀이 전부 한국에서 쓰는 동안에는 세 항목 모두 드러나지 않는다.

---

## 3. 다시 서울로 가고 싶어지면

`26d8d37`을 되살리면 된다. 그때 만든 것은 이랬다.

- `src/shared/time/seoulTime.ts` — `seoulDateTimeFormat`(타임존 박힌 formatter),
  `seoulParts`(로컬 getter 대체), `seoulInputToInstant`·`instantToSeoulInput`
  (타임존 없는 입력을 서울로 해석/역변환)
- 표시 formatter 20곳 + 입력 변환 4곳 + 직접 조립 형식 3곳
- 단위 시험 9개(기대값을 서울로 못박아, 구현이 로컬로 돌아가면 KST 아닌 기계에서 깨진다)

손대야 하는 자리를 찾는 방법: `Intl.DateTimeFormat`·`toLocale*`(표시), `new Date(입력값)`
(입력 파싱), `getHours()`류 로컬 getter(직접 조립)를 훑으면 된다.

---

## 4. 남길 만한 함정 — 값 import는 `.ts` 확장자가 필요하다

새 모듈을 `'../../shared/time/seoulTime'`으로 들여왔더니 **단위 시험 4개만 깨졌다.**

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '…/shared/time/seoulTime'
```

단위 시험은 `node --experimental-strip-types --test`로 **소스를 직접** 불러 돌린다.
Node의 ESM 해석은 확장자를 요구하는데 `vite`·`tsc`는 없어도 되므로, **타입 검사와 lint는
통과하고 시험만 깨진다.** `import type`은 런타임에 지워져 확장자가 없어도 되기 때문에
기존 소스가 두 방식을 섞어 쓰고 있었다.

**값 import는 `.ts`를 붙인다** — 이 되돌림과 무관하게 남는 규칙이다.

---

## 5. 남은 것

### 팀 판단이 필요한 것

- 해외 사용자가 실제로 생기면 §2의 감수 항목을 다시 본다. 그때는 서울 고정보다
  **"표시 옆에 타임존을 함께 적기"**(`11:00 KST`)가 더 나은 답일 수 있다 — 사용자의 시계와
  현장의 시계를 둘 다 살린다.
- 컨테이너 `TZ`는 UTC 그대로다. 로그를 KST로 읽고 싶으면 바꿀 수 있지만 Grafana·Loki
  대시보드 눈금과 함께 봐야 한다.
