## 2. 작성 원칙 — "없는 내용 금지"

요청이 "실제로 있는 파일들의 내용만"이었다. 그래서 다음을 규칙으로 뒀다.

1. **파일을 열어 읽은 것만 쓴다.** 목록만 본 것은 "이런 파일이 있다"까지만 쓰고
   동작을 추정해 채우지 않았다.
2. **설계 근거는 코드 주석에서 인용한다.** 이 저장소는 주석에 "왜 이렇게 했는가"가
   이례적으로 많이 남아 있다. 결함 병합 SQL의 `RESOLVED` 제외 근거, Nginx가 이미지
   경로에서 쿠키를 끊는 근거, X-Forwarded-For를 이어붙이지 않는 근거, readiness에서
   LLM을 뺀 근거가 모두 주석에 있다. 발표에서 가장 설득력 있는 재료라 그대로 옮겼다.
3. **숫자는 세어서 쓴다.** 파일 수는 `find | wc -l`, 코드 줄 수는 `wc -l`,
   설정값은 `application.yml`·`compose.yaml`의 기본값을 그대로 인용했다.

## 3. 문서에 담은 "질문받기 좋은" 지점

발표 방어용으로 특히 정리해 둔 것들이다.

- **MQTT 수신 6단 방어** — topic 파싱 → QoS 일치 → 엄격 역직렬화 → schema_version →
  mqtt_id 일치 → 신선도 → replay. 그리고 dispatcher가 **핸들러 누락을 기동 시점에
  실패시킨다**는 점.
- **결함 병합 정책의 비대칭** — `RESOLVED`는 병합에서 빼고 `FALSE_POSITIVE`는 남긴다.
  둘 다 종결 상태인데 반대로 처리한 이유가 각각 있다.
- **이미지 두 경로 분리** — 업로드는 `X-API-Key`, 조회는 HMAC 서명 URL, 그리고
  Nginx가 그 경로에서 쿠키를 양방향으로 끊는다.
- **LLM 전면 폴백** — 실패 사유 9종이 enum + DB에 남고 readiness에는 안 들어간다.
- **IMU 없이 도는 FSM** — 종료 판정을 yaw에서 시각+시간으로 옮긴 실외 관찰 근거.

## 4. 코드 변경 반영 (2026-08-12)

작성 직후 두 건이 바뀌어 문서에 반영했다.

| 변경 | 내용 | 반영한 절 |
| --- | --- | --- |
| 커밋 `ee49989` | 이미지 보안 체인에 `NullAuthenticatedSessionStrategy` 추가 — 서명·API Key 인증이 기존 관리자 세션 ID를 회전시키던 문제 차단 + 회귀 테스트 | §4.5(신설 문단), §7.2, Q&A 2건 신설 |
| `operations.yml` (미커밋) | `BackupStale`에서 `backup="totp"` 제외, `TotpKeyringExportStale`(7일 warning) 신설 | §7.4(신설 문단), Q&A 1건 신설 |

두 변경 모두 **"왜 그렇게 했는가"가 주석에 적혀 있어** 그대로 옮겼다. 특히 이미지
쪽은 §7.2의 Nginx 쿠키 차단과 **같은 문제의 안쪽 방어**라서, 두 절을 서로 참조하도록
연결했다 — 발표에서 "edge만 막은 것 아니냐"는 질문이 나올 자리다.

테스트 파일 수는 158개 그대로다(기존 `ImageApiSecurityChainTest`에 메서드만 추가).
