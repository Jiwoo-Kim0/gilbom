# 지도 깜빡임 작업내용

기간: 2026-08-07
범위: 결함 지도(`DefectMap`)의 갱신 표시와 마커 재생성. 조회 흐름 자체는 그대로다.

## 1. 증상과 원인

**지도가 계속 로딩되면서 깜빡였다.** 원인이 두 개였고, 둘 다 "다시 읽을 때마다"였다.

### 1.1 갱신 표시가 지도 전체를 덮었다

`.defect-map-loading`은 `position: absolute; inset: 0`에 불투명 배경이다. 즉 **재조회 때마다
지도가 통째로 가려졌다.** 첫 조회에는 맞는 표시지만, 이미 마커가 그려진 뒤의 갱신에는
과하다.

실시간 알림이 올 때마다 지도를 다시 읽게 이어둔 뒤부터(795 §4) 결함이 들어오는 만큼
전면이 덮였다.

### 1.2 결과가 같아도 마커를 전부 다시 만들었다

응답이 오면 `setFeatureSnapshot`에 **새 배열**이 들어간다. 마커 effect는 `features` 참조가
바뀌면 마커를 통째로 지우고 다시 만든다. 대개 결과는 그대로인데도 그렇다.

재보니 같은 결과로 세 번 갱신했을 때 **마커 생성이 1 → 4**였다. 지우고 다시 그리는 사이가
눈에 보이는 깜빡임이다.

### 1.3 조회가 무한히 돌고 있던 것은 아니다

먼저 그걸 의심해서 재봤다. 가만히 둔 지도는 **4초 동안 조회 2회**(첫 조회 + 시야 확정 뒤
한 번)로 멈춘다. 루프는 없고, 깜빡임은 "갱신 한 번의 표현" 문제였다.

## 2. 무엇을 바꿨나

### 2.1 전면을 덮는 것은 보여줄 것이 없을 때만

```tsx
{(mapStatus === 'loading' || (queryLoading && features.length === 0)) && …전면 로딩…}
{mapStatus === 'ready' && queryLoading && features.length > 0 && …작은 "갱신 중…" 칩…}
```

이미 그려둔 마커가 있으면 그대로 두고 왼쪽 위에 작은 칩만 띄운다(`.defect-map-refreshing`,
지도를 덮지 않고 `pointer-events: none`). 축척 바(왼쪽 아래)·확대 컨트롤(오른쪽 위)과
겹치지 않는 자리다.

### 2.2 결과가 같으면 이전 배열을 그대로 쓴다

```ts
features: previous !== null
  && defectMapFeaturesEqual(previous.features, response.features)
  ? previous.features        // 참조가 유지되면 마커를 다시 만들지 않는다
  : response.features
```

`defectMapFeaturesEqual`은 **마커 모양을 정하는 값만** 본다 — 좌표(위치), 유형(색),
심각도·상태(설명 글). 신뢰도처럼 마커에 드러나지 않는 값은 보지 않는다. 그것까지 보면 값이
조금 흔들릴 때마다 다시 그린다.

참조가 유지되면 `features`를 의존성으로 쓰는 것들(마커 effect, 범례 개수)이 모두 조용해진다.

## 3. 확인한 것

**단위 시험 7개**(`test/defectUiState.test.ts`): 객체가 달라도 그릴 것이 같으면 같다,
신뢰도만 다르면 같다, 개수·좌표·상태·유형·id가 다르면 다르다. 전체 102 pass.

**e2e 1개 추가**(`e2e/defect-realtime-map.spec.ts` — "결과가 그대로면 지도가 깜빡이지
않는다"). 같은 결함에 대한 알림을 세 번 밀어 넣고 본다.

| | 고치기 전 | 지금 |
| --- | --- | --- |
| 전면 로딩이 뜬 횟수 | **3** | **0** |
| 마커 생성 수 | 1 → **4** | 1 → **1** |

전면 로딩은 순간이라 나중에 세면 놓친다. `MutationObserver`로 **한 번이라도 떴는지**를
기록해서 본다. 마커 생성 수는 가짜 지도에 `markersCreated`를 넣어 센다(뗀 것까지 누적).

두 값 모두 **고치기 전 코드에서 실패하는 것까지 확인했다.**

결함 화면 e2e 49개 통과, `tsc -b`·`eslint`·CSP 게이트 PASS.

## 4. 남은 것

### 내 몫

- 결함이 **연달아** 들어오면 화면 밖 결함마다 지도가 옮겨간다(795의 동작이다). 깜빡임은
  사라졌지만 그때는 지도가 계속 튄다 — 실제 운영에서 초당 여러 건이 들어오면
  "옮기지 않고 알림 줄에 '보기' 버튼" 쪽이 낫다.
- 목록(`DefectManagePage`)도 같은 구조다. 갱신 중에 표가 어떻게 보이는지는 확인하지 않았다.

### 알아둘 것

- `defectMapFeaturesEqual`은 **순서까지** 같아야 같다고 본다. 서버 정렬이 바뀌면 내용이
  같아도 다시 그린다(정렬이 흔들리는 종단이면 정렬 후 비교로 바꿔야 한다).
