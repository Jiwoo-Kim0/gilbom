- **날짜:** 2026-08-06
- **범위:** `/defects` 지도 위 결함 상세 카드. `web/frontend/gilbom/src/features/defect/`와
  그 e2e·단위 시험 안에서 끝났다. `MissionMap`이 같은 카드를 쓰지만 **건드리지 않았다**(§2.4).

  옮긴다. 위치는 CSP 때문에 inline style이 아니라 **CSS class**로 표현한다.

## 2. 설계 판단과 그 이유

### 2.1 왜 inline style을 못 쓰나 — 이 기능의 모든 형태가 여기서 나왔다

`style-src 'self'`다. `left: 337px`을 넣을 방법이 **하나도** 없다.

- JSX `style` prop → 차단
- `element.style.left = …`, `cssText`, `setAttribute('style', …)` → 차단
- 그리고 `scripts/verify-frontend-csp-source.sh`가 **소스 단계에서** 이 셋을 전부 막는다
  (`style[[:space:]]*=`, `\.style\.`, `cssText`). 우회하려면 그 스크립트를 고쳐야 하는데,
  그것이 지키는 것이 바로 이 정책이다.

사진 확대가 배율을 CSS class 단계로 둔 것과 같은 상황이다
([결함-증거사진-확대보기_작업내용.md](결함-증거사진-확대보기_작업내용.md)). 그래서
**위치도 클래스로** 표현한다.

### 2.2 클래스 폭발을 피한 방법 — 10%p 자리와 1%p 자리를 나눈다

1%p 간격으로 101×101 = 10,201개 클래스를 만들 수는 없다. 자리수를 나눠 **더한다.**

```
위치 37% → .dc-x-3 (--defect-card-x: 30%) + .dc-xf-7 (--defect-card-xf: 7%)
CSS       → left: calc(var(--defect-card-x) + var(--defect-card-xf))
```

축마다 11 + 10개, 두 축 합쳐 **42개 규칙**으로 0~100%를 1%p 간격으로 덮는다.
1%p는 지도 폭 1000px에서 10px, 높이 600px에서 6px이라 끌 때 걸리지 않는다.

**px이 아니라 백분율**인 것도 이 구조의 덕이다 — 창 크기가 바뀌어도 카드가 지도 안
같은 비율 자리에 남는다.

### 2.3 아래로 끌면 잘리는 대신 줄어든다

기본 카드는 `top: 16; bottom: 16`으로 지도 높이를 꽉 채운다. 옮기려면 `bottom`을 놓아야
하는데, 그러면 카드가 자기 내용만큼 자라 지도 밖으로 나가고 `overflow: hidden`에 잘린다.

```css
.defect-card.is-dragged {
  max-height: calc(100% - var(--defect-card-y) - var(--defect-card-yf) - 16px);
}
```

**남은 공간만큼 상한을 준다.** 아래로 끌면 카드가 그만큼 줄고 안쪽 스크롤이 생긴다.
내용이 잘려 사라지는 일이 없다.

### 2.4 카드는 `MissionMap`도 쓴다 — 그래서 끌기는 opt-in이다

`onMove`를 넘기지 않으면 손잡이도 그리지 않고 포인터 처리도 붙지 않는다. `MissionMap`은
그대로 두었고 그 화면의 카드는 예전과 **완전히** 같다. 기본 `.defect-card` 규칙도 손대지
않았다(§2.3의 규칙은 `.is-dragged`에만 있다) — 그래서 끌기 시작 순간에 카드 크기가
튀지도 않는다.

### 2.5 옮긴 자리는 카드가 아니라 지도가 들고 있다

카드는 결함마다 `key={selectedDefectId}`로 새로 마운트된다. 자리를 카드 state로 두면
**결함을 바꿀 때마다 제자리로 튀어오른다.** 옆으로 밀어둔 것은 지도를 보려는 뜻이므로
결함을 훑는 동안 유지돼야 한다. e2e가 이 회귀를 지킨다.

### 2.6 방향키로도 옮긴다

끌기는 포인터가 있는 사람만 쓸 수 있다. 헤더 왼쪽 손잡이가 **버튼**이라 Tab으로 닿고,
방향키로 2%p씩 옮긴다(1%p는 눌러도 움직인 줄 모른다). 아직 끌어본 적이 없으면 지금
그려진 자리를 백분율로 환산해 그 자리에서 출발한다 — 기본 자리는 백분율로 들고 있지 않다.

### 2.7 끌기를 시작하지 않는 경우

- 헤더 안 **닫기 버튼**에서 시작한 포인터(손잡이는 예외 — 그것으로 끄는 게 자연스럽다)
- 왼쪽 버튼이 아닌 포인터(가운데 버튼 끌기는 브라우저 자동 스크롤이다)

`setPointerCapture`로 포인터를 잡아둬서 카드 밖으로 빠르게 끌어도 `pointermove`가 계속
들어온다. 크기는 **끌기 시작 때 한 번만** 잰다 — 움직이는 동안 다시 재면 자기 위치
변화가 다음 계산에 섞여 카드가 손끝에서 미끄러진다.

## 3. 작업 중 겪은 함정

### 3.1 세로로 1px도 움직이지 않았다 (자르기 규칙)

처음 자르기는 "카드가 전부 보이는 자리까지"였다. 기본 카드는 높이가 `컨테이너 - 32`라
그 규칙에서 세로 여유가 **정확히 0**이 된다(최소 여백 16px과 상한 16px이 뒤집힌다).
e2e가 "120px 끌었는데 4.8px 움직였다"로 잡았다.

두 단계로 고쳤다.

1. "전부 보이는 자리"를 먼저 시도한다.
2. 그렇게 해서 여유가 안 나오면 **"손잡이(96px)는 남는 자리"까지** 넓힌다.

`cardSize + 2*margin <= containerSize`로 갈리는 것이 아니라 **여유가 실제로 나오는지**로
갈려야 한다. 기본 카드는 딱 맞아떨어져서(등호) 첫 조건을 통과해 버린다 — 처음 고칠 때
이 등호에 걸려 한 번 더 실패했다.

### 3.2 고정 상단 바가 카드 헤더를 덮고 있었다 (e2e)

행을 누르면 페이지가 지도까지 **부드럽게** 스크롤한다. 그 도중에 헤더 좌표를 재서
마우스를 누르면 `pointerdown`이 `HEADER.topbar`로 간다(스크롤이 아직 끝나지 않아 카드
헤더가 상단 바 밑에 있다). 헤더가 상단 바 아래로 내려오기를 기다리는 단계를 넣었다.

**증상이 "드래그가 아예 안 먹는다"라 코드를 먼저 의심했다.** `pointerdown`의 target을
찍어보고 나서야 알았다 — 포인터 시험이 안 될 때는 **무엇이 눌렸는지부터** 봐야 한다.

### 3.3 뷰포트 좌표로 재면 스크롤이 섞인다 (e2e)

"다른 결함을 골라도 자리를 지킨다"가 209px 차이로 실패했다. 카드가 움직인 것이 아니라
두 번째 행을 누를 때 페이지가 다시 스크롤한 것이었다. 카드 위치는 **지도 영역 기준
상대 좌표**로 재야 한다.

## 7. 2차 — 모서리 여백을 없애 지도 꼭대기까지 올라가게 (2026-08-07)

상세 카드와 묶음 목록을 **지도 모서리에 붙이면서**
([결함-묶음-목록_작업내용.md](결함-묶음-목록_작업내용.md) §7.3), 끌기 규칙이 그 자리와
어긋나게 됐다. 자르기가 모서리마다 16px을 남기고 있어서, 기본 자리는 붙어 있는데
**한 번 끌면 다시는 붙일 수 없었다.**

### 7.1 여백을 없애고 "자리 유무" 판정만 따로 뒀다

예전 규칙은 16px 여백 하나가 두 가지 일을 겸했다.

1. 카드가 모서리에 닿지 않게 하는 **여백**
2. "다 들어가는 자리로는 못 움직인다"를 가르는 **문턱**
   (`fitPercent > minPercent`, 여기서 `minPercent`가 곧 여백이었다)

1을 없애면 2도 함께 무너진다 — 여백이 0이면 지도 높이를 꽉 채운 카드도 "5%p는 움직일 수
있다"가 되어, 손잡이만 남기고 내려가는 규칙(§3.1)이 발동하지 않는다. 그래서 문턱을
`MIN_TRAVEL_PERCENT = 8`로 **분리**했다.

```ts
const fitPercent = floor((containerSize - cardSize) / containerSize * 100)
const maxPercent = fitPercent >= MIN_TRAVEL_PERCENT
  ? fitPercent                                   // 다 보이는 자리까지
  : floor((containerSize - MIN_VISIBLE) / containerSize * 100)  // 손잡이만 남기고
return clamp(percent, 0, maxPercent)             // 아래끝이 0 = 모서리
```

값이 이렇게 바뀐다(지도 1000×600, 카드 340×300 기준).

| | 전 | 후 |
| --- | --- | --- |
| 왼쪽·위 끝 | 2% / 3% (16px 여백) | **0% / 0%** (모서리에 닿음) |
| 오른쪽·아래 끝 | 64% / 47% | 66% / 50% (모서리에 닿음) |
| 지도를 꽉 채운 카드의 아래 끝 | 84% | 84% (그대로) |

### 7.2 e2e

`끌어서 지도 꼭대기까지 올릴 수 있다` — 아래로 내렸다가 다시 끝까지 올려 위·왼쪽 간격이
**정확히 0**인지 본다. 단위 시험의 자르기 기대값도 함께 고쳤다.
