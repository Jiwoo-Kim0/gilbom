# 서버 담당자 준비 및 전달 체크리스트

외부 팀에 테스트 패키지를 전달하기 전에 서버 담당자가 확인할 항목입니다.

## 전달 대상

PowerShell에서 전달용 ZIP을 생성합니다.

```powershell
cd C:\ssafy\SSAFY-TASK\test\통신테스트
.\build-external-package.ps1
```

생성 결과:

```text
gilbom-mqtt-external-test-all-topics.zip
```

ZIP에는 실행 파일, 공개 CA와 함께 실제 `robot-test` 비밀번호가 적힌
`.env`와 `connection-secret.md`가 포함됩니다. ZIP 자체를 Secret으로 취급하며
Mattermost 비공개 채널 또는 DM으로만 전달합니다.

## 비밀번호 출처

`robot-test`의 원문 비밀번호는 Git에서 제외된
`C:\ssafy\SSAFY-TASK\web\.env`의 `MQTT_ROBOT_PASSWORD` 값입니다.
Mosquitto `passwd`에 있는 `$7$...` 값은 해시이므로 원문으로 사용할 수 없습니다.

`build-external-package.ps1`이 이 값과 외부 MQTT 접속정보만 패키지 전용
`.env`와 `connection-secret.md`에 기록합니다. 서버의 `web/.env` 전체는 ZIP에
포함되지 않습니다. 생성된 폴더와 ZIP은 `.gitignore`로 제외되어 있습니다.

## Docker Backend로 확인

```powershell
cd C:\ssafy\SSAFY-TASK\web
docker compose up -d db mqtt-init mosquitto backend
docker compose ps
docker compose logs -f --tail 100 backend mosquitto
```

`Ctrl+C`는 로그 보기만 종료하며 컨테이너는 계속 실행됩니다.

## STS Backend로 확인

Docker Backend를 먼저 중지합니다.

```powershell
cd C:\ssafy\SSAFY-TASK\web
docker compose stop backend
docker compose up -d db mqtt-init mosquitto
```

그 다음 STS에서 Spring Backend를 실행하고 STS Console을 확인합니다.
Docker Backend와 STS Backend를 동시에 실행하면 같은 메시지를 중복 처리하거나
동일 Client ID가 서로 연결을 끊을 수 있습니다.

## 외부 접속 준비

- 공유기 TCP 8883 포트포워딩
- Broker PC의 고정 내부 IPv4 확인
- Windows Firewall TCP 8883 허용
- `MQTT_BIND_ADDRESS=0.0.0.0`
- Broker 인증서 SAN에 외부에서 접속할 IP 또는 hostname 포함
- Mosquitto가 `0.0.0.0:8883`으로 실행 중인지 확인

현재 테스트 접속값:

```text
Host=125.137.58.131
Port=8883
Username=robot-test
Password=<MQTT_ROBOT_PASSWORD 값만 별도 전달>
CA=local-ca-cert.pem
```

## 테스트 완료 기준

- 외부 PC에 `Connected ... tls=on` 출력
- State Publish 성공
- Telemetry Publish 성공
- Mosquitto 로그에 `robot-test` 연결 표시
- Backend 또는 STS Console에 `STATE`, `TELEMETRY` 라우팅 로그 표시

`ROBOT_NOT_FOUND`는 임시 `robot-test`가 DB 정식 로봇이 아니어서 발생할 수
있으며, 외부 MQTT 통신 성공 여부와는 별개입니다.
