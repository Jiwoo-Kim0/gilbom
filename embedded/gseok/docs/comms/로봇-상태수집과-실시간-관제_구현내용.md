## 0. 3분 요약

Robot Presence·State·Telemetry를 MQTT로 받아 History와 Current State에 저장하고,
온라인·오프라인과 Boot 수명을 관리한다. 관리자에게는 Robot 목록·요약·지도·상세
REST를 제공하고, 변경 시 SSE로 알린 뒤 React가 REST 정본을 다시 읽는다.

중요한 안전 규칙은 다음 세 가지다.

1. 오래된 Telemetry는 History로 남을 수 있어도 Current State를 덮지 않는다.
2. DB Transaction이 Commit된 뒤에만 SSE를 보낸다.
3. 목록·지도·요약·단건 모두 사용자 Robot Scope를 SQL에서 적용한다.

로컬 TLS Broker에서 Mock Robot→MQTT→DB→SSE→REST→React Card·Marker 흐름을
검증했다. 실제 Naver 지도는 운영 Origin 등록이 필요하고, 실제 Jetson 연결은
외부 통합 범위다.

## 1. 요구사항과 수용 기준

### 1.1 Telemetry

- GPS, 배터리, 속도, CPU·Jetson·모터·배터리 온도 저장
- `sampled_at`/`observed_at`과 Backend `received_at` 분리
- History INSERT와 Current UPSERT를 한 Transaction으로 처리
- 더 오래된 표본은 Current를 덮지 않음
- 미등록·비활성 Robot 거부
- Topic/Payload `mqtt_id` 불일치 거부
- 동일 Boot·Sequence 재전송은 중복 History를 만들지 않음

### 1.2 Presence·State

- ONLINE/OFFLINE과 `last_seen_at`
- LWT·정상 종료 구분
- Boot Session과 Status History
- 새 Boot 첫 Sequence 1
- 90초 무응답 Offline, 30초 Scan
- State의 mode·reason·health·mission 상태 반영

### 1.3 REST·SSE

REST:

```text
GET /api/v1/robots
GET /api/v1/robots/summary
GET /api/v1/robots/map
GET /api/v1/robots/{robotId}
GET /api/v1/stream/robots
```

- Permission: `ROBOT_STATUS_VIEW`
- 컬렉션·집계 Scope는 SQL `EXISTS/JOIN`
- 범위 밖 단건은 404
- SSE는 변경 알림, REST는 최신 정본
- 재연결 후 REST를 다시 조회

## 3. 설계 판단과 그 이유

### 3.1 History와 Current를 분리했다

History는 사실 보존용이고 Current는 빠른 관제 조회용이다. 하나의 표로 해결하면
매 조회마다 최신 행을 계산해야 하고 오래된 메시지가 최신값을 덮는 위험이 커진다.

### 3.2 Current 갱신 조건을 DB 쓰기에서 강제했다

Java에서 먼저 시각을 비교한 뒤 UPDATE하면 동시 수신에서 경쟁할 수 있다. SQL
조건과 잠금 아래 최신 표본만 Current를 갱신한다.

### 3.3 SSE를 정본으로 쓰지 않는다

SSE는 연결이 끊겼을 때 Event 유실이 가능하다. 브라우저는 Event를 받으면 필요한
REST를 다시 읽고, 재연결했을 때도 전체 정본을 복구한다.

### 3.4 Commit 이후 발행한다

DB Rollback 전에 SSE를 보내면 화면에 존재하지 않는 상태가 잠시 보인다.
`AFTER_COMMIT` Listener를 통해 Transaction 성공 뒤에만 Event를 발행한다.

### 3.5 객체 Scope를 Java 후처리하지 않는다

전체 Robot을 조회한 뒤 Java에서 제거하면 Count·Pagination·Summary가 틀어지고
권한 없는 데이터가 Process 메모리에 들어온다. 목록·요약·지도부터 SQL에서
범위를 제한한다.

### 3.6 Offline은 LWT 하나에만 의존하지 않는다

비정상 네트워크에서 LWT가 지연되거나 Broker·Backend 연결이 달라질 수 있다.
LWT와 90초 Heartbeat Timeout을 함께 사용한다.

## 5. 작업 중 겪은 함정

### 등록 Robot에 Current State가 없으면 목록에서 빠졌다

실제 로그인 Mission E2E에서 Robot 목록 Query의 Join 때문에 임시 Robot이
보이지 않았다. 테스트 Seed도 운영 Registration Service와 같은 Current State
생성 불변식을 따라야 한다.

### Naver Maps 오류를 SSE 오류로 오인하기 쉽다

Marker가 안 보일 때 다음을 분리한다.

- REST 좌표
- SSE 수신
- SDK Script 로드
- Client ID
- 허용 Origin
- 좌표 순서

Naver Origin이 막혀도 React 상태와 Adapter 갱신은 별도로 검증할 수 있다.

### 좌표 순서는 GeoJSON과 지도 SDK가 반대다

GeoJSON은 `[longitude, latitude]`, Naver 생성자는
`LatLng(latitude, longitude)`다. Type만 맞아도 위치가 크게 틀릴 수 있어
Fixture로 검증한다.

### SSE Callback 정리를 빼면 Test 간 연결이 누적된다

Singleton Service의 Emitter Registry가 남으면 다음 Test의 구독 수와 발행 대상이
오염된다. 완료·Timeout·오류 Callback과 Test Context 격리가 필요하다.
