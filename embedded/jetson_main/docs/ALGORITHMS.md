>    그 이전 동작(한 프레임 소실 = 즉시 IDLE, 조향 = 프레임 목표 직결)을 전제한

>    **목표(중심선·블록 혼합)와 방향 선택(코스트맵)이 분리된** 구조다.

# 0부 — 이미 논의된 것 (기본 포함)

## B1. Context Steering

- **무엇**: 후보 방향을 슬롯으로 쪼개고 interest 맵(가고 싶은 곳)과 danger 맵(피할 곳)을
  각각 채운 뒤 합성해 방향을 고른다. 게임 AI 계보 (Andrew Fray, *Game AI Pro 2*, 2015).
  Reynolds의 steering behaviors가 벡터를 더하다가 "좌로 + 우로 = 직진해서 박음"이 되는
  문제를 "더하지 말고 방향별로 따로 평가하라"로 푼 것.
- **왜 우리에게**: 현재 `_handle_cruise`는 `any(o.blocking)`만 본다. **`blocking=False`인
  장애물은 `proximity`가 0.9여도 완전히 무시되고 중심 추종만 한다** — 옆의 볼라드·비켜선
  보행자를 그대로 스친다. soft danger를 주면 상태 전이 없이 미리 비껴간다.
- **어떻게**: `driving/steering_context.py`(순수 모듈) 신설. 슬롯 축은 **각도가 아니라
  인지의 정규화 image-x `[-1,+1]`** 로 잡는다 — `lateral_bias`·`center_offset_ratio`가
  이미 그 좌표계에 있고, 내부 파라미터 없이 극좌표를 흉내 내면 없는 기하를 지어내는 꼴이다.
  선택된 `d*`에 `steer_gain_deg`를 곱해 도(°)로 환산.
- **전제**: 없음. 현재 `SegmentationFrame` 그대로 동작 (`obstacles` 튜플이 다봉 danger 맵의 재료).
- **리스크**: 반응형이라 로컬 미니마를 못 벗어난다. **"멈출까"는 절대 맡기지 말 것** — 이
  알고리즘은 항상 "제일 덜 나쁜 방향"을 하나 내놓지 스스로 멈추는 법이 없다. 정지 판단은
  FSM 가드에 유지.

## B2. VFH / VFH+ ⭐

- **무엇**: Borenstein & Koren(1991)의 극좌표 히스토그램 장애물 회피. 사실상 context
  steering의 로봇 쪽 조상. **VFH+**(Ulrich & Borenstein, 1998)가 추가한 것: ①로봇 반경
  팽창 `γ = asin((r_robot+s)/d)` ②2-임계 이진 히스토그램(히스테리시스) ③최소회전반경
  마스킹 ④3항 비용함수.
- **왜 우리에게**: ①과 ③이 context steering에 없는 것 — "저 틈에 실제로 들어가나"와
  "그 방향으로 실제로 꺾을 수 있나". 비홀로노믹 문제를 정면으로 푼다.
- **어떻게 — 오늘 절반, IPM 뒤 나머지 절반**:

  | 단계 | 지금 가능? | 비고 |
  |---|---|---|
  | ① 1차 히스토그램 (거리 가중 + 반경 팽창) | ✗ IPM 필요 | `d`, `r_robot`이 미터여야 함 |
  | ② 이진 히스토그램 (τ_low/τ_high 히스테리시스) | **✓ 가능** | 1D 신호처리, 축 무관 |
  | ③ 마스킹 (최소회전반경) | ✗ IPM + 조향 캘리브 | **선택이 아니라 필수** (아래 참조) |
  | ④ 비용함수 (목표/현재조향/직전선택) | **✓ 가능** | 축 무관 |

  ②④는 지금 B1 모듈에 넣어도 나중에 ①③이 오면 **그대로 승격된다 — 버려지는 코드 없음.**
  필요한 상태는 `StateMachineContext`에 `prev_binary`, `prev_sector` 두 필드뿐이라
  `step()` 순수성이 유지된다.
- **우리 로봇용 개조 3가지**:
  1. **비대칭 마스킹** — 좌우 `r_min`을 따로. 우측 한계는 소프트 리밋 30이 아니라
     **HARDWARE.md의 지속 조향 권장치 25°** 를 쓸 것 (절대 130°가 링키지 걸림 경계).
  2. **섹터 범위** — 원본은 소나 링 360° + 제자리 회전 전제. 여기는 카메라 FOV ∩ 조향 가능
     부채꼴로 한정. **마스킹(③) 없이 "목표에 가장 가까운 골짜기"를 고르면 도달 불가능한
     골짜기를 골라놓고 못 가는 상황이 난다.**
  3. **속도 제어** — 원본 감속식이 `throttle_pct`에 그대로 대응. 단 50%=0.16 m/s라 감속
     여지가 작아 우선순위 낮음.
- **리스크**: 원본의 certainty grid는 **여러 측정을 누적**하는 게 본질인데, 누적하려면
  움직인 만큼 격자를 밀어야 하고 그건 오도메트리다 → **N1이 이 블로커를 푼다.**
  로컬 미니마는 VFH+도 못 푼다 (VFH*는 룩어헤드를 붙이지만 맵이 필요). DEAD_END는 FSM에 유지.

## B3. IPM / BEV 호모그래피 — **아래 절반의 전제**

카메라 높이·틸트각·화각만 실측하면 세그 마스크를 탑다운으로 편다. 고정 마운트라 1회
실측 후 `config.yaml`에 상수로 박으면 끝. 이게 되면 `proximity`가 proxy가 아니라 미터가
되고, 열(column) 프로파일이 자동으로 따라온다. 하향각에서 거리의 신뢰 단서는 마스크
**아랫변(지면 접촉선)** — 덩어리 전체가 아니라 바닥에 닿는 픽셀 행 하나만 보면 된다.

**대가**: 틸트를 줄수록 근거리를 얻고 원거리를 잃으며 **범퍼 앞에 사각지대**가 생긴다.
다른 센서가 없으므로 카메라에서 사라진 물체가 없어진 물체가 아니다 → **N4가 필수에 가깝다.**

## B4. Pure Pursuit / Stanley

look-ahead 점 + 휠베이스 기하로 조향각을 낸다 (`δ = atan(2·L·sin α / L_d)`).
현재 `offset_ratio × gain`은 기하가 없는 순수 P제어라 속도가 바뀌면 흔들린다.
**CRUISE 한정 단일 최대 개선.** 전제: 조향 오프셋(°) → 실제 곡률 캘리브레이션.

## B5. Costmap + Inflation Layer

장애물을 격자에 찍고 로봇 반경만큼 부풀려 비용을 매긴다(ROS nav2 방식). B1의 danger
감쇠 함수의 산업판이되, 미터 공간이라 "로봇 폭 30cm니 이 틈은 못 지나감"을 정확히 판정.

## B6. DWA (Dynamic Window Approach)

Fox/Burgard/Thrun(1997). 가속 한계상 다음 스텝에 도달 가능한 (속도, 조향)만 샘플링해
짧은 호로 시뮬레이션 후 `목표진행 + 여유 + 속도`로 점수. **방향만 고르는 B1/B2와 달리
속도까지 같이 고른다.** 지금 스로틀 50% 고정을 대체할 정공법.

## B7. Velocity Obstacles / RVO / ORCA

움직이는 보행자를 속도 공간에서 기하학적으로 배제. 현재 `_handle_avoid`의
"움직이는 장애물은 기다리면 지나간다"는 주석은 **속도 장애물의 가장 원시적인 특수해**다
(자기 속도를 0으로 두면 충돌 원뿔에서 빠져나오므로). 0.16 m/s vs 보행 1.4 m/s라
그 근사가 실제로 꽤 잘 맞는다 — 우선순위를 낮게 둬도 되는 이유. 전제: **N5(추적)**.

## B8. TTC (Time-To-Collision)

마스크가 **커지는 속도**로 충돌까지 남은 시간 추정. 깊이 없이 되는 게 장점(실제 AEB의
기본 신호). IPM이 들어오면 대체로 불필요해지므로 IPM을 건너뛸 때의 우회로.

# 1부 — 신규 10개

## N1. 시각 오도메트리 — 지면 광류 ⭐⭐ **강력 권장**

- **무엇**: 하향각 카메라가 보는 **지면 텍스처의 광류(optical flow)** 로 자기운동을 복원한다.
  희소 Lucas-Kanade 특징 추적 + 이미 알고 있는 지면 호모그래피(B3) → 픽셀 이동을 미터
  병진 + 요(yaw) 회전으로 환산. **광학 마우스 센서를 크게 키운 것**과 원리가 같다.
- **왜 우리에게 — 이게 현재 설계의 전제 하나를 뒤집는다**:
  현재 `README.md`·`hardware/interfaces.py`는 **"자기운동을 알 수 있는 유일한 길은 IMU"** 라는
  전제 위에 서 있다. 그래서 SLOPE·DEAD_END·AVOID 복귀가 전부 `imu is None`으로 닫혀 있다.
  그런데 **하향각 + 지면 평면 + 저속(틱당 8mm)** 은 시각 오도메트리에 거의 이상적인 조건이고,
  **필요한 하드웨어가 이미 다 있다.** 이게 되면:
  - AVOID 우회 후 원방향 복귀의 yaw → **IMU 없이 나온다**
  - DEAD_END 180° 누적 판정 → **IMU 없이 나온다**
  - N4(점유격자 누적)의 블로커인 오도메트리 → **풀린다**
  - B2 VFH+의 certainty grid 누적 → **풀린다**

  IMU가 여전히 유리한 곳은 **pitch(경사)** 다. 광류는 지면 평면 가정이 깨지는 경사에서
  약해지므로 SLOPE는 IMU 게이트로 두는 게 맞다. 즉 **IMU 게이트를 없애자는 게 아니라,
  "IMU 게이트에 걸려 있는 3개 중 2개는 사실 IMU가 아니라 오도메트리가 필요했던 것"** 이다.
- **어떻게**: 인지 계층에 `OdometryProvider`(신규 추상)를 두고 `EgoMotion(dx, dy, dyaw, dt,
  confidence)`를 낸다. `step()` 시그니처에 `imu` 옆에 `ego` 인자를 추가 — 게이트 판정을
  `imu is not None` 에서 **"필요한 양이 확보됐는가"** 로 바꾼다(pitch는 imu, yaw는 imu **또는** ego).
  `hardware/mocks.py`의 `MockImu`처럼 mock ego를 꽂아 테스트로 경로가 열림을 증명하는 방식은 그대로.
- **전제**: B3(IPM). 지면 텍스처가 있어야 한다.
- **리스크**: 매끈한 지면(젖은 대리석·균일 아스팔트)에서 특징이 안 잡힌다 → `confidence`를
  반드시 내보내고 낮으면 게이트를 다시 닫을 것. 스케일 드리프트가 누적되므로 **절대 위치용이
  아니라 수 초 스케일의 상대 운동용**으로만 쓸 것 (우리 용도가 정확히 그것). 경사·요철에서
  평면 가정이 깨짐. Orin Nano에서 희소 LK는 CPU로 충분(세그 GPU와 경합 없음).

## N2. Reeds-Shepp / Dubins 곡선 ⭐ **DEAD_END TODO를 대체**

- **무엇**: 최소회전반경이 있는 차량의 **최단 경로 폐형식 해**. Dubins(1957)는 전진만,
  **Reeds-Shepp(1990)은 전진+후진**을 허용해 48개 경로 패턴 중 최적을 골라준다.
- **왜 우리에게**: 현재 `_handle_dead_end`의 TODO는 "왼쪽 최대 조향 전진 → 조향 정렬 후
  후진, 반복 + yaw 누적 180°"인데, 이건 **손으로 짠 개루프 기동**이고 몇 번 반복해야 하는지,
  주어진 폭에서 가능하긴 한지 알 수 없다. Reeds-Shepp은 **"현재 자세 → 목표 자세(180° 반대)"
  를 최소 기동으로 푸는 교과서 문제 그 자체**다. 회차가 물리적으로 불가능한 폭이면
  **해가 없다고 알려주는 것**도 중요하다 (지금은 무한 반복에 빠질 수 있다).
- **어떻게**: `driving/maneuver.py`(순수) — 목표 자세와 `r_min`(좌/우 비대칭)을 넣으면
  `(방향, 조향, 길이)` 세그먼트 리스트가 나온다. `_handle_dead_end`는 그 리스트를 순서대로
  실행하는 얇은 실행기가 된다. 진행도 판정은 **N1의 ego 누적**으로.
  덤: 여기서 계산되는 `r_min` 기하가 **B2 VFH+ 마스킹(③)이 요구하는 바로 그 값**이다.
- **전제**: 조향 오프셋(°) → 회전반경 캘리브레이션. **좌우 비대칭(좌 45 / 우 25)을 반드시
  반영** — 대칭 가정 구현체를 그대로 가져다 쓰면 우측에서 링키지 걸림 경계를 넘길 수 있다.
- **리스크**: 개루프 실행이면 오차가 쌓인다 → N1으로 닫아야 실용적. 후진 시 **카메라가
  전방만 보므로 후방은 완전 무지** — 후진 구간은 저속 + 짧은 거리 + N4의 기억에 의존해야 하고,
  그마저 불충분하면 "후진 금지" 모드(Dubins만 사용)로 떨어뜨리는 폴백이 필요하다.

## N3. Hybrid A*

- **무엇**: 격자 A*에 **연속 자세(x, y, θ)와 차량 기구학**을 얹어 실행 가능한 경로만 탐색한다
  (Dolgov·Thrun 등, DARPA Urban Challenge의 Stanford Junior). 노드 확장이 Reeds-Shepp
  세그먼트라 N2 위에 자연히 올라간다.
- **왜 우리에게**: N2가 "빈 공간에서의 최소 기동"이라면 Hybrid A*는 **장애물이 있는 상태에서의**
  기동이다. 좁은 인도에서 회차하거나, 폭이 아슬아슬한 AVOID 우회에서 반응형(B1/B2)이
  못 푸는 경우를 푼다.
- **어떻게**: N4의 점유격자 위에서 국소 윈도우(예: 전방 3m × 폭 3m)만 탐색. 매 틱이 아니라
  **DEAD_END 진입 시·AVOID 재확인 실패 시에만** 1회 계획하고 이후는 추종(B4)으로.
- **전제**: N2 + 격자(N4 또는 B5). **`driving/`의 순수성 계약은 유지되지만 탐색은 무겁다** —
  20Hz 루프 안에서 매 틱 돌리면 안 된다.
- **리스크**: 계획 시간이 튄다(수십~수백 ms). 계획 중 로봇은 정지시키는 게 안전하고,
  다행히 그건 이미 AVOID/DEAD_END의 기본 동작이다.

## N4. 로그오즈 점유격자 (이진 베이즈 필터) ⭐⭐ **강력 권장**

- **무엇**: 격자 셀마다 점유 확률을 **로그오즈**로 들고, 매 관측을 역센서모델로 더한다
  (Moravec & Elfes 1985; Thrun *Probabilistic Robotics*). 덧셈만으로 베이즈 갱신이 되어
  아주 싸고, 관측이 겹칠수록 확신이 올라가고 안 보이면 서서히 잊는다.
- **왜 우리에게 — 지금 인지는 기억이 전혀 없다**:
  `SegmentationFrame`은 프레임 1장의 스냅샷이고 FSM은 매 틱 그걸 새로 본다. 그런데
  **하향각은 범퍼 앞에 구조적 사각지대를 만든다(B3의 대가).** 즉 **로봇 바로 앞으로 들어온
  물체는 시야에서 사라지고, 현재 구조에서는 그 순간 존재하지 않는 것이 된다.** 다른 센서가
  하나도 없으므로 이건 설계상 실제 위험이다. 세그 노이즈(한 프레임 깜빡임)로 상태가 튀는
  문제도 같이 잡힌다 — 세그 노이즈(한 프레임 깜빡임)는 현재 `perception_grace_sec`
  유예창이 1차로 막고 있고, 격자 누적은 유예를 넘는 지속 소실까지 견디게 해주는 다음 단계다.
- **어떻게**: 인지 계층에 로봇 고정 좌표계 격자(예: 전방 4m × 폭 3m, 5cm 셀 = 80×60)를 두고,
  매 프레임 IPM으로 편 마스크를 로그오즈 가산. **로봇이 움직인 만큼 격자를 시프트**하는 데
  **N1의 ego**를 쓴다. `SegmentationFrame`은 그대로 두고 이 격자에서 요약 필드를 재생성하면
  하위 호환이 유지된다(주행 계층 무변경).
- **전제**: B3 + N1. N1이 없으면 누적 없이 프레임 단위로만 쓸 수 있으나 기억 이득이 사라진다.
- **리스크**: ego 오차가 격자를 뭉갠다 → `confidence` 낮으면 누적 중단하고 리셋. **SLOPE
  구간은 지면 평면 가정이 깨지므로 진입 시 격자 리셋이 안전.** 메모리·연산은 무시할 수준.

## N5. EKF / 등속 모델 다중 객체 추적

- **무엇**: 프레임 간 검출을 연결(IoU·중심 거리 매칭)하고 각 트랙에 칼만 필터(등속 모델)를
  붙여 위치·속도를 추정. SORT 계열의 최소 구성이면 충분하다.
- **왜 우리에게**: 현재 `ObstacleRegion`에는 **ID도 속도도 없다.** 그래서 "이 사람이 다가오는지
  멀어지는지"를 원리적으로 알 수 없고, `_handle_avoid`가 3초 세고 다시 보는 것 말고 할 수 있는
  게 없다. 추적이 들어오면 **B7(ORCA)·B8(TTC)이 동시에 열리고**, 무엇보다 **"기다리면 지나갈
  장애물"과 "안 비켜줄 고정 장애물"을 구분**할 수 있다 — 지금은 둘 다 3초 후 똑같이 취급한다.
  이 구분이 되면 `avoid_recheck_sec` 고정 대기를 상황 적응형으로 바꿀 수 있다.
- **어떻게**: 인지 계층에서만 처리하고 `ObstacleRegion`에 `track_id`, `velocity_bias`(또는
  BEV라면 `vx, vy`), `age` 필드를 추가. 주행 계층은 필드가 늘어난 것만 보면 되므로 계약 확장이
  하위 호환이다.
- **전제**: 없음(IPM 없이 image-x에서도 동작). IPM이 있으면 속도가 미터/초가 되어 훨씬 유용.
- **리스크**: 세그 마스크가 붙었다 떨어졌다 하면 ID가 갈린다. 저속이라 매칭 자체는 쉬운 편.

## N6. RANSAC + 중심선 다항식 적합 ⭐⭐ **강력 권장 → 2026-07-31 채택(부분)**

> **채택 범위**: 행별 중심 표본 → RANSAC 2차 적합 → `lookahead_ratio` 지점을 조향
> 목표로 읽는 것까지 `perception/segmentation.py`에 구현했다(파라미터는
> `config.yaml` `perception.segmentation.post.centerline`). 적합 실패 시 무게중심으로
> 강등되므로 종전 경로가 폴백으로 남는다.
> **안 한 것**: `centerline_coeffs`·`curvature`·`fit_confidence`를 `SegmentationFrame`에
> 노출하지 않았다 — 소비처가 아직 없고, 곡률은 **B3(IPM) 전에는 물리적 의미가 없다**.
> 아래 본문의 "① 미리 감속 ② TURN 트리거 ③ B4 look-ahead 대상"은 그 필드가 필요해질
> 때 함께 열 것. 따라서 `CRUISE → TURN` 진입 조건은 여전히 미배선이다.

- **무엇**: 세그 마스크의 주행가능 영역 경계에서 좌/우 경계선을 **RANSAC**(Fischler & Bolles
  1981)으로 강건하게 뽑고, 그 중앙을 2차 다항식이나 스플라인으로 적합해 **중심선**을 만든다.
  BEV(B3)에서 하면 곡선이 실제 도로 곡률이 된다.
- **왜 우리에게 — 현재 인지→주행 인터페이스에서 가장 정보 손실이 큰 지점**:
  지금 인도 형상 전체가 `sidewalk_center_offset_ratio` **스칼라 1개**로 압축된다. 그래서
  ① 앞이 굽었는지 직선인지 모르고(→ 미리 감속·선조향 불가) ② 곡률을 모르니 **B4 pure
  pursuit을 붙일 수가 없고**(look-ahead 점을 찍을 대상이 없다) ③ 세그 경계 노이즈가 그대로
  조향으로 새어 나온다. RANSAC 적합은 **이 셋을 한 번에** 해결하고 연산은 거의 공짜다.
  덤으로 **곡률이 나오면 `README.md`에서 "진입 조건 미정"인 `CRUISE → TURN` 트리거의
  후보가 생긴다** (곡률이 임계 초과 + 지속).
- **어떻게**: `SegmentationFrame`에 `centerline_coeffs: Tuple[float, ...]`(BEV 기준 2차 계수)와
  `curvature`, `fit_confidence`를 추가. `_handle_cruise`는 스칼라 대신 이 곡선에 look-ahead를
  찍어 B4로 조향. 기존 `sidewalk_center_offset_ratio`는 곡선에서 유도해 채워주면
  **폴백 경로로 그대로 남는다** (적합 실패 시 현재 P제어로 안전 강등).
- **전제**: 없음(이미지 공간에서도 가능). 단 BEV에서 해야 곡률이 물리적으로 의미 있다.
- **리스크**: 인도가 갈라지거나 교차로에서 경계가 둘 이상이면 RANSAC이 엉뚱한 선을 잡는다 →
  `fit_confidence` 필수, 낮으면 폴백. 점자블록을 경계로 오인하지 않도록 클래스 분리 필요(N7).

## N7. 시맨틱 주행가능도 코스트맵 ⭐⭐ **강력 권장 → 2026-07-31 채택(1단계)**

> **채택 범위**: 인지가 하단 밴드를 x축 슬롯으로 쪼개 클래스별 비용을 얹은
> `cost_profile`을 산출하고(`perception/segmentation.py`의 `build_cost_profile`),
> CRUISE가 슬롯 점수(통행 비용 + 목표 이탈 + 직전 선택 이탈 히스테리시스) 최소
> 방향을 고른다(`driving/steering_costmap.py`). 차도=∞라 그 방향은 선택 자체가
> 안 되고, 전 방향 ∞면 AVOID 정지 후 재확인 주기마다 재평가한다.
> 클래스→비용 표는 `config.yaml perception.segmentation.costmap`, 조향 가중치는
> `driving.cruise.costmap`.
> **슬롯 축은 각도가 아니라 정규화 image-x(-1~+1)다** — `cost_profile`과
> `*_offset_ratio`가 이미 그 좌표계에 있고, 기하 없이 극좌표를 흉내 내면 없는 기하를
> 지어내는 꼴이다(B1 항목의 결정 그대로). 실제 각도 변환은 B3(IPM) 이후의 일이다.
> **격자가 아니라 1차원 프로파일이다**: 아래 본문의 로봇 고정 격자·팽창(B5)·
> 시간 누적(B2)은 전부 미채택 — 그쪽은 IPM(B3)과 ego 추정(N1)이 선행 조건이다.
> **폴백**: `cost_profile`이 없는 프레임(mock 기본)은 종전 비례 조향 그대로다.
> 남은 것: 실사 영상 기반 비용·가중치 보정, B5(inflation)는 B3 이후.

- **무엇**: 세그 **클래스별로 통행 비용**을 부여해 격자를 만든다(인도=0, 점자블록=낮음,
  연석=높음, 잔디·화단=중, **차도·통행금지=∞**). 실제 배달로봇들이 인도 주행에서 쓰는 방식.
- **왜 우리에게 — `roadway_encroachment_risk`가 bool인 게 지금 설계의 약점**:
  현재 차도 위험은 **참/거짓 하나**이고 그 결과는 **즉시 ESTOP 래치(수동 해제만)** 다. 문제는
  ① 방향이 없어서 **차도 쪽으로 조향하지 않도록 예방할 방법이 없다** — 위험해진 다음에야
  반응한다 ② 세그 한 프레임 오탐이 곧바로 "사람이 가서 풀어줘야 하는 정지"가 된다.
  클래스별 비용이면 **차도 방향 섹터에 무한 비용을 박아 애초에 그쪽을 고르지 않게** 되고,
  ESTOP은 예방이 실패했을 때의 최후 방어선으로 제자리를 찾는다.
  또한 `README.md`가 "범위 외"로 둔 **점자블록 탐지가 새 파이프라인 없이 여기 클래스 하나로
  들어온다** — 유도 신호로 쓰든 회피 대상으로 쓰든 비용값만 바꾸면 된다.
- **어떻게**: 클래스→비용 표를 **`config.yaml`에** (튜닝 숫자 단일 출처 규칙 그대로). 인지가
  비용 격자를 만들고, B1/B2의 danger 맵과 B5 costmap이 그걸 그대로 소비. `SegmentationFrame`의
  기존 bool은 "무한 비용 셀이 코리도 안에 있는가"로 유도해 채우면 하위 호환.
- **전제**: 세그 모델이 **다중 클래스**로 학습돼 있을 것. 2단계 모델 설계 시 **지금 결정해야 하는
  사항**이다 — 이진(주행가능/불가)으로 학습해버리면 나중에 재학습해야 한다. ← **가장 시급한 판단**
- **리스크**: 클래스가 늘면 추론이 무거워지고 라벨링 비용이 오른다. 최소 4클래스(인도/차도/
  장애물/기타)에서 시작해 점자블록은 나중에 추가하는 게 현실적.

## N8. BEV 자유공간 → 가상 LaserScan 변환

- **무엇**: BEV 자유공간을 각도별로 레이캐스팅해 **가짜 2D 레이저 스캔**을 만든다
  (ROS의 `depthimage_to_laserscan`이 깊이 카메라에 쓰는 것과 같은 수법).
- **왜 우리에게**: 순수 알고리즘이라기보다 **통합 전략**이다. 스캔 형식이 되는 순간 VFH+·DWA·
  TEB·costmap 등 **기성 구현체를 그대로 재사용**할 수 있다 — 직접 짤 물건이 확 줄어든다.
  카메라를 라이다로 교체하거나 추가할 때도 상위 알고리즘이 안 바뀐다는 게 부수 이득.
- **어떻게**: 인지 계층 마지막 단계. `SegmentationFrame`과 별도 산출물로 내되 소비는 선택적.
- **전제**: B3.
- **리스크**: 2D로 눌러서 **높이 정보를 버린다** — 낮은 턱과 벽이 구분 안 된다. 다만 지금도
  구분 못 하므로 손해는 아니다. ROS를 안 쓴다면 이득의 절반이 사라진다.

## N8-ego. 자차 연결 주행가능 영역 — **2026-08-04 채택·구현**

- **문제**: 0803 실외 주행에서 **길 건너 차도가 `sidewalk`로 오분류되는 경우**가 있었다.
  `drivable`을 클래스 마스크의 전역 합집합으로 쓰고 있었으므로 그 픽셀이 무게중심·중심선
  적합·경계 판정에 그대로 섞여 조향 목표를 차도 쪽으로 끌어당겼다. 관련 연구도 이
  road↔sidewalk 혼동을 "false-safe representation of an unsafe region"으로 부르며 안전
  치명 실패 모드로 분류한다 — 즉 세그 정확도를 올려서 해결할 문제가 아니라 **하류에서
  걸러야 하는** 문제다.
- **무엇**: 로봇은 지금 인도 위에 있다. 그러므로 **자차 위치에서 끊기지 않고 이어진 영역만**
  자기 주행면으로 인정한다. 길 건너 영역은 사이에 차도(비주행)가 있어 연결이 끊긴다.
  일반형은 연결성분 분해(flood fill / CCL)지만, 여기서는 **열 방향 연속성**만 본다:
  각 열에서 판정 밴드 아래 경계부터 위로 누적 AND를 걸어 연속 구간만 남긴다.
- **왜 열 방향인가**: ① N8-lite(자유공간 프로파일)가 이미 같은 계산을 하고 있었다 —
  같은 물리를 보는 판정을 두 벌로 두지 않기 위해 하나로 합쳤다(`_ego_run_mask` 한 장이
  두 판정의 재료다). ② 640×480 전면 CCL은 20Hz 예산에서 부담이고, scipy 없이 numpy로
  반복 팽창을 돌리면 최악 480회 전체 배열 연산이다. 열 누적 AND는 `logical_and.accumulate`
  한 번이다.
- **보정**: 그림자·맨홀 뚜껑·타일 이음선이 한두 행을 끊으면 그 위 인도가 통째로 탈락하므로,
  누적 전에 `post.ego_gap_rows`만큼 **세로 닫힘**(팽창→침식)을 건다. 닫힘은 정의상 원본을
  포함하므로 주행가능 면적이 줄어들 위험이 없다.
- **한계**: 열 방향이라 **코너를 돌아가는 연결은 못 따라간다** — 인도가 앞의 가림물 뒤에서
  꺾이면 그 뒤쪽은 탈락한다. 주행 목표는 lookahead 지점(밴드 안)이므로 실질 손해는 없지만,
  전역 지도를 만들 단계(N4 점유격자)가 오면 진짜 연결성분으로 올려야 한다.
  `gap_rows`를 키우면 **사람 다리 사이로 이어져** 방어선이 무력해진다.
- **검증**: `tests/test_ego_connectivity.py` — numpy 알고리즘을 순수 파이썬으로 미러링해
  합성 장면(내 인도 + 차도 띠 + 길 건너 오분류 패치)에 돌린다. 전역 합집합은 무게중심을
  왼쪽으로 끌고(오분류 패치 방향), 자차 연결은 오차 0.02 이내로 유지한다.

## N9. MPC (기구학 자전거 모델, 짧은 예측구간)

- **무엇**: 예측 모델로 N스텝 앞을 시뮬레이션하고 비용을 최소화하는 제어 입력열을 풀어
  **첫 스텝만 적용**하고 매 틱 다시 푼다.
- **왜 우리에게**: **비대칭 조향 한계(좌 45 / 우 25)를 "나중에 클램프"가 아니라 최적화의
  하드 제약으로 직접 넣을 수 있다.** 지금은 상위 로직이 낸 값을 하드웨어 계층이 잘라내므로,
  잘린 결과가 의도와 다르다는 걸 상위가 모른다. 조향 속도 제한(서보 슬루율)도 제약으로 들어간다.
- **어떻게**: 채택한다면 B4(pure pursuit)를 대체하는 자리. 예측구간 1~2초면 0.16 m/s에서
  16~32cm — 매우 짧아서 문제 크기가 작다.
- **전제**: B3 + 조향/속도 캘리브레이션 + 모델 식별.
- **리스크**: **이 속도에서는 과잉일 가능성이 높다.** pure pursuit + 조향 rate limit으로
  대부분 해결되므로 **B4를 먼저 하고, 부족함이 실측으로 확인될 때만** 올 것. 솔버 의존성도
  Jetson 환경에서 부담.

## N10. 제어 장벽 함수 (CBF) 안전 필터

- **무엇**: 안전 집합을 벗어나지 않도록 **어떤 제어기의 출력이든 최소한으로 수정**하는 필터.
  QP 한 번으로 "가능한 한 원래 명령을 존중하되 안전 제약은 반드시 만족"을 푼다 (Ames 등).
- **왜 우리에게**: 이 프로젝트에는 이미 **같은 철학이 있다** — `SteeringServo.set_offset_deg`
  템플릿 메서드가 상위 로직 버그와 무관하게 물리 한계를 강제한다. CBF는 그 아이디어를
  **기하학적 한계가 아니라 충돌 안전까지** 확장한 형식화 버전이다. 여러 알고리즘(B1/B2/B4/N3)이
  섞여 명령을 낼 때 **안전 논증을 한 곳으로 모을 수 있다**는 게 구조적 이점.
- **어떻게**: `main.py`의 `apply_command` 직전 한 지점(이미 single writer라 자리가 정확히 하나다).
- **전제**: 모델 + 장애물 거리 함수(N4).
- **리스크**: **현 단계에서는 명백히 과잉.** FSM 가드 + 하드웨어 클램프 2중으로 이미 충분하고,
  CBF가 잘못 튜닝되면 오히려 안전 논증이 불투명해진다. **"나중에 알고리즘이 3개 이상 섞이면
  이런 정리 수단이 있다"는 참고 항목**으로만 기록.

# 2부 — 채택 순서 권장

전제 의존성을 따라가면 순서가 거의 결정된다.

```
[세그 모델 도입]  ←── N7 클래스 설계를 여기서 같이 결정해야 함 (재학습 방지)
      │
      ├─ N5 추적 ─────────────────┐  (IPM 불필요, 지금도 가능)
      ├─ N6 RANSAC 중심선 ────────┤  (이미지 공간에서도 가능, BEV면 더 좋음)
      ├─ B1 + B2의 ②④ ───────────┤  (계약 변경 0, 나중에 100% 승격)
      │                            │
      └─ B3 IPM ★핵심 분기점       │
           ├─ N1 시각 오도메트리 ★★ → N4 점유격자 ★★ → B2의 ①③ 완성 (진짜 VFH+)
           ├─ B4 Pure Pursuit ←── N6가 있어야 look-ahead를 찍을 대상이 생김
           ├─ N2 Reeds-Shepp → N3 Hybrid A*  (DEAD_END 실구현)
           ├─ N7 시맨틱 코스트맵 → B5 / N8
           └─ B7 ORCA (N5와 결합) / B6 DWA / N9 MPC / N10 CBF (후순위)
```

**단계별 묶음:**

| 순서 | 작업 | 얻는 것 | 계약 변경 |
|---|---|---|---|
| 0 | N7 **클래스 설계 결정** | 재학습 방지 | (세그 모델 학습 전에 결정) |
| 1 | B1 + B2②④, N5, N6 | 비-blocking 회피, 떨림 제거, 추적, 중심선 | 필드 추가만 (하위 호환) |
| 2 | **B3 IPM** + 조향/속도 캘리브레이션 | 미터 공간 — 이후 전부의 전제 | `config.yaml` 절 추가 |
| 3 | **N1 시각 오도메트리** | **IMU 게이트 3개 중 2개 해제** | `step()`에 `ego` 인자 |
| 4 | N4 점유격자 + B2①③ | 사각지대 기억, 진짜 VFH+ | 인지 내부 |
| 5 | B4 Pure Pursuit, N2 Reeds-Shepp | CRUISE 안정화, DEAD_END 실구현 | 없음 |
| 6+ | N7 코스트맵 확장, N3, B6/B7, N8~N10 | 상황별 | — |

**2번(IPM)과 3번(N1)이 이 문서 전체의 병목**이다. 둘 다 하드웨어 추가 없이 실측과 코드만으로
되고, 그 위에서 나머지 대부분이 열린다.

# 3부 — 지금 틀에서 **바꾸지 말아야 할 것**

위 알고리즘을 얹더라도 아래는 유지하는 게 맞다. 전부 안전 논증의 뼈대이고, 새 알고리즘은
**그 아래 계층**으로 들어가야 한다.

| 유지할 것 | 이유 |
|---|---|
| **FSM이 상태·정지를 판단** | B1/B2/B6은 전부 "제일 덜 나쁜 방향"을 항상 하나 내놓지 **스스로 멈추지 않는다.** 정지·ESTOP 판단을 반응형 알고리즘에 넘기면 안 된다 |
| **ESTOP 래치 + 수동 해제** | N7로 예방이 좋아져도 최후 방어선은 남아야 한다 |
| **경계 소실 → IDLE (자동 재출발 없음)** | 인지 실패 시 사람에게 넘기는 정책. N4가 노이즈를 걸러줘도 정책 자체는 유지 |
| **`step()` 순수성 (I/O·시계 금지)** | N1~N7 전부 순수 함수로 표현 가능. N3만 무거워서 "매 틱 아님"이 필요 |
| **single writer (`apply_command`)** | 알고리즘이 늘수록 더 중요해진다. N10이 붙는다면 정확히 이 지점 |
| **하드웨어 계층 클램프** | 상위가 아무리 똑똑해져도 물리 한계 강제는 최하층에 남아야 한다 |
| **dry-run 기본** | 알고리즘 추가마다 실물 없이 검증 가능해야 한다 |
| **튜닝 숫자는 `config.yaml`만** | 위 알고리즘들은 튜닝 파라미터를 많이 들고 온다. 이 규칙이 없으면 금방 무너진다 |

**FSM을 Behavior Tree로 바꾸는 것도 검토했으나 권하지 않는다.** BT가 상태 수가 늘 때 유리한 건
맞지만, 현재 7상태 규모에서는 이득이 없고 **전이 테이블이 명세서와 1:1로 감사 가능하다는
현재의 장점**(`TRANSITION_TABLE` ↔ README 다이어그램 ↔ pytest)을 잃는다. 안전 요구가 있는
쪽에서는 명시적 FSM이 더 방어하기 쉽다.

# 4부 — 검토했으나 현 구성에 부적합

| 알고리즘 | 왜 아닌가 |
|---|---|
| SLAM (ORB-SLAM 등) | 맵이 필요한 용도가 없다(GPS·전역 경로 범위 외). 연산도 세그와 경합 |
| 파티클 필터 MCL | 사전 맵 전제. 위와 동일 |
| Stixel / v-disparity | **스테레오 전제.** 두 카메라는 용도·마운트가 다른 비캘리브 구성이라 스테레오 쌍이 아니다 — 불가 |
| D* Lite / 전역 A* | 전역 맵·목적지 개념이 없다. 국소 창에서는 N3로 충분 |
| RSS (책임 민감 안전) | 차량 간 규칙 모델. 인도·보행자 환경에 안 맞음 |
| 강화학습 기반 주행 | 안전 논증·재현성·검증 비용 모두 이 프로젝트 성격과 반대 |
| Potential Field (원조) | 로컬 미니마로 유명하게 실패한 조상. **B1/B2가 그 교훈의 결과물** — 역사 참고용 |
| Flow Field (게임) | 다수 유닛용. 단일 로봇에는 costmap(B5)이면 충분 |
