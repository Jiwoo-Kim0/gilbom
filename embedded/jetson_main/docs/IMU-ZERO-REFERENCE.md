# IMU 영점 — pitch 는 절대, yaw 는 상대 (미적용 · 설계 결론)

**현재 코드는 pitch 영점을 부팅 자세로 잡는다. 출발 지점 경사가 매번 다르면 못 쓴다.**
아래는 고칠 방향이고 아직 반영하지 않았다.

## 1. 증상

`hardware/jetson/imu.py` `_calibrate()` 가 첫 `read()` 에서 pitch 기준면을 **그 순간의
자세**로 잡는다. 그래서 pitch 는 절대 수평이 아니라 "출발 자세 대비 상대값"이다.
출발선 경사가 그대로 0 점에 박히고, 그만큼 SLOPE 판정 전체가 밀린다.

`config.yaml driving.slope` 의 임계와 곧바로 충돌한다 (값의 출처는 config 다):

| 출발 지점 | 평지에 나왔을 때 읽히는 pitch | 결과 |
|---|---|---|
| 5° 오르막 | −5° | `enter_pitch_deg`(현재 5.0) 도달 → 평지에서 SLOPE 내리막 진입 |
| 12° 오르막 | −12° | `downhill_brake_pitch_deg`(현재 12.0) 도달 → **숏브레이크 정지, 수동 개입 전까지 안 움직임** |

로봇을 창고에서 켜고 출발선까지 들어 옮기는 운용에서도 같은 일이 난다 — 창고
바닥이 0 점이 된다.

## 2. 세 값은 성격이 다르다

한 함수(`_calibrate()`)가 성격이 다른 것을 함께 잡고 있는 것이 원인이다.

| 값 | 무엇 | 기준 | 드리프트 | 언제 재나 |
|---|---|---|---|---|
| **pitch 오프셋** | 기준점 — "어디를 0 으로 볼 것인가" | 중력 (외부·절대) | 없음 | **한 번**. 상수여야 한다 |
| **yaw** | 기준점 — 진행 방위 | 없음 (적분만) | 쌓인다 | 기동 진입 시점마다 (상대) |
| **자이로 바이어스** | 기준점이 아니다. 측정값 자체의 오차 | — | 온도로 변한다 | **매 기동**. 경사와 무관 |

- **pitch 는 절대일 수 있다.** 가속도계가 중력을 보므로 매 순간 외부 기준이 새로
  주어진다. 부팅 때 0 을 잡아 둘 이유가 없고, 잡는 순간 그 시점 지면 경사가
  오염으로 박힌다.
- **yaw 는 절대일 수 없다.** MPU6050 은 6 축(가속도 3 + 자이로 3)이라 지자기 센서가
  없다. 북쪽을 줄 외부 기준이 아예 없으므로 적분값을 상대로 쓰는 수밖에 없다.
  소비처들이 이미 옳게 대처하고 있다 — `turn_entry_yaw_deg` · `avoid_entry_yaw_deg` ·
  `dead_end_entry_yaw_deg` 가 전부 "진입 시점 값을 저장하고 차이만 본다" 패턴이다.
- **자이로 바이어스는 영점이 아니다.** 정지인데 각속도가 0 이 아니게 나오는 오차다.
  정지해 있으면 어느 경사에 서 있든 참값이 0 이므로, 경사면에서 재도 유효하다.
  매 기동마다 재는 현재 동작이 맞다.

셋 중 **pitch 오프셋 하나만** 성격을 잘못 잡았다.

## 3. 고칠 것

pitch 오프셋을 **측정하지 말고 config 상수로 받는다.** 분리해야 할 두 값은:

- **장착 기울기** — IMU 가 차체에 삐뚤게 붙은 각도. 로봇 좌표계 고정. 상수
- **바닥 기울기** — 서 있는 지면의 경사. 매 순간 변한다. **이것이 측정 대상**

현재 코드는 `atan2` 한 번으로 둘을 합쳐서 통째로 빼기 때문에, 재고 싶은 것까지 함께
지워진다.

1. `config.yaml hardware.imu` 에 `mount_pitch_offset_deg` 추가 (§4 로 실측)
2. `JetsonImu.__init__` 이 그 값을 받아 `self._pitch_offset_deg` 에 넣는다
3. `_calibrate()` 는 **자이로 바이어스만** 잰다. `accel_forward_sum` ·
   `accel_up_sum` 누적과 `_pitch_offset_deg` 대입을 걷어낸다
4. `config.yaml hardware.imu.gyro_bias_samples` 주석에서 "pitch 기준면" 부분을 지운다
5. `imu.py` 모듈 docstring 의 좌표 규약에서 "출발 자세 대비 상대값" 문단을 고친다

`read()` 의 계산식은 **그대로 둔다**. 빼는 값이 "부팅 자세"에서 "장착 오차"로 바뀌면
결과가 자동으로 절대 수평 기준이 된다.

## 4. 장착 기울기 재는 법

평평한 바닥을 확보할 필요 없다. **같은 자리에서 로봇을 180° 돌려 두 번 재고 평균**을
낸다.

```
정방향 측정   m1 = 장착 + 지면
180° 회전     m2 = 장착 − 지면      (지면 기여만 부호가 뒤집힌다)
장착 기울기    = (m1 + m2) / 2
```

장착 오차는 차체 기준이라 로봇을 돌려도 안 변하고, 지면 경사는 진행 방향 기준이라
뒤집힌다. 평균에서 지면이 상쇄된다.

캘리브레이션 스크립트가 두 번 재고 값 하나를 찍어 주면, 그걸 config 에 박고 끝이다.
차체를 다시 뜯기 전까지 유효하다. 방향 검증용 `scripts/imu_check.py` 가 이미 있으므로
그 옆에 두거나 모드로 붙이는 것이 자연스럽다.

## 5. 하지 말 것 — 시작마다 재측정

"부팅 때 잡는 게 문제면 미션 시작마다 다시 잡으면 되지 않나" 는 **반대 방향이다.**
15° 경사 출발선에서:

```
시작 시점에 재측정  →  0 점 = 15°
로봇이 읽는 pitch    →  0.0°   ("나는 평지에 있다")
실제                 →  15° 오르막
```

평지 스로틀로 언덕을 오르려다 못 올라간다. pitch 가 0 이니
`uphill_throttle_gain_pct_per_deg` 가 걸릴 일이 없다.

부팅 때 잡는 현재 방식은 부팅 장소와 출발선 경사가 비슷하면 우연히 얻어걸리기라도
한다. 시작마다 재면 **출발선 경사가 반드시, 매번 지워진다** — 일관되게 틀리는 쪽이다.

재측정 주기의 문제가 아니라 **기준의 문제**다. 언제 재든 "그때 그 자세" 를 0 으로
놓는 이상 상대 영점이고, 매초 재도 상대다. `config.yaml driving.slope` 의 임계는 전부
실제 중력 기준 물리량이라 — "이보다 급한 내리막에서는 서라" 같은 활강 방지 규칙은
기준이 출발선이 되는 순간 의미를 잃는다. 출발선이 그 각도의 내리막이면 그 자리가
0 이 되어 안전 정지가 영영 안 걸린다.

pitch 에 필요한 것은 재측정이 아니라 **측정 안 함**이다.

런타임에 다시 재도 되는 것은 **자이로 바이어스뿐이다** — 기준점이 아니라 센서 오차라
참값이 0 인 것이 물리적으로 확실하고(정지 중 각속도), 온도 따라 변하므로 자주 잴수록
좋다.

## 6. 함께 걸리는 것 — 미션 시작 워밍업

같은 조사에서 나온 별건이다. 요지만 남긴다.

- **자이로는 미션 시작을 늦출 이유가 없다.** `_calibrate()` 는 첫 `read()` 에서
  ~0.4 초 블록으로 끝나고, 그 첫 read 는 부팅 직후 IDLE(브레이크) 상태에 일어난다.
  정지 전제가 이미 성립하고 명령이 오기 한참 전에 끝나 있다
- **GPS 가 진짜 대기 구간이다.** 콜드 스타트 fix 는 수십 초~수 분이고 줄일 방법이
  없다. 리더 스레드는 `communication/runtime.py` `start()` 에서 이미 먼저 뜬다
- **기다릴 자리는 이미 있다.** `communication/commands.py` 가 result 를 두 번 낸다 —
  검증 즉시 `ACCEPTED`, FSM 이 실제로 CRUISE 에 닿아야 `COMPLETED`
  (`_is_applied` 의 START_MISSION 목표가 `{DriveState.CRUISE}`). IDLE 은 그동안
  `BRAKE_COMMAND` 로 잡고 있다. 계약 변경 없이 그 사이가 워밍업 구간이 된다
- **막는 것은 하나다.** `request_start()` 가 한 틱만 산다
  (`driving/state_machine.py` — "외부 요청은 다음 step 한 틱에서만 소비된다").
  `main.py` 에 매 틱 재요청하는 폴백이 있지만 `elif` 라서 **`comms_runtime` 이 붙어
  있으면 타지 않는다** — MQTT 로 들어온 START_MISSION 은 그 틱에 인도가 안 보이면
  유실되고 TTL 만료 시 `EXPIRED` 가 나간다. 워밍업을 기다리게 하려면 이 래치를
  sticky 로 바꾸는 것이 선결 조건이다
- **미결**: `expires_at` 은 서버가 command payload 에 실어 보낸다. GPS 콜드 스타트가
  그 TTL 보다 길면 워밍업 도중 `EXPIRED` 가 나간다. 서버 TTL 값을 확인해야 "기다린다"
  와 "fix 없으면 즉시 REJECTED" 중 무엇을 택할지 정할 수 있다
