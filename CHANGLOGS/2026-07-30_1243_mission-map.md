## 작업 요약

Jira `S15P11D101-471`, 내부 작업 `DAY6-B-00-7`의 Mission 지도를 구현했다.
Mission 전용 Snapshot API가 지정 Area의 Polygon/MultiPolygon, 유효 GPS
Telemetry의 실제 Trajectory와 담당 Robot의 최신 유효 현재 위치를 반환한다.

Mission 상세 화면은 Naver Maps `Polygon`, `Polyline`, `Marker`로 세 Layer를
표시하고 `ROBOT_TELEMETRY_UPDATED` SSE 뒤 Snapshot을 다시 읽는다. 현재 위치가
Area 밖이면 별도 경고를 표시한다. DB·API 호환용 `AUTONOMOUS_DEFAULT` Dummy
Route는 지도 API·Layer·범례에서 제외했고, Naver SDK Key 누락 또는 Script
실패 시 동일 좌표의 SVG Fallback을 제공한다.

## 상세 내용

### Backend·계약

- 기존 Robot 관제 지도는 `ROBOT_STATUS_VIEW`가 필요하므로 Mission 화면과 권한이
  섞이지 않도록 Mission 전용 Snapshot을 `MISSION_VIEW`로 제공한다.
- Snapshot의 Area는 `patrol_area.boundary`를 GeoJSON으로 변환하고, 실제
  Trajectory는 Mission에 연결된 유효 GPS Telemetry를 `sampled_at`,
  `received_at`, `message_id` 순으로 읽는다.
- Current Position은 `position_valid = true`인
  `telemetry.robot_current_state`만 반환한다.
- 내부 Dummy Route Geometry는 조회 SQL과 응답 DTO에 포함하지 않는다.
- OpenAPI는 `/api/v1/missions/{missionId}/map`, Current Position,
  Polygon/MultiPolygon과 최대 5,000개 Trajectory 계약을 고정한다.

### Frontend·Browser

- GeoJSON `[longitude,latitude]`를 Naver `LatLng(latitude,longitude)`로 변환한다.
- Area는 Polygon, 실제 궤적은 Polyline, 현재 위치·heading은 Marker로 표시한다.
- SSE Telemetry Event는 400ms Debounce 뒤 REST 정본을 다시 읽고 기존 Layer를
  제거한 다음 새 Snapshot Layer를 생성한다.
- Polygon Hole과 MultiPolygon을 고려해 현재 위치 포함 여부를 계산하되, 이 값은
  경고에만 사용하고 시간 기반 Mission 진행률에는 사용하지 않는다.
- Naver SDK를 불러오지 못하면 지도 배경 없이 좌표 Layer를 확인할 수 있는 SVG
  Fallback으로 전환한다.

### 문제 원인과 해결

- PostGIS `double precision`의 `127.007`이 Java에서
  `127.00699999999999`로 표현되어 정확 비교가 실패했다. 공간 좌표 Assertion을
  좁은 허용 오차 비교로 바꿨다.
- 첫 OpenAPI 검증 Script가 `/api/v1` 접두사를 빠뜨려 잘못된 누락을 보고했다.
  실제 Path로 수정해 전체 로컬 `$ref`까지 재검증했다.
- 첫 전체 Backend 실행은 Tool Timeout을 1초로 잘못 지정해 중단됐다. 600초
  제한으로 동일 명령을 재실행해 전체 회귀를 통과했다.
- 전체 회귀 종료 시 Spring Session Cleanup이 닫힌 Testcontainers DB를 조회하는
  기존 종료 로그가 있었으나 Gradle Exit 0, 546건 실패 0·Skip 0으로 실제 실패와
  구분했다.
- 외부 Naver Origin·Key에 의존하지 않는 Browser 회귀를 위해 Chromium에 SDK
  생성자 계약을 주입해 Polygon·Polyline·Marker 생성과 갱신을 검증하고, 별도
  Spec에서는 Script 실패 Fallback을 검증했다.

## 영향 및 주의사항

- Mission Client는 지도 표시 시 신규
  `GET /api/v1/missions/{missionId}/map?limit=5000`을 사용한다.
- `MISSION_VIEW`만 있으면 Mission 지도 Snapshot을 읽을 수 있으며 별도의
  `ROBOT_STATUS_VIEW`를 요구하지 않는다.
- Naver Maps 운영 사용에는 `VITE_NAVER_MAP_CLIENT_ID`와 등록된 Web Service
  Domain이 필요하다.
- Naver Cloud 공식 가격표의 무료 구간은 대표 계정·호출량 조건을 가지며 정책이
  바뀔 수 있으므로 배포 전 최신 가격표를 다시 확인한다.
- Snapshot Trajectory는 최대 5,000개다. 장기 Mission에서 점 수가 커지면
  시간/거리 Downsampling 또는 구간 Pagination을 별도 설계한다.
- 같은 파일에 먼저 존재하던 시간 기반 Mission과 사용자 변경은 보존했다.
